# Security policy

## Reporting a vulnerability

Report vulnerabilities privately through GitHub Security Advisories: use "Report a vulnerability" on the
repository's Security tab (private vulnerability reporting). Never report a vulnerability in a public issue,
discussion or pull request.

Please include:

- the affected version or commit;
- steps to reproduce;
- the impact as you see it.

Do not attach customer files or personal data.

This channel also receives Code of Conduct reports until the conduct contacts are published (see
[CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md)).

## What happens next

- We acknowledge your report within 7 days.
- For critical issues, we aim to ship a fix or mitigation within 30 days.
- Disclosure is coordinated: details are published after a fix is available, or by agreement with the reporter.
- A CVE is requested for each fixed vulnerability.
- Reporters are credited if they wish.

## Supported versions

| Version | Supported |
|---|---|
| No releases yet (development builds only) | — |

The latest minor gets all fixes; each minor gets security and data-loss fixes for 6 months after its successor ships.

Before 1.0 only the latest 0.x release is supported, and there is no long-term-support line.
