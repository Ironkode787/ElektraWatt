# ElektraWatt documentation map

This page is the entry point to the documents. Read what your task needs and no more: the code is the reference for
how things work today, and a design document explains why and what is intended.

## Where to start

| You want to | Read |
|---|---|
| Know what is being worked on | [plan/README.md](plan/README.md), then the running milestone it names |
| Change code | [CONTRIBUTING.md](../CONTRIBUTING.md), "The development loop"; then [architecture](design/04-architecture.md) and the design document of your area |
| Understand the product | [Vision and scope](design/00-vision-and-scope.md), the [golden project](design/20-golden-project.md), the [user guide](book/src/introduction.md) |
| Judge how the window should look and behave | [Design language](design/16a-design-language.md) and [UX and UI](design/16-ux-ui.md) |
| Know why something was decided | The [ADR index](adr/README.md) |
| Cut a release | [release/README.md](release/README.md) |

## Keeping the documents right

- A document states what is true or intended now. When behaviour changes, change the sentence that describes it;
  do not append an amendment, a date or a reference to where it was decided.
- A decision with consequences for the architecture gets an ADR ([how to add one](adr/README.md#how-to-add-an-adr)).
- Open work is a row of the [backlog](plan/backlog.md).
- House rules (public repository, no customer data) are in [CLAUDE.md](../CLAUDE.md) and
  [CONTRIBUTING.md](../CONTRIBUTING.md).
