# M3.5: hygiene

**Status:** running · **Started:** 2026-11-20 · **Base:** `f3503c6f9` (the sixth candidate of 0.3.0) ·
**Release:** 0.3.5

M3.5 makes the repository cheaper to work in, by three measures in this order, and ends with a fix round (step 13) that works the backlog down, the rows of the first production job first:

1. **What a builder must read and trace.** Nearly every change here is made by a model that starts cold, finds its
   way by search and reads files into a limited context. A thing must be findable by search, traceable by direct
   calls, small enough to read for the change at hand, and mapped from the code itself. Where ease for a human
   reader and reading cost for a model pull apart, the model's cost decides (owner, 2026-11-20).
2. **Wall time of the loop:** what an edit costs before its tests start, and what the tests cost.
3. **Lines carried:** code, tests and committed copies that nothing needs.

The rule of [CLAUDE.md](../../CLAUDE.md), "Proportion", holds for the milestone itself: a step that cannot say
what it saves is not done.

**The exit.** Every step below is done or is a row of the backlog with its reason; the fix round has taken every
row it was given or says where the row went; the whole workspace and the deep run pass; the table "The loop,
measured" has its second column; the review and its fixes (step 14) are done; then a candidate of 0.3.5 is cut. The
gate is the owner's go. Step 15 follows the second candidate and goes out with the third (owner, 2026-11-23).

**Verdict.** Inside its modules the code is healthy: every source file states what it holds, almost nothing is
dead, the new placer is clean, the layering is right but for two accidental edges. What stands in the way is
structure: one crate that every change recompiles, tests that pay a whole program for one assertion, one rule
written in several places that drift, names a search cannot find, and the reference project under everything.
So the refactors come first and the planned steps (the reference project retired, the test pass, the grid
follow-up, the triage) follow in the same milestone.

## Step 15: one concept, one place

Owner, 2026-11-23: after the second candidate of 0.3.5 is cut, the maintenance step that was the first step of M4
(FT-1937) is done in this milestone, with the tasks like it. Its work goes into the next candidate, the third of
0.3.5 (owner, the same day): 0.3.5 is promoted from a candidate that holds it. Before that candidate is cut the
step is reviewed as step 14 says, read for one thing above all: behaviour it changed without saying so.

**What it is for.** A fix is cheap when the thing it changes is written once and the file that holds it can be read
for that change alone. Measured in the fix round: a fix commit touches 7 files at the median and 12 or more in a
quarter of them; 60 % of the source a lane read came from files of 30 to 100 KB; and the reviews before both
candidates each listed the same kind of spot, "one idea, many files". No part of the step changes what the program
does; a move of code is committed apart from anything else, as in the steps before.

**The scan comes first** (owner, 2026-11-23: the step makes its own thorough scan and does not stop at what the
reviews happened to name; the aim is a project back in shape: a fix that takes less time, fewer faults, a shorter
loop and less to read). Read-only passes over the whole repository, one per region (the format, the model and the
commands; the derivation and the checks; the drafting crate; the scene, the lists and the outputs; the view-model;
the window; the command line, the tools and the tests), each by a reader that has not built the region, each with
the same seven questions and an answer per finding of where (file and line), what it costs today and what is left
when it is gone:

| The question | What counts |
|---|---|
| Is one thing made or decided in more than one place? | Two functions that lay out, name, convert, order or word the same thing; a list of kinds repeated per consumer; a rule restated beside the query that holds it |
| Is something that was replaced still there? | An older form, path or parameter that a newer one took over and that can still run; a compatibility branch for something no version writes |
| Is a concept built larger than its use? | A trait, a generic or a registry with one implementation; a setting nobody sets; a layer that only passes on; an option of a command that no caller gives |
| Is a fix a patch on the symptom? | A special case for one kind, one part or one page where the rule should have changed; a second pass that repairs what the first pass did; a flag that switches off a check for one caller; a comment that names a row as the reason for a branch |
| Could it be said in fewer lines? | A function that does two things; a long match that a table would hold; parameters that travel together and are not one record; code a helper of the crate already has |
| Is it carried without being used? | Code no path reaches; a test that guards nothing or pins what need not hold; a document or a generated file that repeats another |
| Is an item kept apart from the others of its kind? | Owner, 2026-11-23: what is spread over the code is brought together, texts first. A text a person reads that is written in the code and not with the texts (a toast, a finding, a refusal, a heading built from a sentence in a function; a rule's message in the rule's code beside its entry in the text file); a number that draws or decides (a distance, a pitch, a clearance, a tolerance, a limit) written where it is used and not with the numbers of its concern, named, with its unit and the document that sets it; a default of a form in the form's code; a shortcut outside the keymap; a colour, a line width or a text size outside the style; a part number or symbol key of the starter content named in code. A number used once beside its only use, with its reason, stays: the test is whether a person would look for it or change it, or whether two places must agree on it. A first count: about 74 sentence-like texts built in the code of five crates, 342 numeric constants of length or count in 167 files |

Beside the readers, the measurements of the first scan are made again (sizes, the most-read files from the lanes'
records, which files a fix touches together), so that the findings are ranked by what they cost and not by how they
look. The findings are triaged in one sitting: each is done in this step, is a row of the backlog with its reason,
or is dropped as not worth its change; the rule of [CLAUDE.md](../../CLAUDE.md) holds, delete before you fix and fix
before you add. Parts 1 to 3 below are what is known before the scan; the scan adds to them.

**The design documents are scanned as the code is.** Every lane reads them, and they have grown by adding: eight
of them are about 200 KB each, and the larger ones hold 50 to 80 notes headed "As built" that tell how a thing
came to be and not what it is. A document says what is; the history is in git. The notes are folded into the text
they amend, what was replaced is cut, and a document is split where a chapter is read alone.

**A ceiling keeps the gain.** Once the files of part 2 are split, a repository rule holds a source file under a set
size (set from the sizes after the split), with no list of exceptions: a file that reaches it is split in the
change that makes it grow. During the fix round before the second candidate the files on the list to split grew
by several hundred lines.

**What the step is measured by.** Four numbers, read at its start and at its end from the lanes' own records and the
check, written into "The loop, measured"; none is a test:

| | At the start (the fix lanes before the second candidate) |
|---|---|
| Tokens a lane spends on one fix | about 55,000 to 180,000 (lanes of four to seventeen fixes spent 530,000 to 930,000) |
| Wall time of one lane from its brief to a passing check | 50 to 105 minutes for four to seventeen fixes |
| Findings of one persona run (faults, missing words and its misreadings together) | 8 to 13 a run, eight runs |
| Files a fix touches | 7 at the median, 12 or more in a quarter of the fixes |

**Part 1: one idea written once.** The spots the reviews and the lanes named, each with the files it costs today:

| The idea | Written today | One place |
|---|---|---|
| A new command with its action | 18 files | what a command needs beyond its own file is generated or derived from its declaration |
| A new optional member of a record | 5 files and 3 sections of notes; every struct literal of `ReportBlock` (5 files), `BoxSpec` (9 literals), every member of `Part` spelled out in `placeholder.rs` | records are built through `Default` or one constructor, so a new member is one line |
| The words of a list kind, and its cells | 21 files; every list kind builds its cells itself | one table of list kinds with their words and columns |
| Where a wire's size comes from | five consumers (`ew-api` twice, `ew-reports`, `ew-sqlview` twice) | one function that the consumers print |
| The first layout page that shows a plate | three functions | one |
| The project's or the window's language | chosen at each call site, 35 sites (FT-1819) | chosen where the text is asked for |
| A form of the window | built by hand in 6 files | the one form renderer of step 8 takes the rest |
| Two host commits as one undo step | 7 places | one helper |
| A property row's words per kind, a typed value's special case per row | after the sheet is built; `fields.rs` | with the row's declaration |
| A copy of pages | split over `ew-api` and `ew-commands` | one crate |

| `route_wire`'s signature | 7 files | one parameter record |
| The layout of a PLC card's box | more than one path lays it: a card placed from the device catalogue came in the two-row form that Draw on a page replaced (a persona run, 2026-11-23; the owner: that form should have been retired, and each thing should refer to one instance of itself) | one function, called by every path that makes a box; the retired form's code is gone. The fix is made before the second candidate; the step's part is the rule below |

**A replaced thing is removed.** Where a new form, rule or path replaces an old one, the old one goes in the same
change from every path that could still make it, with its tests and its words; what an older project stores is read
through one place that says so. The step looks for the pairs that are left (a search for "older form", "as before"
and "still" in the head comments and the design documents is where it starts) and removes or names each.

**Part 2: files that can be read for one change.** The source files read most and edited for a few lines:
`ew-scene/src/page.rs`, `ew-viewmodel/src/shell/editing.rs`, `shell/properties.rs`, `shell/creation.rs`,
`shell/part_dialog.rs`, `tools/black_box.rs`, `ew-api/src/output/view.rs`, `output/fields.rs`,
`ew-commands/src/commands/paste.rs`, `ew-drafting`'s `route.rs`, `labels.rs` and `place/sketch.rs`,
`ew-ui`'s `canvas.rs` and `app.rs`, `ew-library`'s `asset.rs` and `store.rs`: each split along the lines it is
read by, as step 3 did for the shell. The two text files of the window (`shell.ftl`, about 500 KB each) are split
by area, so that a new text is added to a file of its area. The design documents over 180 KB are split by their
chapters where a chapter is read alone.

**Part 3: tests and documents that follow one change.** The sample's contents are stated once and read by the
tests that need them (they are restated per test, and its shield is found six ways); a derived value that changes
is re-blessed in one step and not in ten tests and seven pictures; a visible change has its line in the release
notes and is not written out again in two more documents; the CSV dialect is described in one document.

**Part 4: faults caught sooner, fixes started sooner.** Five things the persona round and its fix lanes showed
(owner, 2026-11-23), each with what it catches or saves:

| What | What it catches or saves |
|---|---|
| Every window test runs on the frame clock, the page's tiles in step with the frames | Both tests that failed in the round passed alone and failed with lanes building beside them: one counted frames while the tile workers were late, one measured a dialog whose height followed the length of a temporary folder's name |
| The project's integrity check runs after every command in the tests' harness | What a command leaves behind: a strip of terminals nothing draws that could not be deleted, a wire drawn to where its terminal stood. Personas and a reader of a diff found these, no test did |
| `cargo xtask blind replay <run> --until <frame>` puts a builder at the frame where a persona was stuck | Each fix lane of the round wrote its own script to play a run back before it could look at the fault |
| The check writes down the tree it passed on, and the gate runs it again only for a tree that differs | A lane and the gate ran the same check of five to seven minutes on the same tree, the gate's as a fourth build beside three lanes |
| A repository rule: an action that can be greyed gives a reason in words | The round's largest theme was "it did not say why": the window's lane added reasons by hand in a dozen places, and the next greyed entry would ship without one |

**The yardstick.** One standard small fix (a new optional member that a list prints, with its text in two
languages) is made before the step and again after it: the files touched, the tokens a lane reads before its first
edit and the wall time to a passing check are written into "The loop, measured". It is read by hand and is not a
test.

**Done** when every finding of the scan is done, a row with its reason or dropped; each row of part 1 is one place or says in the backlog why it stays, the files of part 2 are split
or measured as not worth it, each of part 4's five is built or says why not, the yardstick has its second
column and the four numbers above have theirs.
