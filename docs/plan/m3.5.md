# M3.5: hygiene

**Status:** running · **Started:** 2026-11-20 · **Base:** `f3503c6f9` (the sixth candidate of 0.3.0) ·
**Release:** 0.3.5

M3.5 makes the repository cheaper to work in, by three measures in this order, and ends with a fix round (step 13) that works the backlog down, the rows of the first production job first:

1. **What a builder must read and trace.** Nearly every change here is made by a model that starts cold, finds its
   way by search and reads files into a limited context. A thing must be findable by search, traceable by direct
   calls, small enough to read for the change at hand, and mapped from the code itself. Where ease for a human
   reader and reading cost for a model pull apart, the model's cost decides (owner, 2026-11-20).
2. **Wall time of the loop:** what an edit costs before its tests start, and what the tests cost.
3. **Lines carried:** code, tests and committed copies that nothing needs.

The rule of [CLAUDE.md](../../CLAUDE.md), "Proportion", holds for the milestone itself: a step that cannot say
what it saves is not done.

**The exit.** Every step below is done or is a row of the backlog with its reason; the fix round has taken every
row it was given or says where the row went; the whole workspace and the deep run pass; the table "The loop,
measured" has its second column; the review and its fixes (step 14) are done; then a candidate of 0.3.5 is cut. The
gate is the owner's go.

| The reference project | 307 test files (57 % of the test lines) open it or build from it; its expected outputs were regenerated in 74 commits in three weeks, the window's pictures in 135 |

**Verdict.** Inside its modules the code is healthy: every source file states what it holds, almost nothing is
dead, the new placer is clean, the layering is right but for two accidental edges. What stands in the way is
structure: one crate that every change recompiles, tests that pay a whole program for one assertion, one rule
written in several places that drift, names a search cannot find, and the reference project under everything.
So the refactors come first and the planned steps (the reference project retired, the test pass, the grid
follow-up, the triage) follow in the same milestone.

## The steps

One lane per step unless it says otherwise; at most three at once, on crates that do not overlap. A move of code
is committed apart from a change of behaviour. No step changes what the program does except where it says so.
Each lane reports the lines it deleted and the times it measured.

**What the baseline changed.** With incremental builds one edit costs 13 to 34 s before every test can start, so compile time is not what the loop waits for: the tests are (319 s), then a fresh worktree's first build (289 s, which every lane pays once) and the lint's separate compile (84 s). Steps 2 and 6 carry the wall time; steps 1 and 3 are for reading and tracing.

**Not in M3.5,** each a row of the backlog if it stays wanted: the symbol editor's gestures moved into the
view-model (a feature's worth of work); a crate of its own for `ew-api`'s output (large, and steps 1 and 3 may
make it unneeded: measure after them); folding the smallest crates (no gain worth a lane). Seventeen commands
are reachable from scripts only: whether they stay as the script catalogue is the owner's decision.
