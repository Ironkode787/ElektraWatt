# M2.5: back on track

**Status:** closed on 2026-11-11 · **Started:** 2026-11-09 · **Base:** `5516edba4` (0.1.0 is `v0.1.0`)

M2.5 builds no features and fixes no behaviour. It leaves a project that is lean to work in: less code to carry,
one source for every list, documents that say what is true today, and a development loop of one command. M2.5-Fix
follows it and makes the program work properly; M3 is new development.

This file is the plan, the log and the exit record of M2.5. It replaces the M2.5 row of the global plan.

## Principles

1. **Delete before fixing, fix before adding.** A check, list, document or abstraction stays only when someone can
   say what it caught or who reads it.
2. **One source.** Anything listed twice is generated or derived from one of the two, or one of them goes.
3. **Behaviour does not change.** Golden A, the acceptance tests and the snapshots stay byte-equal through M2.5:
   they are the proof of every move. A fix that changes behaviour waits for M2.5-Fix.
4. **Proportion.** This is an early alpha of a desktop tool with one developer and one pilot. Machinery that suits
   a released product with a team waits for 1.0, in git history, not in the tree.
5. **History stays in git.** Nothing is "archived" in the tree. What leaves is found at `5516edba4`.

## Assessment (2026-11-09)

The read of 2026-11-08 found the layers sound and the debt in a few long files, the hand-kept lists and the
backlog. This is a second reading, from counts taken on the base and four read-only surveys whose claims were
checked before they were used. It agrees about the lower half and disagrees about the upper half.

**The lower half holds.** The identifiers, units, schema, format, model, derivation, commands and store (about
170,000 lines) keep to their layers, and the crate graph enforces it. They are trimmed, not restructured.

**The upper half is where the cost is.** `ew-api`, `ew-viewmodel` and `ew-ui` hold 175,000 lines, and every one of
the owner's hands-on findings on rc.3.

1. **One object holds the window.** `ShellModel` has 90 fields and about 1,200 methods in 48 `impl` blocks over 43
   files (38,000 lines). The symbol editor, the strip editor, the part dialog, the wizard, macros, revisions and
   printing are all state on it, reached through 392 action entries in one 6,800-line table. Splitting files or
   cutting the crate in two leaves this as it is: a change to one feature still reads and compiles all of them.
2. **`ew-api` is not an API.** 28,000 of its 46,000 lines (`output/`) are mostly the window's presentation: the
   property sheet, the navigators, find, the editing offers. The command line uses the export, print and table
   parts. It depends on 27 crates, five of them empty.
3. **The window is built for a text driver first.** `describe.rs`, `script.rs`, `alias.rs` and the visual and
   headless drivers (about 8,000 lines) exist so that agents can drive the program without a window. The tests
   follow: most of them drive the model or the view model. The owner's findings are in what those tests do not
   reach, the window's own handling of the mouse, focus and overlays. That is how 7,400 tests pass on a program
   that fails in the hand.
4. **Every text is written three times.** A refusal's English stands in `TEXTS` (Rust) and in the en-GB file, its
   Dutch in the nl-NL file, and a generated list of 4,900 keys is committed beside them.
5. **About 40,000 lines of generated mirrors are committed**, each with a test that fails when it drifts: 135
   command and result schemas, the rule catalogue, the CLI, query and `api_v1` snapshots, three keymap files, the
   blind reference, the key list. They are the hand-kept lists' disease in another form.
6. **The tests carry the same weight twice.** 298,000 lines against 476,000 of source; about 970 literals of
   Golden A's tags and cells, 76 pixel images with 15 Linux overrides nobody on Windows can bless, about 100
   literal totals, 22 copies of `fn shell()`.
7. **Process residue in the product.** 13 empty crates, the workspace-hack crate in 31 manifests, about 8,500
   comment lines that cite a ledger instead of explaining, test-only features with their own policing.

### What A and B became

Reading the code for the moves corrected the assessment in two places.

**A.** Point 1 above overstated the problem. The window's handlers are already one file per feature under
`shell/`, most features already keep their state in a struct of their own, and an action is already declared once.
The order of the action table is the order of the menus, the palette and the shortcut list, so its entries cannot be
regrouped by feature; a crate split would re-sign about 1,200 methods for no gain a reader would notice. A is
therefore: the table in eight consecutive section files; the alias parameters named by the action itself; the
repetition in the handlers removed (one refusal constructor, one or-return macro).

**B.** Point 2 above was wrong in its size. The property sheet, the navigators, the field parser and the table
editing are not the window's alone: the command line's table export and import go through them, so that a cell
edited in the grid and a cell read from a file compile to the same command. Of the 28 modules of `output/`, five
are used by the window only (the clipboard, find, the history rows, cable editing, the PLC binding offers; 2,800
lines). They are now `ew_api::window`; `output` holds what both front ends reach and never depends on `window`. A
move to a crate above `ew-api` was not possible in any case: the modules add inherent methods to `Session`.

- **The text-key check.** `key!` checks its key when the code is built, by a search the compiler runs in its const
  evaluation. The search went through the 4,905 keys from the start for each of the 2,700 keys `ew-viewmodel`
  names: about 70 s of compile time, twice in a test build. It is a binary search of a sorted list now.
- **The build profile.** The workspace's own crates build at opt-level 1 in dev and test builds, because most tests
  open the golden project and spent their time loading and deriving it in unoptimised code. `ew-api`,
