# Plan folder guide

**Status:** Draft v0.1 · **Date:** 2026-10-18 · **Part of:** ElektraWatt plan

**Purpose.** This page says what each file of `docs/plan/` is, which files a script writes, how to regenerate and
check them, and what the headline dates are. Back to the [documentation map](../README.md).

## 1. Files

| File | What it is | Written by |
|---|---|---|
| [01-global-plan.md](01-global-plan.md) | Capacity model, scenarios, milestones, phases, pilot preview, release train | Hand-written, with generated blocks from `schedule.py` and `totals.py` |
| [02-work-packages.md](02-work-packages.md) | The work breakdown: 124 WPs in eight streams | Hand-written, with generated blocks from `schedule.py` and `totals.py`; checked against the CSV by `totals.py` |
| [03-gates.md](03-gates.md) | Gate system G-M0 ... G-M6, G-PP, G-SP; checkpoints (CP-nn), kill triggers (KT-n), gate-pack items (GP-nn) | Hand-written; one generated block from `schedule.py` |
| [04-risk-register.md](04-risk-register.md) | Scored risks, owners, mitigations, review gates | Hand-written |
| [05-traceability.md](05-traceability.md) | Requirements, ACs, defects and reference candidates to WPs; holes | Generated by `trace.py` |
| `gate-records/` | Dated gate records, readiness runs and pack drafts, named `<gate>-<yyyy-mm>` (gates open question 3); first: the [G-M1 readiness run](gate-records/G-M1-2026-10-readiness.md) and its [pack draft](gate-records/G-M1-2026-10-pack-draft.md); the generated [golden-table change list](gate-records/golden-change-list.md) | Hand-written, except the change list (generated by `golden_changes.py`) |
| `specs/` | Closed specifications handed to a lane, one per work package or part, named `<WP-ID>-<slug>.md` (decision log ID-441); first: [WP-S2.01 part 1, the application shell](specs/WP-S2.01-application-shell.md) | Hand-written |
| [06-decision-log.md](06-decision-log.md) | Decided items (Part A) and open questions (Part B) | Hand-written |
| [work-packages.csv](work-packages.csv) | The source data of the plan: one row per WP | Hand-edited; the single input of the tools |
| [milestones.csv](milestones.csv) | Scenario x milestone: month number and calendar month | Generated by `schedule.py` |
| [wp-schedule.csv](wp-schedule.csv) | Per WP: start and finish month per main scenario, developer in the baseline | Generated by `schedule.py` |
| [traceability-matrix.csv](traceability-matrix.csv) | Requirement to WPs, one row per FR/NFR | Generated by `trace.py` |
| `tools/` | The scripts below, plus `engine.py` (schedule model) and `wbs.py` (shared helpers) | Hand-written |

## 2. Generators and checks

All scripts use only the Python standard library. Run them from the repository root (any working directory works).
Never edit text between `<!-- generated:NAME -->` and `<!-- /generated:NAME -->` markers by hand.

| Script | Regenerate | Check (exit 1 if stale) | Output |
|---|---|---|---|
| [tools/totals.py](tools/totals.py) | `python3 -I docs/plan/tools/totals.py` | `python3 -I docs/plan/tools/totals.py --check` | Effort tables in 01 and 02; CSV and section consistency checks |
| [tools/schedule.py](tools/schedule.py) | `python3 -I docs/plan/tools/schedule.py` | `python3 -I docs/plan/tools/schedule.py --check` | milestones.csv, wp-schedule.csv, date tables in 01, 02, 03 |
| [tools/trace.py](tools/trace.py) | `python3 -I docs/plan/tools/trace.py` | `python3 -I docs/plan/tools/trace.py --check` | 05-traceability.md, traceability-matrix.csv |
| [tools/golden_changes.py](tools/golden_changes.py) | `python -I docs/plan/tools/golden_changes.py --write` | `python -I docs/plan/tools/golden_changes.py --check` (needs the full git history; `--test` is the offline unit test) | [gate-records/golden-change-list.md](gate-records/golden-change-list.md): the golden-table change list for the pilot's acknowledgement (FT-300, G-M1-09) |
| [tools/doccheck.py](tools/doccheck.py) | not generative | `python3 -I docs/plan/tools/doccheck.py` | Links and anchors, table columns, WP IDs, gate IDs |

CI runs the three `--check` modes together:

```bash
python3 -I docs/plan/tools/totals.py --check && python3 -I docs/plan/tools/schedule.py --check \
  && python3 -I docs/plan/tools/trace.py --check
```

A change to the plan is a change to `work-packages.csv` (or a catalogue), then a re-run of the generators, then a
review of the diff, in one pull request.

## 3. Headline dates

Source: [milestones.csv](milestones.csv); month 0 is 2026-11-01 and a month is labelled with the calendar month in
which it ends. Scenario names are `<developers>d-<scope>[-ai-<level>]`.

| Scenario (lean scope) | M1 spine exit | M-PP pilot preview | M2 MVP | M6 release 1.0 |
|---|---|---|---|---|
| `3d-lean`: 3 developers, **plan of record** (external commitments) | Feb 2028 | Dec 2028 | Mar 2030 | Mar 2032 |
| `3d-lean-ai-moderate`: 3 developers with AI assistance, **internal target** | Nov 2027 | Jul 2028 | Jul 2029 | Feb 2031 |
| `4d-lean`: 4 developers | Feb 2028 | Oct 2028 | Oct 2029 | Aug 2031 |
| `2d-lean`: 2 developers | Sep 2028 | Nov 2029 | Oct 2031 | Nov 2034 |

The AI-assisted scenarios are hypotheses with weak evidence; each gate review replaces both dates with a re-forecast
from actuals ([global plan](01-global-plan.md) §3.7). The full-scope and capacity-sensitivity variants (`-full`,
`-cap80`, `-cap120`, `-best`) are in the same CSV.
