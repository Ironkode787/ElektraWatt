# ElektraWatt 0.3.0

The release and migration notes of ElektraWatt 0.3.0.

## 1. What 0.3.0 is

ElektraWatt 0.3.0 is the automation release for the pilot. It adds what a control-cabinet project needs around its
schematic: the PLC and the bus (racks and slots, addresses, safety data, PROFINET, EtherCAT and IO-Link), fluid power
(valves, media, tubes, the ISO 1219 symbols), the exchange with PLC software (AutomationML, the TIA Portal tag table,
PLCopen XML), drawings and EPLAN data brought in (DXF, DWG, PDF, EDZ, EPLAN parts and report files), and three
workspaces for this work. The window is now designed for 1920 × 1080 and uses the room of 2560 × 1440 (section 3).
It comes as the same downloads as 0.2.0, for Windows and Linux on x86-64, and with the same warnings:

- **Unsigned.** No file of this release is signed: no signed tag, no Authenticode signature on the Windows programs,
  no signed `SHA256SUMS`. Windows may warn before it runs the setup. Check a download as section 2 says instead.
- **No network code.** ElektraWatt makes no network connection of its own: no update check, no crash upload, no
  analytics (`PRIVACY.md`, in the installation and the repository).
- **Supported until the next minor release.** Before 1.0 only the latest 0.x release is supported, until the next
  minor release ([`SECURITY.md`](../../SECURITY.md)). With 0.3.0 out, 0.2.0 is no longer supported.
- **Engineering verification.** ElektraWatt's checks do not replace engineering verification by a competent person.

## 2. The downloads and how to verify them

The release on the repository's releases page holds these files, each built by the release workflow from the
release's commit:

| File | What it is |
|---|---|
| `ElektraWatt-0.3.0-x64-user-setup.exe` | The per-user setup for Windows 10 and 11: the window, `ew.exe`, the starter content, the sample project and the user guide in one folder, no administrator rights needed |
| `ElektraWatt-0.3.0-x86_64.AppImage` | The same for Linux (glibc 2.35 or newer, as on Ubuntu 22.04 and Debian 12), one file to make executable and run |
| `ew-0.3.0-x86_64-pc-windows-msvc.zip`, `ew-0.3.0-x86_64-unknown-linux-gnu.tar.gz` | The command-line program `ew` alone, with the starter content, the sample project, the licence texts and the notices |
| `SHA256SUMS` | The SHA-256 checksum of every other file |

Verify a download before you run it: check it against `SHA256SUMS`. The user guide's
[Verify a download](../book/src/how-to/install.md#verify-a-download) gives the commands for Windows and Linux;
[Install ElektraWatt](../book/src/how-to/install.md) installs, upgrades and removes each download.

## 3. What is new since 0.2.0

### The PLC workspace

The PLC button of the workspace switch in the tab row, or View ▸ Workspaces ▸ PLC, puts the PLC navigator in the left
column, the page in the middle and the PLC grid in the bottom dock. The tools are on the PLC tab of the command bar.
A station's rack is a view in a tab beside the page tabs (below).
The guide's [Work in the PLC workspace](../book/src/how-to/plc-workspace.md) goes through it step by step.

- **From nothing.** The starter parts hold a CPU with a PROFINET and a PROFIBUS DP port, a remote I/O head (a
  station of its own), an input and an output module, a PROFIBUS cable and an Industrial Ethernet cable, so a new
  project can hold two stations and a bus without a part of your own. PLC modules, CPUs, remote I/O heads and parts
  with a bus interface are listed under PLC and bus in the device browser, not under Other. The window says "module"
  for what the reports still call a PLC card.
- **New station.** New station… is the first button of the PLC tab, and the plus of the PLC panel. It opens a tab
  New station beside the page tabs, in the same view as a station's rack (below), and makes a PLC station the way TIA
  Portal does. You choose what the station is (PLC (CPU), Remote I/O, Valve terminal or Compact device) and the PLC it
  belongs to (an existing one or a new one); a double click on its head part in the catalogue sets the head (New
  part… makes one, started as that kind of part, and the part you save is the head when you come back), and a double
  click on each module puts it into the next free slot. Where a kind's part list is empty the catalogue says why and
  offers New part…, and it offers a device that already stands on the bus as the station. Its tag letter follows its
  part (a valve terminal: K). Create makes the station and its modules in one undo step; nothing is written before,
  and closing the tab before Create asks first. The station is drawn on no page yet, so its tags read -?A? and its
  hover and To do say that a tag gets its number when it is drawn on a page. To do under the table says what
  is left and offers it, one line for each side of the station: its electrical side (Draw on an electrical page…),
  its bus side (Put it on a bus page…) and, for a valve terminal, its pneumatic side (Draw on a fluid page…), with
  Make the overview page for a valve terminal. A side is drawn on a page of its kind: a terminal drawn on its fluid
  or bus page first still has its electrical side to do. The line's button draws on the open page when that is a
  page of its kind, on a new page when the project has none, and otherwise asks which page of its kind (New page…
  after them). Drawing puts the station and all its modules side by side in slot order, in one undo step, and binds
  each module's channels to its pins: the addresses stand at the pins, and a device wired to a pin is the channel's
  target. A module's own Draw on page draws one module. Put it on a bus page draws every bus interface of the
  station as a box of its own; a station whose part has no bus interface is refused in words. A step on something
  that was deleted or undone meanwhile names it ("No longer in the project: the device…").
  EW-PLC-018 finds a module that an earlier build drew with its channels unbound, and its quick fix binds them.
- **Names in place.** A station's tag and a module's tag are changed where they stand in the station's view, by a
  click or F2; a tag another device has is refused in a sentence under the rack, and a tag that moves other tags
  too waits for Apply in Properties. The name of the PLC ("Belongs to PLC: …" in the view's header) is changed the
  same way; a name another PLC has is refused in words. The station's tag and the PLC's name show a pencil after
  them and an outline under the pointer, so that they look changeable, and the Tag row's help in Properties says
  what Derived and Freeze mean.
- **Place here.** A PLC station or module that no page draws yet on one of its sides has Place here first in its
  row's menu in the PLC panel and in the station view's bar. The open page takes the side that belongs on it: the
  part's box on an electrical page, its bus ports on a bus page, a valve terminal's positions on a fluid page. On any
  other page the entry is grey and says which page to open. Place here gives way to the Select tool once the box is
  down, and a box that hangs on the pointer ends when a step (an Undo or Redo, a delete in a navigator) takes away
  what it was made from. A channel's row and a bus port's row have Place here too, for the card or the station's bus
  ports that no page draws; where a channel's card is drawn and the channel still is not (a valve terminal's output
  with no valve on its position, a card drawn without a pin for it), the entry is grey and says what to do. In a
  row's menu a grey entry shows its reason on a line under it, not only on hover.
- **Undo and Redo say what they did.** Every Undo and Redo names what it took back or did again and on which page
  ("Undone: Draw wire on 101"), with Go to page when that page is not on show. Ctrl+Z with something
  hanging on the pointer (a box or a symbol, a pasted block, a wire begun, a pin's name being typed) first puts it
  away, undoes nothing and says so in the status line; the next Undo takes back the last step. With a tool merely
  armed, such as the Wire tool after a wire, Undo takes the last step back at once.
- **Modules and stations.** Placing a station opens its rack. A module placed beside a station joins it, and a
  toast names its slot and offers Rack…. A module placed where no station takes it waits: with one station a toast
  says how to attach it, with several a dialog asks which station takes it, and with none the toast offers New
  station…. In the PLC panel a module is dragged onto a station's row, or its own row offers Attach to and each
  station's tag. A bus device is given to a PLC from its menu, on its symbol, its row in the Devices list or its row
  in the Bus panel: Add to PLC makes it a station of that PLC or of a new one. A managed switch is given to the PLC
  with a toast and no rack; an unmanaged switch or a plug has no place in a PLC and its row says why. The device's
  Properties have a PLC row (the PLC it belongs to, or "in no PLC" with Add to PLC…), and the Bus panel shows the
  same as a badge. A station shows its PLC in its menu. A station that is its own module is one row, and a
  device not yet drawn on any page carries a "not drawn" badge in the PLC and Devices lists (the one word for it in
  every list; the badges "not drawn" and "spare" say on hover what they mean). EW-PLC-017 reports a
  device that sits in a rack as a module although its part describes no PLC module; its quick fix takes it out of
  the rack.
- **The navigator** runs from the configuration project to its stations, their racks, their modules and each
  module's channels, with the station's bus ports after the modules. A module without a station is listed under
  Modules without a station, and Attach modules without a station on a station's row takes it. This is how a second
  CPU or a remote I/O head gets its modules.
  Dragging a channel onto a pin binds it; a device wired beside its module is attached and bound in one step, one undo.
- **The grid** has a row per channel, with the data type, signal range, safety and rack columns beside the address,
  symbol, state, target and comment. Its filter takes the words `safety` and `bus:<net>` as well as the earlier ones.
- **The station's view.** Rack… on a station's row, Rack on the PLC tab, a double click on the station in the PLC
  panel and placing a station's part open its rack as a view in a tab beside the page tabs, not as a dialog: the
  window keeps working around it (Properties, selection, undo), and Esc goes back to the page, the tab staying. The
  view draws the rack, one card per place (the head, then each slot), which says what the module gives, its tag, its
  part number and the page it is drawn on; under it a table lists the same places with the slot, the module, its part
  (number and description), what it gives, its addresses and its page. A module without a part says so and offers
  Choose part…. Channels lists the channels of the selected module with their address, symbol and what is wired to
  them, a link to its place on its page, and To do says in a sentence each what is wrong or left, with its fix beside
  it. The catalogue at the right lists the parts that fit the station by kind under a filter: a part that does not
  fit the selected slot is greyed with the reason, and so is a library part that nothing can draw yet because it has
  no pins, with what to do in the part editor. A module goes into the rack by a double click on its part in the
  catalogue (into the selected free slot, else the first free one) or by dragging it onto a slot, is moved by
  dragging its card (onto another module the two change places and the addresses follow) and is changed from the bar
  above the rack (Replace, Remove, Draw on page, Go to page, Move left and Move right), from a right click, with
  Delete (it empties the slot) and with the arrow keys. A slot the part does not allow, a slot that is taken and a
  full rack are refused with the reason under the rack (EW-PLC-011). A station whose part takes no modules, such as a
  valve terminal of valve positions alone, shows no free slot. A valve terminal's positions are filled in the same
  view: a position shows its valve's part, and its right-click menu speaks of the valve. A station's view that stands
  beside another tab shows its table, channels and To do as well, and in a narrow pane it leaves the catalogue out
  until you click in it.
- **Re-address…** on a module, or on a configuration project for all its modules, previews every address that moves
  ("channel 3 of -201U5: Q10.3 → Q2.3") in the Preview tab, and Apply makes it one undo step. **Make manual addresses
  automatic…** drops the manual addresses that equal the derived ones, and says which it keeps because dropping them
  would move another module. **Freeze addresses…** makes the address of every used or reserved channel manual and pins
  the module starts, so that a module inserted later moves nothing; a spare channel keeps its automatic address. Freeze
  is refused under a tag-based address profile. The three are also in the Addresses menu of the PLC panel and of
  the grid; Apply says in a toast how many addresses it changed, and a manual address carries the badge manual in the
  panel and a lock in the grid.
- **Properties** show a station's role, order and configuration project in words; a module's station is chosen by
  attaching it, and a channel's binding names its pin.
- **Targets.** A channel bound to a module's pin takes the field device its signal reaches as its target, with the
  terminals it passes (the I/O list's target and target pin). That device's address slot prints the channel's address.
  Addresses at terminals, in the Addresses group of the PLC tab, prints the address at the terminals on the path as
  well.
- **Safety data.** Safety data… on a module sets its F-source and F-destination address and its F-watchdog time;
  Mode and safety… on a channel sets a multi-function port's mode and the channel's safety evaluation and requirement.
  The rules EW-SAF-001 to -003 check the F-addresses, the 1oo2 pairs and the test pulses.
- **Symbols and tags.** Symbol policy… on a configuration project sets the template that gives a channel without a
  manual symbol its symbol, whether symbols are strict IEC 61131-3 identifiers and the tag table. Process-tag
  scheme… on the PLC tab sets the pattern process tags follow. A further built-in address profile, Rockwell Logix
  (tag-based), prints `Local:3:O.Data.1` from the station and the slot.
- **IO-Link, PROFINET and EtherCAT.** A part can describe an IO-Link master's ports, and each port's devices take
  their process-data windows from their parts; addresses of the three buses are typed forms, not text.

### The bus navigator

The rail's Bus shows the bus navigator: the logical nets with their rates and ports, the physical nets with their
segments, ends, terminations and cables, and the ports that belong to no net. Shown as a table it edits a port's
address and termination. Properties names a port's nets and reads its address as the reports print it. A CPU's row
offers Place port for each port its part has and no symbol draws, with the symbol of its bus (PROFIBUS DP,
PROFINET). On a bus-topology page the Wire tool draws bus lines, and a bus line puts the ports it joins into one
logical net: the net one of them names, else a new net named for the bus with the CPU's port as its master. A bus
plug passes the net through. A bus cable's core lands on the pin of its signal at each port, and the cable diagram prints those pins. The PLC
tab's New bus page makes a bus-topology page, and a bus-topology page that holds nothing yet says its three steps:
place the stations, connect their ports with Wire, give their addresses in the Bus panel. In Properties a bus port's
Main rows hold what a person types first: the device name and IP of a PROFINET port, the station address of a
PROFIBUS port.

A station or bus device the project has already is put onto a bus-topology page, not made again: Put a station
on this page… in the page's menu and at the top of the PLC tab's Place port list places it with a box for each bus
interface; a row dragged from the PLC, Bus or Devices list onto the page does the same, and a drop that cannot be
taken says why. Placing a station's part, or the Black box tool, on a bus page asks first: put the station the
project has here, or a new station. The chip for a device drawn on another page reads as a jump ("Go to page 1,
A0") and has Put it here beside it on a bus page.

A bus line has its own cable and plugs. With bus lines selected, Cable… (the Draw tab's button, first in the line's
right-click menu) opens a form for the cable that carries them: its type (the cables made for that bus come first),
its tag, its length, and with one line selected the plug at each end with its termination. A line just drawn
without a cable says so in a toast with Choose cable…. The line's Properties have Cable and Plugs rows, in Main, that
open the same form. Another type chosen for the line's own cable is that cable's type, its cores following.
Applying is one undo step. The Cable form of wires on a wiring page asks the same, the cable type, the tag and the
length, then the cores; the length can wait (the row says that Check project then lists the cable as having no
length and the parts list counts 1 m), and a length typed there is the cable's. A cable mark's tag stays
inside the drawing area.

- **The cable's tag** is numbered on its line's page, as a cable drawn on that page is (-501W1 on page 501), and
  stands at the line in the tag style with its type under it; it can be moved like the mark of a cable. The form
  proposes the tag the cable will get. A further line can run on in a bus cable the project has (the form offers
  them), and a new cable chosen for a line replaces the old one in the same undo step when nothing else uses it,
  so the replaced cable does not stay in the lists.
- **New bus cable… and New plug…** end the form's lists of cables and plugs. New bus cable… asks for the maker, the
  name, the part number and the bus the cable is made for, whose cores it fills as the bus has them; New plug… asks
  the same and the bus, the cable outlet (straight or angled), a programming socket and a switchable terminating
  resistor. Save returns to the form with the new part chosen.
- **The cable's cores** are used by the bus line: the cable overview names their ends (a port's pin, or the port;
  an end at an interruption point by its name), and Connect cores offers none of them for a wire.
- **In the lists.** The parts list, the Parts navigator and the order list count a bus line's cable and plugs at
  once; a plug at an end without a device (an interruption point) counts too, with the line's page as its place. A
  cable with a length counts that length in the parts list. A generated list that runs on to another page says so in
  the bar at the foot of the page ("This list continues on page 301.1"): accessories such as plugs stand after the
  placed parts, so they can be on the list's second page.

The starter parts hold ten generic plugs (PROFIBUS with switchable termination, the same with a programming socket,
RJ45 and M12 D-coded for PROFINET, M12 B-coded, and the plugs of EtherCAT, EtherNet/IP, Modbus TCP, CANopen and
IO-Link) and a generic cable for every bus (section 4).

### Your own PLC and bus parts

A part with ports or channels is made in the window; the guide's
[Make your own PLC or bus part](../book/src/how-to/own-parts.md) goes through a module, a head station, a switch and a
PROFINET device typed from the data sheet.

- **New part.** Edit ▸ New part…, and New part… in the part dialog and the device browser, open the part editor on a
  new part. Save puts it into My parts, so that the next project has it, and into the project. A part in My parts or in a
  company library is offered in every project wherever parts are offered: the device browser, a station's
  catalogue, the Cable form's type list and a device's Parts row.
- **Bus interfaces.** A row per interface: its name, port label, bus system, role, number of ports and termination
  switch. One interface has one address, however many ports it has. The Bus table's Address cell and a port's
  Address row in Properties say the form for that bus with an example (a PROFINET address is a name and an IP
  address: "plc1 192.168.0.1").
- **Switches and devices.** An unmanaged switch has ports and no address: it passes the net through, and the Bus
  navigator lists it under the net with "passes the net through". A managed switch and a PROFINET device that is no
  PLC (a drive, a gateway) are nodes of the net with one name and IP address. The starter parts hold a five-port
  unmanaged switch, an eight-port managed switch and a generic PROFINET device.
- **Placed with its ports.** On a bus-topology page a device whose part has bus interfaces, a station as well as a
  switch or a drive, is drawn with its ports; no symbol has to be drawn first. Each interface is a box of its own
  with a connection point per port (P1 … Pn, or the interface's name where the part counts none), and the box
  prints the address ("Node switch-1 192.168.0.2", "Node TBD" while it is open). A station's supply pins stay off
  the bus page; its black box is placed on a schematic page. The Bus panel lists Ports not drawn yet, each with
  Place port.
- **Corrected later.** Edit part… on a part of your own opens the same forms with what was saved. A part of My parts
  is saved as its next version, and the update card lists the changed fields and the devices that use it before
  the project takes it; a part that is in the project only changes in place. The card says the change in words
  ("Interface X1: 8 ports → 6 ports") and names a bus line on a port the part no longer has. A device already
  drawn follows the correction: its box shows the ports the part still has. A starter part says that it cannot be
  changed and offers Copy as a part of your own….
- **The PLC section.** A station or a module: its channels (kind, count, data type), the pin pattern with a preview of
  its first and last pin, the supply pins, the allowed slots and a station's most modules. A module made this way,
  placed beside a CPU, is attached, addressed and bound to its pins. New part… in the new-station view starts as
  the kind of part asked for: a station with a controller interface for a PLC (CPU), with a device interface for
  remote I/O, with eight outputs or inputs for a valve terminal or a compact device, a module part from Add module….
  Saved, the new part is the head or module part the view uses.
- **Size and mounting.** The part editor has a section Size and mounting: width, height and depth in mm, how the part
  is fixed (on a rail, screwed to the plate, in a door cut-out, or not mounted), its mass and the clearance the layout
  keeps free on each side, with the size drawn to scale over a 35 mm rail. A device in the layout's Unplaced devices
  navigator whose part has no size offers Give it a size… in its row's menu. A length or a mass that is not a number is
  refused in words. The part's drawn front view has no editor.
- **From the symbol editor.** Make a part for this symbol…, in the editor's Draft menu, opens a new part that is drawn
  with that symbol.

### The symbol editor and the device box

The symbol editor is built as the main window is. With nothing in hand it shows a start card: New symbol, Copy a library
symbol…, Device box for a part…, Import a file…, the draft in hand and the symbols edited lately; Start in the command
bar returns to it. With a symbol in hand the command bar holds the tools, the symbol's outline stands on the left (its
connection points, texts and shapes, and To do, which lists what keeps the symbol from being saved), the drawing in
the middle and Properties on the right. A tool's options stand on a card on the drawing, and Properties show the
rows of what is selected, as a page does. The guide's [Symbol editor](../book/src/reference/symbol-editor.md) goes
through it.

- **Selection and keys as on a page.** A rectangle dragged from empty paper selects the things inside it (the things
  it touches when dragged to the left), Shift and Ctrl add and toggle, and the arrow keys, Delete, Ctrl+C, Ctrl+X,
  Ctrl+V, Ctrl+D and Ctrl+A work as they do on a page; a copy also goes to the system clipboard, so Ctrl+V pastes it.
  A shape that is not filled is taken by its line (a click on it, or a rectangle dragged to the left that crosses
  it); a click or a drag inside it is on empty paper and draws a selection rectangle, so the shape does not move away
  from its leads. A selected shape shows handles to reshape it. A thing's place and size are rows in Properties; Draw
  by coordinates and the pin-mapping list are gone. Redraw them works inside the editor, the page's toasts leave when
  the editor opens, Properties scrolls to its foot, and Close box returns to where the editor was opened from.
- **What it is** asks what a symbol stands for in a panel builder's words, and decides how the symbol's device is listed
  and checked. It offers pressure switch or sensor, position switch or sensor, thermostat or temperature switch,
  heater, transformer, pressure switch or gauge (fluid) and flow control, besides the kinds before them, so that the
  device takes the letter its kind needs. A connection point put on the end of a lead faces along that lead, and
  Copy a library symbol… names the grid of each symbol ("Lamp (4 mm grid)", "Lamp (QET 10 px grid)"). Under More, Function type shows the program's own word for it with the meaning under the list, and
  Ready-made function (Use this function, Take off) takes a function of a library. A symbol's discipline
  (electrical, pneumatic, vacuum, hydraulic or bus) is set beside it, and the symbol browser shows it.
- **The device box.** A device that is a box with pins, such as a power supply, a drive or a protective device, needs
  no drawing: its part says which pins it has, where they stand on its box and how large the box is, and placing the
  part draws that box with one click. The editor edits it on the same screen. The ways in are Device box for a part…
  on the start card, Pins and box… in the part editor and in the device browser under a part drawn as a box, and Edit
  this device's box… in the menu of a box on a page. Device box for a part… lists every part drawn as a box, of the
  project and of every installed library, placed or not, each with its library; you type to filter it, and it says
  when nothing matches and why a PLC card or a bus device is not listed (its pins come from its channels or its
  ports). A part you cannot change, such as a starter part, opens as a copy of your own: a line over the box says what
  Save makes (a copy in your own library, or in the project for a part the project holds), and the original stays as
  it is. The device browser draws such a part's box with its pins. Copy, Cut, Paste and Duplicate act on the selected
  pins of a box. A pin is added, removed, renamed, given a potential and dragged along its edge
  or onto another edge (a dragged pin keeps its side, stays a step from each corner and never lands on another
  pin); the box is sized by any edge or corner: the pins of the edge that changed stay centred on it and off the
  corners, the pins on the other edges stay where they are, and the box goes no smaller than its pins and their
  names on two lines need (the drag stops, and the status line says why). Centre the pins in a box's right-click
  menu centres the pins of every edge. A box drawn on a page of another grid keeps its layout, with the distances rounded up to the
  page's grid, and a box near the frame's edge is no longer refused. After a layout is saved, Redraw them lists the
  boxes of that part that are still drawn the old way and redraws them with their wires. A part's pins can also be
  added, removed, renamed and given a potential in the part editor. A new part without a PLC role no longer gets an
  empty PLC section.
- **A box drawn without a part takes pins where it stands.** A plain box of the Black box tool has no part and so no
  pins to begin with; Add pin in its right-click menu puts a pin on the edge nearest the click and asks its name in place
  (Enter adds it, Tab adds it and asks for the next pin one step further along the same side, Esc cancels). A wire
  drawn to a free point of its edge asks for a pin there in the same way, and the pin and the wire are one undo
  step. A double click on a pin renames it, and Remove pin in its right-click menu takes it away while no wire
  holds it; a name with a space in it or one the box has already is refused in words. The name is stored with the
  pin (`BoxCp.name`, section 4), which gives the box's device its own pins to wire to.
  On the box of a part Add pin opens the part's device box and says why: its pins are the part's.
- **Pin texts of a box stand upright** on every edge, also on the top and the bottom, beside their pins. Two texts
  that would touch stand on two lines, and a text near a corner moves along its side so that it stays inside the
  box's outline. A rack's card drawn with Draw on a page grows so that its texts fit on one line; a box that you draw keeps the
  size you drew, and its texts take two lines where they would touch. A box
  too narrow for its cross-reference has it stand outside.
- **A symbol of another grid.** A symbol drawn on a connection grid other than the page's (a 4 mm symbol on a QET
  10 px page, or the reverse) is placed on the page in front: the project gets a copy of it drawn on the page's grid,
  every connection point on the grid point of its own number, and the picker says so under Place. Place on a new
  page with its grid is the second choice. A page's type that does not take the symbol (a fluid pressure switch on a
  schematic page) still greys its row with the reason.

### The exchange with PLC software

- **Where.** The PLC tab holds the group PLC exchange with Export to PLC and Import from PLC (the buttons of Export to
  PLC software… and Import from PLC software…).
- **Export.** Export to PLC software… is a form: the format (AutomationML AR APC 1.4.0, or 1.2.0 for older
  PLC software; the TIA Portal "PLC Tags" workbook; PLCopen XML for CODESYS), the stations and the document date, which starts as
  today's. It asks for the file under a name that fits the format (`plc.aml`, `plc.xlsx`, `plc.xml`), writes it whole or not at all and says what it holds. An AutomationML file or a tag workbook is
  recorded in the project as the base of the next import. A PLCopen list is never recorded: it does not come back.
- **Import.** Import from PLC software… previews the file against that base in four tabs: Changed (each
  field with the project's value, the file's value and what the import makes of it: applied, rejected, kept or
  pending), Conflicts (both sides changed it: keep the project's value or take the file's), Removed (what the file no
  longer holds) and Parking (objects of the file that match nothing, or more than one; a module or station can be
  created unplaced). A refusal that Apply would make is shown before you choose Apply, with the rows it concerns. The
  card has a box, The file is complete: tick it when what the file does not hold was removed in the PLC software.
  Apply commits what the preview showed, as one undo step.
- **What ownership protects.** After the first import that gives a value the PLC owns, the project refuses to edit
  that value until you unlock it: a module's start, a station's firmware, a bus port's address and, when you gave the
  symbols to the PLC, a channel's symbol and comment. Unlock module starts, Unlock symbols and Unlock PLC data are
  on the configuration project's row. An import turns every start it gives into a manual start, so a module
  inserted later moves none.
- **Instrument list.** Import instrument list… on a configuration project reads a CSV or workbook of process tags and
  signal types, previews it, and on Apply gives each tag a placeholder device and spare channels of its kind.
- **New rules.** EW-PLC-016 says the configuration project changed since its last exchange; EW-PRC-002 reports an
  instrument tag without a device or channel.

### The fluid workspace

The Fluid power button of the workspace switch, or View ▸ Workspaces ▸ Fluid power, shows the fluid navigator (valve
terminals, their modules and valves, other fluid devices, with their lines, and the media), and the tube table and
medium table in the bottom dock. The tools are on the Fluid tab of the command bar. The guide's
[Work in the Fluid workspace](../book/src/how-to/fluid-workspace.md) goes through it.

- **Valves.** A valve is described by its switching positions, flow paths and actuators, so the program knows what
  each position connects. The starter set has 50 ISO 1219 pneumatic symbols besides those of 0.2.0 (directional valves
  with a solenoid, a lever, a push button or a roller, cylinders and drives, vacuum, air preparation, flow and logic
  valves, fittings, the air supply and the valve-terminal supply plate) with their function definitions. A valve
  terminal's galleries are derived from its modules.
- **Smaller symbols.** Every ISO 1219 symbol, those of 0.2.0 too, is drawn on one 12 mm module: a valve position is a
  12 mm square with its ports 4 mm apart, so a fluid symbol stands beside an electrical one at a like size. A project
  that holds the earlier drawing is offered the update; the update keeps each tube on its port, stretching its end
  segments where the port moved.
- **Pneumatic parts.** The starter parts hold the basic pneumatic parts with their symbols: solenoid, lever, push
  button and roller valves in 2/2, 3/2, 5/2 and 5/3 forms, single and double-acting, cushioned, magnetic and rodless
  cylinders, a rotary actuator, a gripper, a suction cup and an ejector, filters with and without a drain, regulators,
  a lubricator, service units, an air reservoir, a condensate drain, a soft-start valve, a distributor, flow control,
  non-return, quick-exhaust, shuttle and dual-pressure valves, gauges and pressure switches, a silencer, an exhaust
  port and a blanking plug, besides an air supply, three tubes (PU 6×4, 8×6 and 10×8 mm) and two fittings.
- **A valve's solenoid.** The valve's menu says what to do with each solenoid of its part: Draw solenoid 14 on an
  electrical page…, which asks you to click where the coil goes, or Go to solenoid 14 at its page once it is drawn. The valve's Properties list each solenoid with its PLC output, and a coil's Properties say which solenoid of
  which valve it is. Going to a valve or its coil selects that symbol and names it. A coil's row in the Devices list offers the same entries (Draw solenoid 14 on this page…, Go to the valve), Follow reference goes from a coil to its valve, and with an electrical page in front the solenoid is drawn there; from another page a form asks which electrical page. Typing a valve's tag into a coil's Tag offers to make that symbol the valve's solenoid. The
  solenoid coil symbol is `ew.iec.valve-solenoid`. The starter valves EW-GEN-VLV-1 and -2 have the valve as their
  main function.
- **One word.** The window calls a drawn fluid line a tube, in its menus, its Properties, its findings and its
  tables.
- **Media.** New medium… (Media group of the Fluid tab) adds a medium: it starts from a usual medium (compressed air,
  vacuum, hydraulic oil, cooling water, lubricant, inert gas) that fills the name and the usual pressure, and the
  form says what each field means. The Fluid panel offers New medium… and Fluid settings… beside its filter. A
  tube's right-click menu and its Properties set its medium and its line kind; Properties also show the tube's
  effective size and material and where each comes from. A tube's length is typed in mm, or with its unit (2 m,
  35 cm). A medium set on several tubes holds on all of them;
  in a project with no medium yet the Medium list offers the usual media ("Compressed air, 6 bar" and the others)
  to choose straight away, besides New medium…; an air supply's Properties show and set its medium. The medium follows the line's net and the media pass through the valves' flow paths. A medium's row highlights its
  zones in colour and hatch. The medium table counts the consumers of each medium, actuators included.
- **Tubes.** A line takes its tube from the project's default (Fluid settings…: outer and inner diameter, material,
  how fluid lines are tagged), a part or a typed length. The tube table says where each value comes from.
  A tube that goes from page to page through fluid interruption points is counted as one tube, and a tee carries a
  fitting of its own.
- **Routes.** A tube takes a route as a wire does. A route crosses a text where keeping clear of it would be a far
  longer way (more than 8/5 of the route across), and the hint line and Route page's row say so; a short step aside
  to keep clear of a text is still taken, and a body, a port or another line is never crossed. A crossed tag moves
  off the line where its symbol has a free place; a black box's caption stays, and EW-CORE-070 reports it once.
  A line leaves a pin through an interruption point drawn on it, so Reroute no longer leaves such a wire
  unrouted. While a tube is drawn, the hint line says what a click will do (a bend, a tee on another line); the Wire
  tool refuses a bend inside a symbol and says why, and its first hint says that clicking free points leads the wire.
- **Drawing.** The Tube tool on the Fluid tab draws at once, and its bar shows the line kind and the tube it draws
  with; Tube… picks the kind (Pilot, Exhaust, Drain, Flexible). Fluid symbol, Valve terminal… and Air supply… work
  from any page of a project that can be changed: on the fluid page in front, else on the nearest one, else on a
  fluid page made there and then (a toast says so). The Tube stays a tool of the fluid page in front, and its hover
  names the fluid page when it is greyed. Fluid ports autoconnect with fluid lines on fluid pages, never to an electrical point and never an exhaust port to a
  working port; an in-line fitting (a flow control, check valve, throttle, coupling or bulkhead: two generic ports)
  is never joined to a fitting beside it, so a row of them stays a row, and one facing a cylinder's or a valve's
  port still joins. A flexible line is
  drawn as an arc. The interruption point tool places the fluid form of a point on a fluid page.
- **Valve terminals.** A valve terminal is one of two kinds, and the window says which under the device's title: with
  a bus node it is a PLC station on its bus (the starter EW-GEN-VTM-1, listed in the PLC lists too); a multipin
  terminal is wired through one plug (the starter EW-GEN-VTP-1: eight positions, a 25-pin plug). Both are filed under
  Valve terminals in the device browser, are placed with one click on a fluid page (one click places one terminal,
  the toast names its positions, and a box is never placed on another box) and show in the Fluid navigator. A
  terminal's menu lists every position from anywhere on its body; its kind and medium lines are headings.
  Properties' header, the menu's heading and the Devices list's hover say the kind in words: "Valve terminal ·
  multipin, wired" or "Valve terminal · PLC station on PROFIBUS DP". A terminal placed at the frame's edge is
  moved inside it; one larger than the drawing area is refused with both sizes.
  Each is drawn as its positions: a supply end, then numbered cells. An empty position is dashed, a blanking plate is
  drawn as one, and a valve stands in its cell as its own symbol, with its tag and its output, however the position
  was filled (from the station's view, the PLC list or the window): its working ports 2 and 4 stand at the cell's top
  edge, where a tube is drawn to them. A terminal without a supply plate has its own supply at its left end, the
  supply port 1 and the exhausts 3 and 5, and the sub-base draws the galleries, each valve port joined to its own. A
  position is as wide as its valve needs, so a 5/3 valve (the starter part EW-GEN-VLV-53) widens it; a valve that
  has no symbol at all is refused for a position, with the reason. Draw its valves in the valve terminal, in the
  terminal's menu, in the station view's To do and as the quick fix of EW-CORE-047, draws the valves of a terminal
  whose positions an earlier build filled without drawing them.
- **Filling a terminal.** A position is filled where it is drawn: click an empty cell (the device browser narrows to
  valves for a terminal), or drop or drag a valve onto it; a drop on a held position swaps the two. A cell's menu
  offers Fill position…, Replace at position…, Empty position and Blanking plate at position, and the station's view
  lists the positions as rows. The browser of an empty cell lists Blanking plate first, and the finding for an
  empty position (EW-FL-013) says where the blanking plate is and fixes it (Blanking plate on position n; Fix all
  blanks every empty position in one step). Only a valve made for a terminal is taken into it: a stand-alone valve, a coil or a
  cylinder stays a device of its own, and a toast says so. The Valve position row of Properties shows only for a
  terminal valve, and typing a position that another valve holds offers Swap. A terminal drawn as a free box in an
  earlier project keeps its look; its menu offers Draw as slots, which previews the change. A valve terminal made as a
  PLC station is drawn on a fluid page from Fluid ▸ Valve terminal…, which offers "Draw -…A1 here" before "A new
  valve terminal…", and from the station's view (To do) and the station's PLC row (Draw on a fluid page…). Every one
  of these reaches a fluid page also for a terminal that was put on a bus page first: with several fluid pages the
  button asks which, with none it makes one and a toast says so, and where it cannot it says why. A valve that has one
  solenoid (the 5/2 for a terminal, the 3/2 and 2/2 valves) prints its PLC address inside its cell, under the cell's
  top line.
- **A terminal valve's solenoid.** Its row in Properties says where the solenoid is driven from: "driven by output
  Q0.0 of -… (inside the valve terminal: nothing to wire)" on a terminal with a bus node, "pin 3 of the plug of …" on
  a multipin terminal; its menu says Go to the output of solenoid 14. On a multipin terminal, Draw the plug of … on an
  electrical page… draws the plug: from the terminal's menu on any page, from the Plug row of its Properties or with
  Draw plug in the Lists group of the Fluid tab. With an electrical page in front the plug is drawn there; from another page a form asks which electrical page, with New page… offered. The plug is placed with one click; its pins run down both sides
  with horizontal texts, and beside each pin stands the valve and solenoid it drives, the position where it is
  empty, and COM for the common. A PLC output wired to a plug pin drives
  that solenoid: the valve's cell shows the output's address, and EW-FL-002 no longer reports the solenoid as without
  an output.
- **Plug ports.** Plug ports on the Fluid tab, beside the Tube, plugs the open working ports of the selected valves
  in one undo step; it is greyed with its reason (Select a valve whose working ports are open) while no selected
  valve has one. The finding for a working port that is open (EW-FL-001) offers the same as its fix, Plug the open
  ports, and Fix all joins the plugs of every valve of its group into one step. Set spare in a valve's menu plugs its
  open ports with it, so a spare valve asks for nothing; the rule still reports a spare valve whose ports are open.
- **The overview.** A valve's row sets it spare or used, blanks a position, adds a valve and plugs an open working
  port. **Generate overview…** on a valve terminal's row lays out its assembly overview on its overview pages, adds
  pages where the frame is full and previews the change in the Preview tab; run again after adding a module, it
  changes nothing that is in order. The page carries the terminal's name as its title, and a member drawn for the
  first time takes a module symbol wide enough for its part number.
- **The lists.** The tube list, tube cut list, tube labels, valve-terminal configuration and medium overview
  (section 5), and tube, fitting and tee lines in the bill of materials.
- **New rules.** EW-FL-005 (two media in one net), -006 (tube does not fit), -007 (tube without specification),
  -008 (exhaust open), -009 (coil voltage), -010 (no air reaches a port or a terminal's common supply), -012
  (port-role conflict) and -014 (tube crosses a location). EW-FL-002, -004 and -010 say in plain words that no
  output drives a solenoid, that a position is closed by a blanking plate and that no air reaches a port.

### Starting a project, and templates

New project opens a dialog with a name, the folder the project is made in (Browse… chooses it, and the dialog says where
it will be made) and what the project starts from: an empty project (one empty page, with the program's frame and title
block and its settings), a template, or another project. Each choice says in words what it brings: its frame and title
block, its check level, its text styles, its sections and its pages. A template's pages and their devices come along
only when Also copy its pages is ticked; without it the project starts with one empty page. The template that is used
for new projects is offered first. The guide's [Start a project](../book/src/how-to/start-a-project.md) goes through it.

- **Why Create waits.** While something is missing or wrong, a line over Create says what: no name, a folder that is
  not there, a path that is not whole and no projects folder to read it from, or a project of that name there
  already. A folder typed without its whole path, such as `Pumps`, is a folder in your projects folder, which Create
  makes when it is not there yet. Browse… that comes back with nothing leaves what you typed as it was.

- **Templates…** (the start page and the Project tab) lists your templates, each with its folder and what it brings.
  Use for new projects chooses the one New project offers first; Edit opens the template as a project, with a band
  that says you are editing it and Template in the title bar (a template is not a recent project); Rename and Remove from
  the list change the list only, as the folder stays on the disk. A new name is saved with Enter, with Save name or
  by leaving the field, and a name another template has is refused. New template… starts the template wizard, and Add a
  folder… takes a template somebody gave you. The one template of an earlier settings file becomes a list of one.
- **Save as template…** (Project) makes a template of the open project: its settings, frames and title blocks, text
  styles, sections and structure, and its pages and their devices only when you tick the box.
- **The template wizard** writes the check level when you press Create, so the pop-up that asked to apply it is gone;
  its last step asks whether new projects use the template, and its review says each choice in words. It makes the
  template in a folder of its own, named after it, in Templates in your projects folder (with a number after the name
  when that folder is taken, so a full folder is never a dead end); Choose another folder… on the review puts it in
  another folder. Close asks first when there are answers in the wizard: Close keeps them for the next time, Back to
  the wizard stays, and Close and drop my answers deletes them. The step that sets the cross-section a wire gets is
  called Wire cross-sections. The window calls all this a template, where it said company standard and basic project
  before (in Dutch: sjabloon).
- **The template a project came from.** The project's own Properties name it, by its name in your list, or say that
  it is no template of your list. A template whose projects start with one empty page says "one empty page" where it
  said "no pages".
- **The people of a project.** The project's Properties show one plain row for each person a title block can print:
  Designer, Checker, Customer, End user, Panel builder and Engineer, each typed as a name; the list of parties with
  their addresses stands under More. The title block's Author cell prints the Designer while no revision names an
  author (only a person at the window makes the designer a revision's author), and Title block fields… says under
  each field which cell of the sheet prints it.
- **Sections in a running project.** Edit section… (on a section's row in the Pages list and on the section links of
  the project's Properties, beside New section…) changes a section's title and its first and last folio in one step;
  a range that runs backwards is refused in words. A page put in a section that does not exist is refused with how to
  make it (New section…).
- **Check level…** (Project ▸ Setup) says how strictly the drawings are checked before they go out, in plain words, and
  offers the two levels that check differently: Pre-delivery, what must be right before drawings go out, and Full, every
  check, the tidiness checks too. A project that names the drafting level keeps it and reads as Full.

### Wires and cables

- **A wire's highlight.** A wire is hovered and selected along its own line, as a band round its path, never as the
  box round its two ends, so a wire cannot be picked far from where it runs. A tube is the same.
- **Handles.** A selected wire shows round handles on its segments and bends: drag one to change the route. With one
  wire selected, Tab and Shift+Tab choose a handle, the arrow keys move it one grid step and Esc returns to the wire;
  the bar at the foot of the canvas says Tab for it. Tab starts at the end of the wire a person reads first (the
  upper, else the left one) and goes along to the other, and the bar names the handle: its place along the wire,
  whether its segment is horizontal or vertical and the arrows that move it, or a bend. An arrow that cannot move the
  handle says why: along its segment it does not go, or the wire's ends would leave their connection points or its
  corners would lose their square.
- **Reroute.** Reroute on the Draw tab, beside Wire, replaces Edit route and Route selection: it routes the selected
  wires, or with nothing selected the whole page, at once and in one undo step. It starts from the drawing: a wire
  gets a new route only where its own breaks a rule, or where a shorter one with fewer corners and crossings
  exists, so a well-drawn wire stays as it is and a page is never worse afterwards. A wire drawn through a text gets a
  route clear of it wherever the Wire tool would draw one, also when the text belongs to a device the wire ends at
  (ADR-0033, amendment 5). Its toast names the wires it changed, by their numbers or else their ends (three, then how
  many more), and the page shows them as selected wires while the toast is up; where nothing changes it says that
  the wires already run as well as the program can route them. Route page beside it routes only the wires that have
  no route yet, and the tooltips of the two buttons say so. The Wire tool never stores a route that runs through a pin or along another wire,
  and puts no junction where two wires cross.
- **The router.** Two-pole devices wired cross-over close together cross once between the devices, where the router
  steps half a grid step if the whole grid gives only a detour (ADR-0033, amendment 3); a wire's corner never lands on
  another wire's corner or end, and Reroute mends what breaks a rule in an older drawing. A page routed for the first
  time (Route page, an import, the wires a paste or a grid change draws anew) is solved in two orders, and the
  drawing of the shorter wires first is taken where it rates better and costs no more unrouted wires, bends,
  crossings or crossed texts (ADR-0033, amendment 4). Wires go round the texts beside a multipin plug's pins. On
  the QET grid a wire from a junction no longer loops round the wire it starts from.
- **Editing between grids.** A paste onto a page of another connection grid is fitted to it: each item moves to its
  nearest grid point (a symbol by its first pin), its wires are drawn anew, and a message says how many items
  moved; Undo takes all back in one step. The pasted block hangs on the pointer at once (in the middle of the view
  until the pointer moves), and a click where part of it would leave the drawing area is refused in the status line.
  Where the router finds no way for some of the pasted wires, they stay dashed and the message counts them and says
  to move the items apart and choose Reroute. A paste between page kinds stays refused, and says why. A page's grid is
  changed on the Page tab (Connection grid…, in the Order group) or in Properties (Change the connection grid…),
  which asks first, says how many items move and how many
  wires are drawn anew, and fits them the same way; every page that holds anything asks, also a page of texts only.
  A symbol that was fitted to another grid moves, turns and pastes by grid steps like any other.
- **A cable's mark.** A cable's mark is drawn as panel builders draw it: the cable's tag, under it its type and size, a
  stroke across each wire at its core and each core's name beside its wire. Cable… places it on every page the cable
  goes over, Connect cores… and every other way a wire becomes a core place it, and a wire that leaves a cable leaves
  its mark. Its tag and type line keep clear of other texts and symbols, at the line's other end when needed. Clicked
  on the page, the mark selects as its cable: Properties show the cable's rows under its tag, headed "Mark of the
  cable", and the status line names it. The Devices list counts a cable as drawn where its cores run and a terminal
  strip as drawn where its terminals stand, and the row opens that page.
- **A core's cross-section** and colour come from its cable: a wire in a cable has them at once, and its Properties say
  where they come from. Its cross-section and colour rows take a click, Enter or typing and say under them that the
  cable sets them, with a button, Change it at cable -1W1, that shows the cable's Properties at its Part row. Giving a
  cable a part sets its cores from the part, and a part with too few cores for the wires, or without a protective
  conductor for a PE wire, is refused.
- **A cable's part.** A cable's Part row in Properties takes any cable of the libraries, not only the parts the project
  holds, and embeds the one chosen with the edit. The cores follow in the same step: the wires stay cores in their
  order, the cores' cross-sections and colours become the part's, and the cable's mark reads the new type alone. One
  undo takes it all back.
- **The cable type.** Cable… asks for the cable type first and lists the parts that fit; a part that does not fit is
  greyed with the reason. New cable type… at the end of the list makes a cable part from its data sheet (cores,
  cross-section, colours or numbers, shield, outer diameter), and Save and add another size keeps all but the part
  number and the cross-section for the next size of a series; a part of the kind cable shows the same section in the
  part editor, and a cable's part dialog offers cable parts only. A cable's size reads 3G1.5 or 4X0.75. A cable
  without a part is a warning with Choose a cable type… beside it (EW-CORE-041). The parts Cable… offers for the
  selected wires have a core for each: a green-yellow core for a wire whose potential says PE, another core for each
  other wire. A type typed that still leaves a wire without a core says which wire and why under the form, and Apply
  makes no cable until every wire has one.
- **Generic cables.** The starter parts hold 22 generic cables, EW-GEN-CBL-4 to -25: two to twelve cores, 0.75 to
  6 mm², some shielded.
- **Supply.** Supply on the Draw tab, beside Interruption, places what comes in from the mains in one go. Its form
  asks what comes in (single phase L, N, PE; three phase with or without N; 24 V DC; your own names) and where it
  comes from; the marks follow the pointer as one group, one click places them in one undo step, and the Potential
  panel opens at them (below). The command search finds it by supply, mains, incoming and feed (in Dutch
  voeding, inkomend, invoeding and net).
- **Supply points in a group.** Where the supply comes from… changes where marked supply points come from. Supply
  points of one place that stand together print the place once; Group these supply points and Take out of its group
  are in the right-click menu, and a point's place and device can be changed in Properties. The command search finds
  Supply comes in here… (for points drawn with Interruption) and Interruption by the same words, and with no
  interruption point selected it is greyed with what to do first: draw the points with
  Interruption (L1, N, PE) and select them.
- **Terminals.** Terminal… has a Spacing in grid steps, each shown with its length on the page, which the open project
  keeps for the next row; Spacing… respaces a row of placed terminals in one undo step, their wires following.
- **Placing and wiring.** A symbol that is placed no longer wires itself to a pin far away or across other wires:
  a toast offers Connect. Connecting on placement never joins a contact (a switch, push button or sensor) to a PLC
  output, and a point that names a conductor (N, PE, L1, a supply's + or -) never takes a point of a potential
  named for another one; a plain L takes any phase, and the two sides of a terminal never join potentials of
  different names. A device drawn as a box is no contact, so its pins may join a PLC output. A two-pole device
  placed under another wires both poles: a pole that faces nothing in line joins the nearest free point up to three
  grid steps aside of a device its partner pole joins, by a wire that steps aside halfway. The Interruption point
  tool has Source and Target choices, offers the partner that is waiting first, and its toast says where the
  partner is. A direction clicked where the tool proposed it holds; D and Ctrl+Z reach the tool also when it was
  chosen with the focus in a navigator; two points of one direction are never paired, so a second target of a
  name waits for its source.
- **Define potential at a pin.** A pin that touches a terminal directly has no wire to select: Define potential at
  the pin is in the device's right-click menu, and the Define potential form asks what the potential is, not where.

### Texts and the panel layout

- **Text styles.** Project ▸ Setup ▸ Text styles… sets the height of a capital letter in mm, the typeface and bold of
  every text style, grouped by what it prints (Devices, Wires and cables, Terminals, Page, Cover and sections), each
  with a line that says what it prints. Standard sizes sets the heights a new project has (the typefaces and bold stay),
  and Reset and Reset all go back. A change shows on the drawing at once and is one undo step. The typefaces come
  with the program, so a drawing looks the same on every computer: Standard, Narrow, Mono and Technical drawing (the
  lettering of technical drawings; it has no bold, so Bold is off with it); the fonts installed on a computer are
  not offered. A free text chooses its style and can have a height of its own, and a text's Properties
  link to its style. The warning about text too small to read names the style, offers Set to 1.2 mm and opens Text styles
  at that style. A new project and a new template start with readable texts, and the number beside a terminal has a
  style of its own, smaller than the others.
- **Texts stay upright.** Turning or mirroring a symbol no longer turns its tag, its designations or its other texts:
  they keep the angle they have in the unturned symbol and stand on the side of the symbol that the turn brings
  them to. An imported QElectroTech element that QElectroTech turned keeps QElectroTech's text angles. A tag is no
  longer turned to get clear of a wire or a text: it moves to the other side of its symbol, above or below, and
  stays where it is when there is no free place. A tag never takes a place on its own symbol, and where a symbol
  turned by a half turn meets another symbol's tag or body, the tag moves off the body.
- **Texts clear of each other.** The program places texts so that they do not lie on one another: the numbers of
  terminals standing in a stack two grid steps apart, a turned breaker's part number and rating, the name of an
  interruption point on a box's pin text, and the captions of a station drawn on an empty page, which starts two
  gaps under the frame's top so that its captions stay inside the drawing area.
- **A text moves alone.** With one symbol selected, each of its texts, a black box's too, can be dragged on its own
  (on the fine grid; Alt for free), turned with R while it is dragged, hidden with Hide text in its menu and put back
  with Put the text back in the menu of the symbol or of the text. One undo step each. The tag of a symbol that is not
  selected is dragged by itself, not the symbol under it (a cross-reference still follows its link, and several
  selected symbols move together), and with nothing selected a press on a drawn box's caption outside its outline
  drags that caption alone.
- **Item numbers and a legend.** A layout page labels its devices with their tags, with item numbers in balloons or
  with both: Labels in the page's menu (Tags, Item numbers, Both) and the Labels row in its Properties. A new layout
  view takes item numbers when the tags do not fit their devices, and a view the window makes at 1:10 and smaller
  takes them as well. Add legend (the Page tab, or the page's menu) puts a legend beside the layout, and beside tags
  it offers item numbers. The legend is one table that lies inside the drawing area, with the position, tag,
  quantity, part number and description of each item: position and tag are always whole, the part number and the
  quantity give way first and then the description (a long one is cut with "…"), text shrinks before it is cut, and
  the box ends under its last row. It can be selected, moved, resized by a corner and deleted. Labels that
  would run into each other move apart. A legend that a new numbered view takes is undone with the step that made the
  view: one undo takes back the view, its scale and the legend, and one redo brings them again.
- **Labels move alone.** A label or balloon beside its device can be dragged on its own: select the device and a
  dashed box with a handle shows where. Reset label position in the device's menu, and Reset label positions in the
  page's, put them back.
- **Location.** A page that has no location of its own shows its tags, labels, legend and title block against the
  location it draws: the cabinet its layout shows, else the one location all its devices share. That location is
  left out of them, so a card given a cabinet does not print it into the next card's tag. Location… in the Devices
  list sets the location of the marked devices, or of every device of a group, in one undo step.
- **Layout tools.** Enclosure is on the Draw tab in the Layout group, with Mounting plate… under its arrow, and an
  empty layout page says "Start with an enclosure…". The Enclosure dialog draws an enclosure that a location has
  already: on a panel layout page its button reads "Draw -UC1 of +CAB1 on this page" and puts the mounting plate
  there, and on any other page it says that it draws nothing there and its button makes a panel layout page after the
  page shown and draws the enclosure on it; Create only beside it makes the enclosure without drawing it. A drop that a layout refuses says why and what to do instead.
  Auto-fill rail says why it placed nothing and offers to give the devices that have no location this cabinet's.
  A layout page with no device on its plate says the next step in the bar at the foot (give the cabinet's devices
  its location, drag them from Unplaced devices on the left rail, or Auto-fill rail), and a symbol placed there is
  refused with a reason that names the same ways. The duct tool says from its first click how it ends, and Enter finishes the duct its clicks drew; the black box tool
  shows "click two corners" at the pointer.
- **Terminals.** Place terminals starts a new strip on a page that has none and shows the strip's tag; with
  "How many" set to 4 one click places four, as one undo step. The Terminal dialog adds to the strip of the terminal
  placed last on the page, New strip standing first in its list.

### File ▸ Import… takes every file

File ▸ Import… beside Open goes on by what the file is: a QElectroTech project (`.qet`), a project archive (`.ewz`),
a drawing (`.dxf`, `.dwg`) or a PDF, an EPLAN part file (`.edz`, `.7z`, `.zip`, `.xml`) or an EPLAN report (`.xlsx`,
`.csv`). The separate entries (Import QElectroTech project…, Import drawing…, Import EPLAN data…, Parts table…) are
gone from the menus and from the Project tab's Import group, which keeps Re-import QElectroTech project…; the
command search still finds each by its name.

- **A drawing.** Add as page makes a DXF or DWG drawing a new graphic page, on the folio after the last page of its
  section. Place under page puts a DXF, DWG or PDF under the shown page as a locked underlay to redraw over; no check,
  report or export reads it, unless an export prints underlays (`ew export … --underlays`). The source stays outside
  the project unless you choose Place and embed: a customer's drawing may be confidential. A drawing that names no
  unit is read in millimetres. The symbol editor's Import a file… takes a `.dxf`, and its blocks become symbol drafts. The
  reading runs as a job in the Jobs pane, with Cancel.
- **A DWG** is read through the ODA File Converter, which ElektraWatt does not include and never downloads. Install
  it and choose its program when the import asks; the choice is kept once it has converted a file. A converter that
  hangs is stopped with what it started.
- **EDZ and parts XML.** The dialog says how many parts the file holds, how many of them the project has a copy of
  and how many of those copies would change. Update shows the changed fields and the devices that use them before
  anything changes, as one undo step; a part the project does not have is never added to it. Add to my parts library
  writes the parts into your own library; a part that was there already is updated with the file laid over it, so
  the technical data you added stays. Before the first EDZ of a session a notice says that the EPLAN Data Portal's
  terms restrict its data to EPLAN products; ElektraWatt reads the file from your disk only and records the file and
  its SHA-256 on every part.
- **An EPLAN report** (device list, terminal diagram, connection list) becomes a new project without drawings through
  a column mapping. The dialog offers the shipped German and English mappings that fit the file's headers, and your
  saved one first. A file that no mapping fits goes to Map the columns…: you say what kind of report it is and what
  each column is, the header row is found below a title, and Import saves the mapping under the file's source key for
  the next file of that report. EW-IMP-206 and EW-IMP-207 report what the import could not use.
- **QElectroTech.** A folder of QElectroTech projects imports in one run with `ew import qet --batch`, and a folder
  of QElectroTech elements becomes a library with `ew lib import qet-elements`. A static text of an imported element
  stands on QElectroTech's baseline, as QElectroTech's own PDF has it.

### DXF export

`ew export dxf` writes one AutoCAD 2000 DXF per page, with a layer per kind of object that `--layer <class>=<name>`
renames. The file is ASCII: ä, °, ² and every other character outside ASCII are written as `\U+XXXX`, so a CAD
program and ElektraWatt read the texts as written. A DXF read back as a page prints where it was drawn, also on a
page whose frame scales the page to the sheet.

### The migration verifier

`ew verify-migration <project> --reference <pdf>` compares an imported project with the PDF of its drawing: every
text with its place (within 0.5 mm) and the drawing of each frame cell with the texts masked. It stretches the
reference to the page's pixels, refuses a page above 4,096 pixels a side in words and pairs pages by the folio their
label names, so a missing page shifts none. The sample project against its own PDF reports no deviation.

### The new checks, and every scheme runs them

Until 0.2.0 a shipped check scheme ran the rules of the first release only. From 0.3.0 every shipped scheme runs every
rule that is built. **A project can show findings it did not show in 0.2.0.** The new rules are:

- PLC: EW-PLC-004 (channel kind mismatch), -005 (invalid symbol), -009 (channel without connection), -010 (data-type
  width mismatch), -011 (slot rules), -013 (card supply wrong), -014 (output load exceeds rating), -016 (changed since its
  last exchange), -017 (not a PLC module) and -018 (module drawn with its channels unbound).
  EW-PLC-013 takes the place of EW-POT-003 on a PLC card's FE pin. EW-PLC-001 and -007 also refuse an edit that
  makes an overlap or a duplicate symbol; an edit that repairs one, or any edit in a project that holds one, is
  not refused.
  EW-POT-009 ("is not connected") leaves out the pin of a PLC channel that is spare, reserved or deactivated, and
  a frozen project gives no spare channel EW-PLC-009.
- Safety and process: EW-SAF-001 (F-address), -002 (1oo2 pair), -003 (test pulse); EW-PRC-001 (process-tag scheme),
  EW-PRC-002.
- Bus: EW-BUS-002 (address outside the range), -003 (PROFINET name or IP), -005 (rate not supported), -006 (segment
  limits), -007 (no master), -009 (wrong bus cable), -010 (net mismatch); EW-IOL-001 (IO-Link port class) and -002
  (IO-Link limits). A finding that rests on a part's bus data of unverified confidence says so.
- Fluid: EW-FL-005 to -010, -012 and -014 (see above). The `pre-delivery` scheme and the `migration` scheme keep
  EW-FL-008 and -014 off; `drafting` shows them as hints.
- Imports: EW-IMP-251 to -255 and -257 (units missing, SHX font substituted, entity unsupported, external reference not
  followed, hatch pattern reduced to its boundary, DWG converted through ODA); EW-IMP-206 and -207.

The sample project shows the change: it reports EW-PLC-013 on its two FE pins where it reported EW-POT-003, EW-FL-007
on its sixteen fluid lines without a tube specification and EW-FL-010 on its valve terminal.

Some findings read differently, and open where they are mended. A double click on a finding that has no place on a
page opens the thing that mends it, such as the text style in Text styles or the device's Properties. Seven findings
that a first project meets say in plain words what is wrong and what to do: EW-POT-008, EW-POT-009, EW-CORE-041,
EW-CORE-047, EW-CORE-067, EW-CORE-068 and EW-FL-010. An earth symbol is an earth connection and asks for no part, so
EW-CORE-041 no longer reports it and its row in the Devices list says what it is. A cable without a length
(EW-CORE-033) is a warning until the check for delivery, where it is an error, and says Type the length…. A cable
without a part is a warning too, with Choose a cable type… beside it.

The findings about potentials (EW-POT-001 to -017) say what is wired to what, on which page and what to do, and
where a cause is likely they name it and the ways out (EW-POT-004 and -005 for a colour set by hand, EW-POT-006 the
size to use). EW-POT-001 reads, for example, "M (0 V) is joined to the protective earth PE on page 101, but not by a wire drawn from the 0 V
straight to an earth point. Select the wire that joins them and choose Draw ▸ Connect ▸ Bond, or take that wire
away."; EW-POT-012 is titled "Wires in a ring". Three things changed with them:

- **A wire from 0 V to earth is the bond.** A wire drawn from a 0 V point straight to an earth point joins the 0 V
  to protective earth, as a PELV circuit asks. It raises no EW-POT-001, the 0 V keeps its name, type and colour,
  EW-POT-002 counts it and the wire list shows it as a bond. A point is 0 V by its pin's role, by a potential
  defined there as 0 V (M, L-) or by the name 0V, M or L-, and an earth point is an earth symbol, a PE or FE pin or
  a point so defined or named, so a 0 V chosen from the potential list is met too. A wire from the 0 V
  to functional earth (FE) is no conflict either: the 0 V is earthed for function, and EW-POT-002 then says that
  this is no protective bond and that the wire belongs at protective earth (PE) or the PE rail. A 0 V that reaches
  earth another way still needs Draw ▸ Connect ▸ Bond.
- **A two-pole breaker does not switch the neutral alone.** EW-POT-013 no longer reports a breaker or switch whose
  function opens a phase as well as the neutral, whatever its definition says about switching N with L (a
  two-pole breaker, a main switch). It still reports a contact in the neutral alone, and its sentence says why that matters (what is behind it stays live while it looks switched
  off) and the two ways out: put the contact in the phase, or use a device that opens phase and neutral together.
- **Earth symbols of one location are one earth.** EW-POT-008 counts them and the location's incoming PE as one
  earth, and names each PE that reaches neither by its pin and page.
- **Supply marks ask what comes in.** Placing supply marks (Supply comes in here…) opens a panel, What comes in
  here, with a row for each mark: its conductor and its voltage, filled in from its name. Enter takes every row in
  one undo step; Esc places the marks without a potential. Potential… in the marks' right-click menu opens it
  again. The panel is all rows or none, closes on Undo, Redo and a change of page, drops the voltage of a row made N,
  PE, PEN or FE, and gives a phase without a voltage the project's supply voltage. Marks placed in a row each
  print where they come from, and 0 V (M) stands near the top of the panel's list of potentials. The toast of a
  placed interruption point says where the point comes from and what to do for a supply from outside.

## 4. The format

ElektraWatt 0.3.0 writes and reads the project format **0.1**, unchanged in its version since 0.1.0. The format grew
**additively** within 0.1 (ADR-0011, amendment 6): the repository's API guard reports `api-guard: 0 breaking, 322
additive` against the published schemas in [`schemas/0.1/`](../../schemas/0.1/index.json). A project of 0.1.0 or
0.2.0 opens in 0.3.0 without a migration.

The additions, by what they hold:

- **PLC and bus 1.0:** a channel's data type, signal range, mode and safety data, a module's safety data and type
  identification, a station's firmware, a configuration project's symbol template, a part's allowed slots, limits and
  IO-Link and rating data, a bus port's signals, MRP role and typed PROFINET, EtherCAT and IO-Link addresses, the
  number of ports of a part's bus interface.
- **The exchange snapshot:** the ownership of a configuration project's fields and the record of its last exchange.
- **Media and tubes:** the valve model of a function definition, the fluid members of a part, a fluid line's tube,
  length and fittings, a tee's fitting, the project's fluid settings and the media with their definitions.
- **The underlay page item,** and the asset formats `pdf` and `dxf` for an embedded underlay source.
- **A legend's columns:** a report block can name the columns it prints, each with its share of the width; a block
  without them prints its report's own columns.
- **A layout's labels:** a layout view says what its placements are labelled with (tags, item numbers or both), and a
  placement can hold the place its label was dragged to.
- **A bus line's plugs:** a plug part, with its termination, at each end of a bus line.
- **A box's slots:** a valve terminal's box can be drawn as one cell per valve position.
- **A box's pin names:** a pin of a drawn box may carry a name (`BoxCp.name`, optional), which gives a box drawn
  without a part pins of its own that the device's function reads; a box of a part has none, its pins are the
  part's. A build that does not know the member keeps the name and draws the pin unnamed.
- **A fluid section's pins:** a multipin valve terminal part names the plug pin of each solenoid.
- **A cable mark's tag place:** a wire marker that is a cable's mark can hold where its tag and type line stand.
- **A supply point's group:** a supply point can name the group it prints with, so older drawings print as before.
- **A part's box:** a part can hold its device box, the box's width and height and each pin's edge and place along it.
- **A text style's typeface:** a text style names one of the bundled typefaces (narrow, mono, technical drawing; the
  standard one when it names none), and a free text can hold its own height.
- **A text place's solenoid:** a symbol's text place for a PLC address can name the solenoid it belongs to, so a
  valve with two solenoids prints each address at its own.
- Eleven report kinds (section 3).
- **A unit of millimetres:** the units a value can carry (a device's, a part's and the project's) include `mm`, which a
  cable part's outer diameter uses (it was written "8 mm", a unit the program did not know, so that no cable type
  with a diameter could be saved). A project that holds it opens in a 0.2.0 build, which shows the bare number.

**A project that 0.3.0 saved, opened in a 0.2.0 build.** The file is format 0.1 in both builds. The older build keeps
the new members, record kinds and page-item kind verbatim, so no data is lost, and does not use them. It does not
enforce what the new members imply: the ownership of a configuration project's fields (an edit it makes is an
ordinary difference in the next import), the delete links of the new kinds (an older build that deletes a module
leaves that module's channels dangling, which 0.3.0 reports), and a safety channel's partner and test-pulse pin (kept
in `extra`, so a stale target is absent to the older build). It reports an embedded asset of a format it does not
know (a PDF or a DXF) as a recovery finding and keeps the file as opaque bytes.

## 6. Upgrade steps

- **From 0.2.0:** install 0.3.0 over it as the user guide's [Upgrade](../book/src/how-to/install.md#upgrade) says.
  Nothing is migrated: a project of 0.2.0, or of 0.1.0, opens as it is.
- **What you may notice in an existing project:**
  - New findings. Every check scheme now runs the rules of the PLC, safety, process-tag, bus, IO-Link and fluid
    packs (section 3), so a project with a PLC or fluid devices can show findings it did not show in 0.2.0. On a PLC
    card's FE pin EW-PLC-013 replaces EW-POT-003. Read each finding with its own text.
  - Editing PLC channels is stricter. An edit that creates an overlapping address or a duplicate symbol is refused.
  - A first start opens the window maximised. A machine that has run ElektraWatt before keeps its saved window; the
    left column is wider at 1920 and the command search is longer.
  - File ▸ Import… is the one entry for every file. Import QElectroTech project…, Import drawing…, Import EPLAN data…
    and Parts table… are no longer in the menus; the command search finds them.
  - The PDF and PNG files that ElektraWatt writes have other bytes than 0.2.0's, with the same pages. A comparison by
    checksum of a page exported before and after the upgrade differs.
  - The project keeps its copies of the starter symbols and parts until you update them from the library (section 4).
    To print channel addresses at terminals, update the project's copy of the terminal symbol, then turn on Addresses
    at terminals on the PLC tab.
  - The library offers updates in the Libraries pane for the redrawn ISO 1219 symbols and for the parts that changed
    (the starter valves, the valve terminal with a bus node). Update… shows the changes in the Preview tab first;
    Apply takes them, and the tubes stay on their ports. A symbol you do not update keeps its larger drawing.
  - A PLC module that an earlier build drew from the rack can stand with its channels bound to no pin. EW-PLC-018
    finds it, and its quick fix binds them, so that the addresses stand at the pins.
  - The terminal diagram lists the wires on the clamps of the starter terminals, which it left empty before.
  - A valve terminal drawn as one free box keeps its look. Its menu offers Draw as slots, which previews the box
    redrawn as its valve positions with its valves in their cells.
  - Texts of a turned or mirrored symbol now read upright (a tag no longer stands at 90°). An imported QElectroTech
    drawing keeps QElectroTech's text angles on the elements it turned.
  - The edited date of a project is set when you save a change, and a date is shown and typed in the project's date
    format. The PLC exchange buttons are on the PLC tab, no longer on the Output tab.
  - A project made before keeps its text sizes. Project ▸ Setup ▸ Text styles… sets them, and Standard sizes there
    gives every style the height a new project has, which is readable on paper; the warning about a text that is too
    small opens it.
  - A valve terminal whose valves were put on their positions before, without their symbols, is drawn by Draw its
    valves in the valve terminal (the terminal's menu, the station view's To do, or the quick fix of EW-CORE-047). A
    terminal drawn before keeps its place when a wider valve is put on it.
  - The one template of an older settings file becomes a list of one in Templates…, and New project offers it first.
    A project made from a template gets its pages only when Also copy its pages is ticked.
  - A project that names the drafting level keeps it and reads as Full in Check level….
  - A cable mark that was placed with the Marker tool draws as the cable's mark, with the cable's tag, type and core
    names. A wire in a cable takes its cross-section and colour from its cable, and a cable without a part is a
    warning; a cable without a length is a warning until the check for delivery.
  - Supply points drawn before have no group and print their place under each point as they did; Group these supply
    points in the right-click menu puts them together.
  - Edit route and Route selection are gone; Reroute does their work at once, for the selected wires or the page. It
    starts from the drawing: a wire that breaks no rule and has no shorter way keeps its route, and the others are
    mended. An earth symbol is no longer reported for a missing part.
  - Nothing already drawn is moved by the change to turning. A symbol that you turn or mirror from now on turns about
    the middle of its body, also a symbol drawn before.
  - A cable's mark that an older drawing holds selects as its cable, and the Devices list counts a cable and a
    terminal strip that stand on a page as drawn. A cable whose part you change at its Part row takes the new
    part's cores; the marks of such cables read the new type alone.
  - Tags and labels that lay on another text or on a neighbour's body may stand elsewhere when the page is drawn
    again: the program places them clear of each other. A text that you moved yourself stays where you put it, and
    a valve in a valve terminal's cell prints its single address one grid step under its insertion point.
  - A two-pole breaker, a main switch, a residual-current device, a stop button or an emergency stop that an older
    project holds without a part can be given one of the new starter parts with Choose part (section 4). A project
    made from a template shows the template's name in its Properties when the template is in your list.
  - A project saved by 0.3.0 and opened again in a 0.2.0 build keeps what 0.3.0 added and does not use it (section 4).
    A file that holds the unit `mm` (a cable's outer diameter) opens in 0.2.0, which shows the bare number.
  - The pin texts of every drawn box stand upright, also on the top and the bottom and in an imported box; where two
    would touch they stand on two lines. A box that you resize in the window keeps its pins centred on the edge that
    changed, off the corners. Reroute keeps a wire that is well drawn.
  - A wire drawn from a 0 V pin straight to an earth point is now the bond of the 0 V to protective earth. What was
    one PE potential through such a wire is now a 0 V and a PE, the findings EW-POT-001 and EW-POT-008 that it caused
    go, and the potential overview shows a bond row. A 0 V that reaches earth another way still needs Draw ▸ Connect
    ▸ Bond.
  - A bus cable's tag gains its line's page and prints in the tag style at the line (-W1 becomes -501W1 on page 501).
    Where that meets another tag on the page, EW-RDS-004 reports the two and offers Renumber the newer. A cable
    with a length counts that length in the parts list. An earth symbol still takes its tag from the cables' letter.
  - The two earth symbols have new names ("Earth (PE), protective: the cabinet's earth", "Earth for function (FE):
    screens and noise, not protection"). A project holds its old copies and keeps their names until you update them:
    the Libraries pane offers the update, and the symbols are the same drawings.
  - A 0 V wired to functional earth (FE) is no longer a conflict: the EW-POT-001 it raised goes, and EW-POT-002 may
    now say that the 0 V goes to functional earth only and where the protective bond belongs. A 0 V that was told
    by a potential defined at its pin, or by its name, is met as well as one told by its pin's role.
  - A two-pole breaker or switch, a main switch or a residual-current device is no longer reported by EW-POT-013 as
    switching the neutral alone; a contact in the neutral alone still is.
  - A station whose electrical box is drawn after its bus port takes the wiring page's number as its tag, as it
    does when the box is drawn first. Opening a project changes no tag: the change comes when the box is drawn, and
    a frozen tag stays as it is.

## 7. Known limitations

- **DWG needs a converter that you install,** and ElektraWatt has not been tested with a real ODA File Converter: the
  tests use a stand-in program. There is no DWG export; export DXF and convert it with your CAD program.
- **The exchange files are not yet read by a real TIA Portal or CODESYS.** The AutomationML, tag-table and PLCopen files
  follow their formats and are checked on reference files only; the bus attribute names of the AutomationML export are
  unverified. The import preview does not list the affected folios, racks are not exchanged items and the HMI flag
  of a tag is not a setting.
- **Large imports still hold the window.** An EDZ's and a parts XML's reading, a PLC import's read and merge and an
  EPLAN report becoming a project run on the window's thread. A drawing import is a job and can be cancelled.
- **Some notices of commands are in English in a Dutch window:** those in the Preview tab (re-address's old and new
  address, the overview generator, the instrument list) and those a command lists after it ran, such as a box
  reshape that moved a pin to another edge or took a pin away.
- **A very large DXF may be refused.** The reader's memory budget is an estimate and about 150,000 plain entities fit; a
  legal large drawing can be over it. A PDF placed as an underlay is bounded in pages and pixels but not in time.
- **Printing draws no underlays.** `--underlays` of the exports does; the print set does not. A part's drilling pattern
  is not read from a DXF.
- **The EPLAN imports are not complete.** A part's picture from an EDZ, a device's connection points from a report
  spreadsheet and a report's re-import into an existing project are not built. The table from EPLAN function
  templates to function definitions is not checked against a real EPLAN export.
- **An imported project shows many hygiene findings** (a device without a part, a frozen value that deviates, a tag
  that deviates from its scheme, routes through symbols). None is an error, but the list buries what matters.
- **An imported QElectroTech folio still differs** in a few places: a master's contact list has no contact symbols
  and its rows stand closer than in QElectroTech; cross-references shown as a cross or placed at the bottom print as
  a list, with a report entry; QElectroTech's folio list arrives as ElektraWatt's own table of contents; an element's
  mirror is not read (QElectroTech 0.100 writes none; newer versions do); fonts are substituted, so texts sit
  slightly lower. Texts of title-block cells stand 0.5 to 2.7 mm to the side of QElectroTech's, and free texts of 12
  pt and more 0.7 to 1.2 mm off in height.
- **PLC drawings are tight.** The canvas prints a channel address and the module's pin labels small: "1 Q0.0" needs
  about 7 mm against a pin pitch of 5.3 mm, so they can be hard to read. The I/O list does not take the passed
  terminals, the signal range and the F-address (they are in the SQL view `api_v1_plc_channel`). A module with two
  channel kinds (16 inputs and 16 outputs) is two parts. EW-PLC-012 offers no quick fix that opens the part's PLC
  section.
- **Your own parts have limits.** A part's PLC section holds one channel kind: a module with inputs and outputs is two
  parts. A device that belongs to no PLC is left out of the export to PLC software. A device with two
  interfaces stands on a bus page as two boxes with one tag, which can be dragged apart; a device placed first on
  a bus page takes its tag from that page, and the tag changes to the schematic page's when its black box is
  placed there later; a port that a corrected
  part adds appears only when the box is drawn again. A part cannot be removed from My parts in the window. Device
  description files (GSD, GSDML) are not read: the part is typed from the data sheet.
- **Fluid power is not complete.** A valve terminal's pilot supply is not derived and EW-FL-010 does not check its X
  port. The tube cut list has no cut allowance or order increment, and the tube labels no marker part, because no
  part carries them yet. A cylinder behind a throttle gets no `drives` link by itself. ISO 1219-2 component codes are
  not built.
- **Valve terminals have limits.** A terminal part that comes in several sizes is not asked for its size when it is
  placed. The part editor cannot set a valve terminal's kind (bus node or multipin) or its pin map; the starter parts
  carry them.
- **A wire's Potential row** in Properties does not open Define potential, and a selected wire does not mark its
  two ends.
- **A silencer, a plug or a drain also shows an editable Medium row.** The window takes a device for a source of a
  medium by its ports, and these have one.
- **A station made in the New station view shows ? in its tag** where the page goes, until it is drawn on a page.
  EW-CORE-047 and the station's To do say so.
- **The printed legend of a layout that already has one keeps its four columns** (position, tag, quantity, part
  number). A legend made by Add legend, or the legend of a new layout page, prints the description too. Where a
  legend has no room, its part-number column is shortened and, last, left out.
- **A tag keeps clear of a neighbouring symbol only around a half-turned symbol.** Elsewhere it can still lie on a
  neighbour's body or text; a drag moves it.
- **A drag on a pin's label of a symbol moves the symbol,** not the label.
- **The router leaves two cases.** A PE wire may cross L and N where the way round a box is far longer (ADR-0033's
  measure), and a pin right under a row of tags has no text-clear route.
- **The enclosure legend's quantity and part-number columns can show "…"** where they are cut.
- **An interruption point on a box's bottom pin** draws its arrow along the box's edge.
- **An unnumbered wire's Properties title reads "?".**
- **The edited date from the command line.** `ew` commands that save a project with changes set its edited date only
  when `SOURCE_DATE_EPOCH` is given, so that no output depends on the day it runs; without it the date stays as it
  was.
- **Some window finish is open.** At 2560 × 1440 the Bus, Devices and Medium tables do not widen their column or
  fill their panel; the Medium table counts "1 lines"; a
  context menu can cover its row.
- **Interruption points need three grid steps** below or above each other: the name stands above the arrow and
  the cross-reference below, so nearer points would print over each other, and the tool does not place them
  (Alt does). Points ended on wires with the Wire tool's interruption point key are not held apart, so wires one
  grid step apart end in points whose texts overlap.
- **A second wire to an occupied pin** is drawn over the first wire's last stretch and shows no dot, so the drawing
  does not say that the two are joined. End the second wire on the first wire instead: that makes a junction with
  its dot.
- **A row of terminals undoes one terminal at a time.** Terminal… lays several terminals with one click, and each
  is its own undo step; the toast's Undo takes back the last one.
- **A point where the supply comes in keeps one warning.** After Supply comes in here… the checks still say that the
  external connection has no cable (EW-CORE-034): add the feeder cable, or waive the finding where that cable
  belongs to the other drawing set.
- **The offered potential needs a known supply.** 0 V is offered on a coil's A2 only when the potential on its A1
  has the type L+ or a phase, or a name that is such a type's word; the starter relay parts do not say whether their
  coil is AC or DC.
- **F1 inside a dialog opens the dialog's section.** A field of a dialog has no section of its own; rows of
  Properties have. There is no page for each kind of device: a contactor opens Devices and symbols.
- **PLC cards and bus devices open read-only in the device box.** Their pins come from their channels and their bus
  interfaces, which the part editor changes.
- **Shapes cannot be drawn from the keyboard alone in the symbol editor,** only a thing already drawn can be moved with
  the arrow keys.
- **Handles show for one selected wire.** With several wires selected, none shows a handle.
- **The spacing between terminals is not kept between sessions.** The open project remembers it for the next row;
  Terminal… starts from its default spacing again when the project is opened anew.
- **Texts can end on one another after a grid fit.** After a page's grid change or a paste fitted to another grid,
  each item goes to its nearest grid point, so two texts that stood apart can end on one another; the commands do
  not know a text's drawn size. Move one of them.
- **The first arrow key on a fitted symbol can show a part of a step** in the readout while the move itself is whole
  steps.
- **A valve stays undrawn when a terminal's positions are filled through `ew apply` without the symbols.** Draw its
  valves in the valve terminal draws it.
- **An earth symbol takes a number from the cables' counter,** so a project's first cable can be W2: the earth
  symbol's tag is hidden on the page and used in the wire list.
- **A 0 V that reaches earth through an interruption point on another page** is not seen as bonded by the wire
  from 0 V to earth, which looks at one page only: it still needs Draw ▸ Connect ▸ Bond.
- **There is no A3 form.**
- **The title block's layout and the frame's columns and rows cannot be changed in the window.** Both are planned for
  the next milestone (FT-1814 and FT-1815).
- **A fitted paste can leave a wire without a route** where two pins end too close to each other. The message counts
  such wires and they stay dashed: move the items apart and choose Reroute.
- **A black box's caption stands above it,** left of its first top pin, where wires into its first top pins pass, so
  those wires loop round it.
- **An interruption point's name can stand on its own wire's way out.**
- **The mouse wheel zooms and the window has no scroll bars.** View ▸ Mouse wheel scrolls makes the wheel pan,
  Shift+wheel pans sideways, and a drag with the middle button (or with Space held) moves the page.
- **The project's Document title is not a cell of the title block.** The program's frame prints no cell for it;
  Title block fields… says which cell prints each field.
- **A new wire takes 0.75 mm²** (the control size) unless its potential names another circuit class: the size is not
  proposed from the circuit's current, so a wire on a 16 A mains line is sized by you in Properties.
- **Some texts of symbols placed at a card's pin pitch still overlap.** Several small symbols side by side at the
  pitch of a PLC card's pins can have tags and pin numbers on one another.
- **A terminal renamed through its Tag** in Properties gets a frozen tag that the page does not print.
- **The importer's messages** (the EW-IMP findings of an import's migration report) read in English in a Dutch
  window: they are stored in the project as the importer wrote them.
- **A new page's grid.** A new page takes the QET 10 px connection grid unless you choose 4 mm in New page or the
  current page has it; the setting "grid for new pages" is not built.
- **A connection point marked not used** shows no mark on the page.
- **Three texts name a thing by its ID or path:** EW-REL-004 prints a revision's ID, EW-CORE-008 a form copy's ID,
  and the refusal of an image file its path.
- **A few built-in symbols keep their English names** in a Dutch window (the junction's dot and bevel, the wire
  marker).
- **A device dropped on a wire connects into it** without asking; a toast says so.
- **The window's pictures were reviewed on Windows only** for this release.
- **Unsigned files.** Nothing is signed (section 1); Windows SmartScreen may stop the setup until you choose to run
  it. Signed releases come with 1.0.
- **Placeholders of online-only files** (Windows' cloud placeholders, iCloud stubs and other dataless files) are not
  detected: a project in a cloud-synced folder whose files are not downloaded fails to open with a missing file,
  instead of opening read-only with the files named.
- **`ew check`** has `--integrity` but not yet its offline mode, `--gate`, `--pages`, `--structure`, `--packs-as-of`,
  `--baseline` and the JUnit and SARIF outputs.
- **What comes with 1.0:** signed files, tags and checksums, a second approval of release jobs, reproducible builds,
  the per-machine Windows installer (MSI), the `.deb` and Flatpak packages, the update check, the crash report with
  its upload, the publishing of the libraries on crates.io, and the steward's processes. No macOS build is planned
  before 1.0. Device descriptions (GSD, GSDML, IODD) and native DWG reading are planned for 1.x.
- **Windows and Linux on x86-64 only.** No aarch64 build is made.
- **A damaged library copy** is named "the library copy of its part" in its banner and in the Save As refusal, also
  when it is a function definition, a symbol or a profile.
