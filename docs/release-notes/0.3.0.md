# ElektraWatt 0.3.0

The release and migration notes of ElektraWatt 0.3.0.

## 1. What 0.3.0 is

ElektraWatt 0.3.0 is the automation release for the pilot. It adds what a control-cabinet project needs around its
schematic: the PLC and the bus (racks and slots, addresses, safety data, PROFINET, EtherCAT and IO-Link), fluid power
(valves, media, tubes, the ISO 1219 symbols), the exchange with PLC software (AutomationML, the TIA Portal tag table,
PLCopen XML), drawings and EPLAN data brought in (DXF, DWG, PDF, EDZ, EPLAN parts and report files), and three
workspaces for this work. The window is now designed for 1920 × 1080 and uses the room of 2560 × 1440 (section 3).
It comes as the same downloads as 0.2.0, for Windows and Linux on x86-64, and with the same warnings:

- **Unsigned.** No file of this release is signed: no signed tag, no Authenticode signature on the Windows programs,
  no signed `SHA256SUMS`. Windows may warn before it runs the setup. Check a download as section 2 says instead.
- **No network code.** ElektraWatt makes no network connection of its own: no update check, no crash upload, no
  analytics (`PRIVACY.md`, in the installation and the repository).
- **Supported until the next minor release.** Before 1.0 only the latest 0.x release is supported, until the next
  minor release ([`SECURITY.md`](../../SECURITY.md)). With 0.3.0 out, 0.2.0 is no longer supported.
- **Engineering verification.** ElektraWatt's checks do not replace engineering verification by a competent person.

## 2. The downloads and how to verify them

The release on the repository's releases page holds these files, each built by the release workflow from the
release's commit:

| File | What it is |
|---|---|

| `ElektraWatt-0.3.0-x86_64.AppImage` | The same for Linux (glibc 2.35 or newer, as on Ubuntu 22.04 and Debian 12), one file to make executable and run |
| `ew-0.3.0-x86_64-pc-windows-msvc.zip`, `ew-0.3.0-x86_64-unknown-linux-gnu.tar.gz` | The command-line program `ew` alone, with the starter content, the sample project, the licence texts and the notices |

Verify a download before you run it: check it against `SHA256SUMS`. The user guide's
[Verify a download](../book/src/how-to/install.md#verify-a-download) gives the commands for Windows and Linux;
[Install ElektraWatt](../book/src/how-to/install.md) installs, upgrades and removes each download.

## 3. What is new since 0.2.0

### The PLC workspace

View ▸ Workspaces ▸ PLC puts the PLC navigator in the left column, the page in the middle and the PLC grid in the
bottom dock. The guide's [Work in the PLC workspace](../book/src/how-to/plc-workspace.md) goes through it step by
step.

- **From nothing.** The starter parts hold a CPU with a PROFINET and a PROFIBUS DP port, a remote I/O head (a
  station of its own), an input and an output card, a PROFIBUS cable and an Industrial Ethernet cable, so a new
  project can hold two stations and a bus without a part of your own.
- **The navigator** runs from the configuration project to its stations, their racks, their modules and each
  module's channels, with the station's bus ports after the modules. A card without a station is listed under Cards
  without a station, and Attach cards without a station on a station's row takes it. This is how a second CPU or a
  remote I/O head gets its cards.
  Dragging a channel onto a pin binds it; a device wired beside its card is attached and bound in one step, one undo.
- **The grid** has a row per channel, with the data type, signal range, safety and rack columns beside the address,
  symbol, state, target and comment. Its filter takes the words `safety` and `bus:<net>` as well as the earlier ones.
- **Rack and slots…** on a station's row opens the rack and slot editor: the station's slots with their modules, parts
  and allowed slots, and a valve terminal's positions beside its stored order codes. Add here puts a card of the chosen
  part into a free slot; a card's Slot field, or dragging the card, moves it. A slot the part does not allow, a slot
  that is taken and too many modules are refused, with the reason in the dialog (EW-PLC-011).
- **Re-address…** on a module, or on a configuration project for all its modules, previews every address that moves
  ("channel 3 of -201U5: Q10.3 → Q2.3") in the Preview tab, and Apply makes it one undo step. **Make manual addresses
  automatic…** drops the manual addresses that equal the derived ones, and says which it keeps because dropping them
  would move another module. **Freeze addresses…** makes the address of every used or reserved channel manual and pins
  the module starts, so that a card inserted later moves nothing; a spare channel keeps its automatic address. Freeze
  is refused under a tag-based address profile. The three are also in the Addresses menu of the PLC panel and of
  the grid; Apply says in a toast how many addresses it changed, and a manual address carries the badge manual in the
  panel and a lock in the grid.
- **Properties** show a station's role, order and configuration project in words; a card's station is chosen by
  attaching it, and a channel's binding names its pin.
- **Targets.** A channel bound to a card's pin takes the field device its signal reaches as its target, with the
  terminals it passes (the I/O list's target and target pin). That device's address slot prints the channel's address.
  Project ▸ Channel addresses at terminals prints the address at the terminals on the path as well.
- **Safety data.** Safety data… on a module sets its F-source and F-destination address and its F-watchdog time;
  Mode and safety… on a channel sets a multi-function port's mode and the channel's safety evaluation and requirement.
  The rules EW-SAF-001 to -003 check the F-addresses, the 1oo2 pairs and the test pulses.
- **Symbols and tags.** Symbol policy… on a configuration project sets the template that gives a channel without a
  manual symbol its symbol, whether symbols are strict IEC 61131-3 identifiers and the tag table. Project ▸
  Process-tag scheme… sets the pattern process tags follow. A further built-in address profile, Rockwell Logix
  (tag-based), prints `Local:3:O.Data.1` from the station and the slot.
- **IO-Link, PROFINET and EtherCAT.** A part can describe an IO-Link master's ports, and each port's devices take
  their process-data windows from their parts; addresses of the three buses are typed forms, not text.

### The bus navigator

The rail's Bus shows the bus navigator: the logical nets with their rates and ports, the physical nets with their
segments, ends, terminations and cables, and the ports that belong to no net. Shown as a table it edits a port's
address and termination. Properties names a port's nets and reads its address as the reports print it. A CPU's row
offers Place port for each port its part has and no symbol draws, with the symbol of its bus (PROFIBUS DP,
PROFINET). On a bus-topology page the Wire tool draws bus lines, and a bus line puts the ports it joins into one
logical net: the net one of them names, else a new net named for the bus with the CPU's port as its master. A bus
plug passes the net through. A bus cable's core lands on the pin of its signal at each port, and the cable diagram prints those pins.

### The exchange with PLC software

- **Where.** The Output tab holds the group PLC exchange with Export to PLC software and Import from PLC software.
- **Export.** Output ▸ Export to PLC software… is a form: the format (AutomationML AR APC 1.4.0, or 1.2.0 for older
  PLC software; the TIA Portal "PLC Tags" workbook; PLCopen XML for CODESYS), the stations and the document date, which starts as
  today's. It asks for the file under a name that fits the format (`plc.aml`, `plc.xlsx`, `plc.xml`), writes it whole or not at all and says what it holds. An AutomationML file or a tag workbook is
  recorded in the project as the base of the next import. A PLCopen list is never recorded: it does not come back.
- **Import.** Output ▸ Import from PLC software… previews the file against that base in four tabs: Changed (each
  field with the project's value, the file's value and what the import makes of it: applied, rejected, kept or
  pending), Conflicts (both sides changed it: keep the project's value or take the file's), Removed (what the file no
  longer holds) and Parking (objects of the file that match nothing, or more than one; a module or station can be
  created unplaced). A refusal that Apply would make is shown before you choose Apply, with the rows it concerns. The
  card has a box, The file is complete: tick it when what the file does not hold was removed in the PLC software.
  Apply commits what the preview showed, as one undo step.
- **What ownership protects.** After the first import that gives a value the PLC owns, the project refuses to edit
  that value until you unlock it: a module's start, a station's firmware, a bus port's address and, when you gave the
  symbols to the PLC, a channel's symbol and comment. Unlock module starts, Unlock symbols and Unlock PLC data are
  on the configuration project's row. An import turns every start it gives into a manual start, so a module
  inserted later moves none.
- **Instrument list.** Import instrument list… on a configuration project reads a CSV or workbook of process tags and
  signal types, previews it, and on Apply gives each tag a placeholder device and spare channels of its kind.
- **New rules.** EW-PLC-016 says the configuration project changed since its last exchange; EW-PRC-002 reports an
  instrument tag without a device or channel.

### The fluid workspace

View ▸ Workspaces ▸ Fluid power shows the fluid navigator (valve terminals, their modules and valves, other fluid
devices, with their lines, and the media), and the tube table and medium table in the bottom dock. The guide's
[Work in the Fluid workspace](../book/src/how-to/fluid-workspace.md) goes through it.

- **Valves.** A valve is described by its switching positions, flow paths and actuators, so the program knows what
  each position connects. The starter set has 33 ISO 1219 pneumatic symbols (directional valves, cylinders and
  drives, vacuum, air preparation, flow and logic valves, fittings, the air supply and the valve-terminal supply
  plate) with their function definitions, and starter parts for a generic valve terminal, three tubes (PU 6×4, 8×6 and
  10×8 mm) and two fittings. A valve terminal's galleries are derived from its modules.
- **One word.** The window calls a drawn fluid line a tube, in its menus, its Properties, its findings and its
  tables.
- **Media.** Project ▸ New medium… adds a medium; the Fluid panel offers it and Fluid settings… beside its filter. A
  tube's right-click menu and its Properties set its medium and its line kind; Properties also show the tube's
  effective size and material and where each comes from. The
  medium follows the line's net and the media pass through the valves' flow paths. A medium's row highlights its
  zones in colour and hatch. The medium table counts the consumers of each medium, actuators included.
- **Tubes.** A line takes its tube from the project's default (Project ▸ Fluid settings…: outer and inner diameter,
  material, how fluid lines are tagged), a part or a typed length. The tube table says where each value comes from.
  A tube that goes from page to page through fluid interruption points is counted as one tube, and a tee carries a
  fitting of its own.
- **Drawing.** Draw ▸ Connect ▸ Tube… picks the kind of the lines the Wire tool draws (Pilot, Exhaust, Drain,
  Flexible). Fluid ports autoconnect with fluid lines on fluid pages, never to an electrical point. A flexible line is
  drawn as an arc. The interruption point tool places the fluid form of a point on a fluid page.
- **Valve terminals.** The starter valve terminal placed from Device is a valve terminal at once and shows in the
  Fluid navigator; its box and its row offer Add valve at position n, which puts the valve's symbol on the pointer.
  A valve's row sets it spare or used, blanks a position, adds a valve and plugs an open working
  port. **Generate overview…** on a valve terminal's row lays out its assembly overview on its overview pages, adds
  pages where the frame is full and previews the change in the Preview tab; run again after adding a module, it
  changes nothing that is in order.
- **The lists.** The tube list, tube cut list, tube labels, valve-terminal configuration and medium overview
  (section 5), and tube, fitting and tee lines in the bill of materials.
- **New rules.** EW-FL-005 (two media in one net), -006 (tube does not fit), -007 (tube without specification),
  -008 (exhaust open), -009 (coil voltage), -010 (no supply on port 1), -012 (port-role conflict) and -014 (tube
  crosses a location).

### File ▸ Import… takes every file

File ▸ Import… beside Open goes on by what the file is: a QElectroTech project (`.qet`), a project archive (`.ewz`),
a drawing (`.dxf`, `.dwg`) or a PDF, an EPLAN part file (`.edz`, `.7z`, `.zip`, `.xml`) or an EPLAN report (`.xlsx`,
`.csv`). The separate entries (Import QElectroTech project…, Import drawing…, Import EPLAN data…, Parts table…) are
gone from the menus and from the Project tab's Import group, which keeps Re-import QElectroTech project…; the
command search still finds each by its name.

- **A drawing.** Add as page makes a DXF or DWG drawing a new graphic page, on the folio after the last page of its
  section. Place under page puts a DXF, DWG or PDF under the shown page as a locked underlay to redraw over; no check,
  report or export reads it, unless an export prints underlays (`ew export … --underlays`). The source stays outside
  the project unless you choose Place and embed: a customer's drawing may be confidential. A drawing that names no
  unit is read in millimetres. The symbol editor's Open takes a `.dxf`, and its blocks become symbol drafts. The
  reading runs as a job in the Jobs pane, with Cancel.
- **A DWG** is read through the ODA File Converter, which ElektraWatt does not include and never downloads. Install
  it and choose its program when the import asks; the choice is kept once it has converted a file. A converter that
  hangs is stopped with what it started.
- **EDZ and parts XML.** The dialog says how many parts the file holds, how many of them the project has a copy of
  and how many of those copies would change. Update shows the changed fields and the devices that use them before
  anything changes, as one undo step; a part the project does not have is never added to it. Add to my parts library
  writes the parts into your own library; a part that was there already is updated with the file laid over it, so
  the technical data you added stays. Before the first EDZ of a session a notice says that the EPLAN Data Portal's
  terms restrict its data to EPLAN products; ElektraWatt reads the file from your disk only and records the file and
  its SHA-256 on every part.
- **An EPLAN report** (device list, terminal diagram, connection list) becomes a new project without drawings through
  a column mapping. The dialog offers the shipped German and English mappings that fit the file's headers, and your
  saved one first. A file that no mapping fits goes to Map the columns…: you say what kind of report it is and what
  each column is, the header row is found below a title, and Import saves the mapping under the file's source key for
  the next file of that report. EW-IMP-206 and EW-IMP-207 report what the import could not use.
- **QElectroTech.** A folder of QElectroTech projects imports in one run with `ew import qet --batch`, and a folder
  of QElectroTech elements becomes a library with `ew lib import qet-elements`. A static text of an imported element
  stands on QElectroTech's baseline, as QElectroTech's own PDF has it.

### DXF export

`ew export dxf` writes one AutoCAD 2000 DXF per page, with a layer per kind of object that `--layer <class>=<name>`
renames. The file is ASCII: ä, °, ² and every other character outside ASCII are written as `\U+XXXX`, so a CAD
program and ElektraWatt read the texts as written. A DXF read back as a page prints where it was drawn, also on a
page whose frame scales the page to the sheet.

### The migration verifier

`ew verify-migration <project> --reference <pdf>` compares an imported project with the PDF of its drawing: every
text with its place (within 0.5 mm) and the drawing of each frame cell with the texts masked. It stretches the
reference to the page's pixels, refuses a page above 4,096 pixels a side in words and pairs pages by the folio their
label names, so a missing page shifts none. The sample project against its own PDF reports no deviation.

### The new checks, and every scheme runs them

Until 0.2.0 a shipped check scheme ran the rules of the first release only. From 0.3.0 every shipped scheme runs every
rule that is built. **A project can show findings it did not show in 0.2.0.** The new rules are:

- PLC: EW-PLC-004 (channel kind mismatch), -005 (invalid symbol), -009 (channel without connection), -010 (data-type
  width mismatch), -011 (slot rules), -013 (card supply wrong), -014 (output load exceeds rating) and -016.
  EW-PLC-013 takes the place of EW-POT-003 on a PLC card's FE pin. EW-PLC-001 and -007 also refuse an edit that
  makes an overlap or a duplicate symbol; an edit that repairs one, or any edit in a project that holds one, is
  not refused.
  EW-POT-009 ("is not connected") leaves out the pin of a PLC channel that is spare, reserved or deactivated, and
  a frozen project gives no spare channel EW-PLC-009.
- Safety and process: EW-SAF-001 (F-address), -002 (1oo2 pair), -003 (test pulse); EW-PRC-001 (process-tag scheme),
  EW-PRC-002.
- Bus: EW-BUS-002 (address outside the range), -003 (PROFINET name or IP), -005 (rate not supported), -006 (segment
  limits), -007 (no master), -009 (wrong bus cable), -010 (net mismatch); EW-IOL-001 (IO-Link port class) and -002
  (IO-Link limits). A finding that rests on a part's bus data of unverified confidence says so.
- Fluid: EW-FL-005 to -010, -012 and -014 (see above). The `pre-delivery` scheme and the `migration` scheme keep
  EW-FL-008 and -014 off; `drafting` shows them as hints.
- Imports: EW-IMP-251 to -255 and -257 (units missing, SHX font substituted, entity unsupported, external reference not
  followed, hatch pattern reduced to its boundary, DWG converted through ODA); EW-IMP-206 and -207.

The sample project shows the change: it reports EW-PLC-013 on its two FE pins where it reported EW-POT-003, EW-FL-007
on its sixteen fluid lines without a tube specification and EW-FL-010 on its valve terminal.

### The new reports

The Output tab holds Report, the report block dialog where every list page is made; the command search finds it by
the name of each list ("tube list", "card list"), and New page says where lists are made. Output ▸ Reports ▸ Report
block… offers every report kind that fills pages and has an engine, by name; Check report,
which has none, is no longer offered. New: PLC card list, Network address list, Bus overview, Bus cable list, IO-Link
port list, Safety I/O list, Tube list, Tube cut list, Tube labels, Valve-terminal configuration and Medium overview.
`ew export report --kind <kind>` writes each. A report table's text that does not fit its cell at the smallest size is
cut with an ellipsis and reported, never printed over the next cell. The tube list's columns widen where their words
need it, and a tube without a length prints "—" with its Source saying "missing".

### The window at 1920 × 1080 and 2560 × 1440

The window is designed for 1920 × 1080 and uses the room of 2560 × 1440: the left column is 480 points wide at 1920
and 640 at 2560, the command search takes a share of the tab row without a cap, and a form of fields stops at its
1920 width. At 1920 the command bar folds no group, in English or in Dutch; where room is short a step shows its
icon alone first. A first start (a machine without a saved window) opens maximised; a later start keeps the size you
left. The two QElectroTech imports are named in full. The window stays usable at 1280 × 800, which is no longer a
target. A table's sorted column widens by its sort icon, so its header is not cut, and a tool of the canvas tool
strip shows disabled while its action is unavailable (a project without pages).

## 4. The format

ElektraWatt 0.3.0 writes and reads the project format **0.1**, unchanged in its version since 0.1.0. The format grew
**additively** within 0.1 (ADR-0011, amendment 6): the repository's API guard reports `api-guard: 0 breaking, 275
additive` against the published schemas in [`schemas/0.1/`](../../schemas/0.1/index.json). A project of 0.1.0 or
0.2.0 opens in 0.3.0 without a migration.

The additions, by what they hold:

- **PLC and bus 1.0:** a channel's data type, signal range, mode and safety data, a module's safety data and type
  identification, a station's firmware, a configuration project's symbol template, a part's allowed slots, limits and
  IO-Link and rating data, a bus port's signals, MRP role and typed PROFINET, EtherCAT and IO-Link addresses.
- **The exchange snapshot:** the ownership of a configuration project's fields and the record of its last exchange.
- **Media and tubes:** the valve model of a function definition, the fluid members of a part, a fluid line's tube,
  length and fittings, a tee's fitting, the project's fluid settings and the media with their definitions.
- **The underlay page item,** and the asset formats `pdf` and `dxf` for an embedded underlay source.
- Eleven report kinds (section 3).

The format-variant lines of this release:

- format-variant: channel ChannelKind multi_function
- format-variant: part ChannelKind multi_function
- format-variant: function NetAddress {profinet}
- format-variant: function NetAddress {ethercat}
- format-variant: function NetAddress {io_link_port}
- format-variant: report_block ReportKind plc_card_list
- format-variant: report_block ReportKind network_address_list
- format-variant: report_block ReportKind bus_overview
- format-variant: report_block ReportKind bus_cable_list
- format-variant: report_block ReportKind iolink_port_list
- format-variant: report_block ReportKind safety_io_list
- format-variant: report_block ReportKind tube_list
- format-variant: report_block ReportKind tube_cut_list
- format-variant: report_block ReportKind tube_labels
- format-variant: report_block ReportKind valve_terminal_config
- format-variant: report_block ReportKind medium_overview
- format-variant: page_item PageItemKind {underlay}
- format-variant: record medium.schema.json
- format-variant: record medium_def.schema.json
- format-variant: record exchange_record.schema.json
- format-variant: record foreign_id.schema.json

**A project that 0.3.0 saved, opened in a 0.2.0 build.** The file is format 0.1 in both builds. The older build keeps
the new members, record kinds and page-item kind verbatim, so no data is lost, and does not use them. It does not
enforce what the new members imply: the ownership of a configuration project's fields (an edit it makes is an
ordinary difference in the next import), the delete links of the new kinds (an older build that deletes a module
leaves that module's channels dangling, which 0.3.0 reports), and a safety channel's partner and test-pulse pin (kept
in `extra`, so a stale target is absent to the older build). It reports an embedded asset of a format it does not
know (a PDF or a DXF) as a recovery finding and keeps the file as opaque bytes.

**What changed in the content a project copies** from the starter libraries:

- **Symbols.** New: 33 ISO 1219 pneumatic symbols, and `ew.iso.ip` (outgoing) and `ew.iso.ip-target` (incoming) for
  a fluid interruption point, each with its `@qet10` twin. The terminal symbol `ew.iec.terminal` and
  `ew.iec.terminal@qet10` are 0.1.2: they have a slot that prints the channel's address of a PLC signal.
- **Function definitions.** New: those of the ISO 1219 symbols, and `ew.fn.ip-fluid` for the fluid interruption
  point. The 3/2 and the 5/2 solenoid valve of the starter set, `ew.fn.valve-3-2-sol-spring` 0.1.1 and
  `ew.fn.valve-5-2-sol-spring` 0.2.1, carry a valve model; their symbols are unchanged.
- **Parts.** The starter parts library is 0.8.0. New: the generic valve terminal EW-GEN-VTM-1 and the parts
  EW-GEN-VLV-3 and EW-GEN-VTS-1 for it; the CPU with PROFINET and PROFIBUS DP EW-GEN-CPU-2, the remote I/O head
  EW-GEN-RIO-1, the bus cables EW-GEN-CBL-2 and -3; the tubes EW-GEN-TUB-6, -8 and -10 and the fittings
  EW-GEN-FIT-6 and -8.
- **PLC profiles.** New: the address profile `rockwell-logix` 2027.1 (tag-based), beside the TIA and IEC profiles.
- **The sample project** holds the new copies of the terminal symbol (the `@qet10` form) and of the 5/2 valve's
  function definition.

A project keeps the copies it holds. It takes the new versions only when you update its copies from the library. A
project's older copy of the terminal symbol has no address slot, so it prints no channel address at terminals until
it is updated.

## 5. The command line, the commands and the other surfaces: what changed

Every surface is still **Preview** ([doc 17](../design/17-extensibility.md#11-api-stability-and-versioning) §11):
the command-line program, its JSON results, the commands, the queries and the SQL views may change in a 0.x release,
and each such change is listed in that release's notes.

### The command-line program `ew`

- **Added:** ew export plc-aml|plc-xlsx|plcopen `[<project-dir>] --out <file> [--config <name>] [--station <tag>]...
  [--lang <tag>] [--apc 1.4.0|1.2.0]` (AutomationML AR APC on CAEX 2.15, the TIA Portal "PLC Tags" workbook, alias
  `plc-tags`, and PLCopen XML with the global variable list `IO_ElektraWatt`; `--apc` belongs to plc-aml and
  defaults to 1.4.0; an AML file or a tag workbook is recorded in the project as the base of the next import, a
  PLCopen list is not; the counts of the tags written are in the singular or plural)
- **Added:** ew import plc-aml|plc-xlsx `<file> [<project-dir>] [--config <name>] [--lang <tag>] [--complete]
  [--accept <choices.json>] [--json]` (previews the file against the last exchange: applied, rejected, kept,
  pending, conflict, parked and removed objects; with `--accept` it applies the choices as one undo step; a refusal
  that Apply would make, such as a start that overlaps another module's (EW-PLC-001), ends the run without
  `--accept`; `--complete` says that what the file does not hold was removed in the PLC software; results
  `ew.import-plc-aml-result/1` and `ew.import-plc-xlsx-result/1`)
- **Added:** ew plc status `[<file>] [--project <dir>] [--config <name>] [--json]` (the last exchange and what changed
  since; result `ew.plc-status-result/1`)
- **Added:** ew import instrument-list `<file> [<project-dir>] [--config <name>] [--apply]` (previews, and with
  `--apply` gives the tags of an instrument list placeholder devices and spare channels of their kind)
- **Added:** ew import dxf `<file> [--as page|underlay|symbol|outline] [--units <unit>] [--layout <name>]
  [--show-layer <name>]... [--on <folio>] [--embed] [--library <dir>] [--part <number>] [--key <key>]` (a DXF R12 to
  2018 drawing as a new graphic page, an underlay of the page `--on`, symbol drafts of its blocks or the front
  outline of a part; a drawing that names no unit is refused until `--units` names it; EW-IMP-251 to -255; one memory
  budget of 192 MiB, estimated, covers the file's pairs and everything its blocks expand to, so a drawing of more
  than about 150,000 plain entities, a block that inserts itself twice and nested arrays of inserts are refused in
  words before memory is taken; a drawing whose `$EXTMAX` does not hold it is placed by its own top; a page or an
  underlay prints where it was drawn)
- **Added:** ew import dwg (the options of ew import dxf and `--converter <program>`, else the program named by the
  environment variable `EW_DWG_CONVERTER`: the user's own ODA File Converter, never bundled; EW-IMP-257; its work
  folder is private and removed on every way out, and a converter that is stopped takes the processes it started
  with it) and ew import pdf `<file> --on <folio> [--page <n>] [--embed]` (a PDF page as an underlay)

## 6. Upgrade steps

- **From 0.2.0:** install 0.3.0 over it as the user guide's [Upgrade](../book/src/how-to/install.md#upgrade) says.
  Nothing is migrated: a project of 0.2.0, or of 0.1.0, opens as it is.
- **What you may notice in an existing project:**
  - New findings. Every check scheme now runs the rules of the PLC, safety, process-tag, bus, IO-Link and fluid
    packs (section 3), so a project with a PLC or fluid devices can show findings it did not show in 0.2.0. On a PLC
    card's FE pin EW-PLC-013 replaces EW-POT-003. Read each finding with its own text.
  - Editing PLC channels is stricter. An edit that creates an overlapping address or a duplicate symbol is refused.
  - A first start opens the window maximised. A machine that has run ElektraWatt before keeps its saved window; the
    left column is wider at 1920 and the command search is longer.
  - File ▸ Import… is the one entry for every file. Import QElectroTech project…, Import drawing…, Import EPLAN data…
    and Parts table… are no longer in the menus; the command search finds them.
  - The PDF and PNG files that ElektraWatt writes have other bytes than 0.2.0's, with the same pages. A comparison by
    checksum of a page exported before and after the upgrade differs.
  - The project keeps its copies of the starter symbols and parts until you update them from the library (section 4).
    To print channel addresses at terminals, update the project's copy of the terminal symbol, then turn on Project ▸
    Channel addresses at terminals.
  - A project saved by 0.3.0 and opened again in a 0.2.0 build keeps what 0.3.0 added and does not use it (section 4).

## 7. Known limitations

- **DWG needs a converter that you install,** and ElektraWatt has not been tested with a real ODA File Converter: the
  tests use a stand-in program. There is no DWG export; export DXF and convert it with your CAD program.
- **The exchange files are not yet read by a real TIA Portal or CODESYS.** The AutomationML, tag-table and PLCopen files
  follow their formats and are checked on reference files only; the bus attribute names of the AutomationML export are
  unverified. The import preview does not list the affected folios, racks are not exchanged items and the HMI flag
  of a tag is not a setting.
- **Large imports still hold the window.** An EDZ's and a parts XML's reading, a PLC import's read and merge and an
  EPLAN report becoming a project run on the window's thread. A drawing import is a job and can be cancelled.
- **Command notices in the Preview tab are in English in a Dutch window** (re-address's old and new address, the
  overview generator, the instrument list).
- **A very large DXF may be refused.** The reader's memory budget is an estimate and about 150,000 plain entities fit; a
  legal large drawing can be over it. A PDF placed as an underlay is bounded in pages and pixels but not in time.
- **Printing draws no underlays.** `--underlays` of the exports does; the print set does not. A part's drilling pattern
  is not read from a DXF.
- **The EPLAN imports are not complete.** A part's picture from an EDZ, a device's connection points from a report
  spreadsheet and a report's re-import into an existing project are not built. The table from EPLAN function
  templates to function definitions is not checked against a real EPLAN export.
- **An imported project shows many hygiene findings** (a device without a part, a frozen value that deviates, a tag
  that deviates from its scheme, routes through symbols). None is an error, but the list buries what matters.
- **An imported QElectroTech folio still differs** in a few places: a master's contact list has no contact symbols
  and its rows stand closer than in QElectroTech; cross-references shown as a cross or placed at the bottom print as
  a list, with a report entry; QElectroTech's folio list arrives as ElektraWatt's own table of contents; an element's
  mirror is not read (QElectroTech 0.100 writes none; newer versions do); fonts are substituted, so texts sit
  slightly lower. Texts of title-block cells stand 0.5 to 2.7 mm to the side of QElectroTech's, and free texts of 12
  pt and more 0.7 to 1.2 mm off in height.
- **PLC drawings are tight.** The canvas prints a channel address and the card's pin labels small: "1 Q0.0" needs
  about 7 mm against a pin pitch of 5.3 mm, so they can be hard to read. The I/O list does not take the passed
  terminals, the signal range and the F-address (they are in the SQL view `api_v1_plc_channel`). A card with two
  channel kinds (16 inputs and 16 outputs) cannot be described. EW-PLC-012 offers no quick fix that opens the part's
  PLC section: the part editor has none.
- **Your own PLC or bus part cannot be made in the window.** The part editor changes a part's identity and technical
  values; it has no PLC section, no bus section and no functions. A card, a head station or a bus plug beyond the
  generic starter parts is written as a part of a library folder by hand, or arrives without a part from a PLC
  software import. A network switch is not modelled: draw it as a device with passive ports.
- **Fluid power is not complete.** A valve terminal's pilot supply is not derived and EW-FL-010 does not check its X
  port. The tube cut list has no cut allowance or order increment, and the tube labels no marker part, because no
  part carries them yet. A cylinder behind a throttle gets no `drives` link by itself. ISO 1219-2 component codes are
  not built.
- **Some window finish is open.** At 2560 × 1440 the Bus, Devices and Medium tables do not widen their column or
  fill their panel; the Medium table counts "1 lines"; the rack editor's refusal stands at the dialog's foot and the dialog
  jumps; some forms (symbol policy, process-tag scheme, fluid settings, mode and safety) have no hint or example; a
  context menu can cover its row.
- **Interruption points need three grid steps** below or above each other: the name stands above the arrow and
  the cross-reference below, so nearer points would print over each other, and the tool does not place them
  (Alt does). Points ended on wires with the Wire tool's interruption point key are not held apart, so wires one
  grid step apart end in points whose texts overlap.
- **A second wire to an occupied pin** is drawn over the first wire's last stretch and shows no dot, so the drawing
  does not say that the two are joined. End the second wire on the first wire instead: that makes a junction with
  its dot.
- **A row of terminals undoes one terminal at a time.** Terminal… lays several terminals with one click, and each
  is its own undo step; the toast's Undo takes back the last one.
- **A point where the supply comes in keeps one warning.** After Supply comes in here… the checks still say that the
  external connection has no cable (EW-CORE-034): add the feeder cable, or waive the finding where that cable
  belongs to the other drawing set.
- **The offered potential needs a known supply.** 0 V is offered on a coil's A2 only when the potential on its A1
  has the type L+ or a phase, or a name that is such a type's word; the starter relay parts do not say whether their
  coil is AC or DC.
- **A project made from the built-in template has no frame** and no title block on its pages, so Title block
  fields… has nothing to edit there; a project made with a company standard has both.
- **A terminal renamed through its Tag** in Properties gets a frozen tag that the page does not print.
- **The importer's messages** (the EW-IMP findings of an import's migration report) read in English in a Dutch
  window: they are stored in the project as the importer wrote them.
- **A new page's grid.** A new page takes the QET 10 px connection grid unless you choose 4 mm in New page or the
  current page has it; the setting "grid for new pages" is not built.
- **A connection point marked not used** shows no mark on the page.
- **Three texts name a thing by its ID or path:** EW-REL-004 prints a revision's ID, EW-CORE-008 a form copy's ID,
  and the refusal of an image file its path.
- **A few built-in symbols keep their English names** in a Dutch window (the junction's dot and bevel, the wire
  marker).
- **A device dropped on a wire connects into it** without asking; a toast says so.
- **The window's pictures were reviewed on Windows only** for this release.
- **Unsigned files.** Nothing is signed (section 1); Windows SmartScreen may stop the setup until you choose to run
  it. Signed releases come with 1.0.
- **Placeholders of online-only files** (Windows' cloud placeholders, iCloud stubs and other dataless files) are not
  detected: a project in a cloud-synced folder whose files are not downloaded fails to open with a missing file,
  instead of opening read-only with the files named.
- **`ew check`** has `--integrity` but not yet its offline mode, `--gate`, `--pages`, `--structure`, `--packs-as-of`,
  `--baseline` and the JUnit and SARIF outputs.
- **What comes with 1.0:** signed files, tags and checksums, a second approval of release jobs, reproducible builds,
  the per-machine Windows installer (MSI), the `.deb` and Flatpak packages, the update check, the crash report with
  its upload, the publishing of the libraries on crates.io, and the steward's processes. No macOS build is planned
  before 1.0. Device descriptions (GSD, GSDML, IODD) and native DWG reading are planned for 1.x.
- **Windows and Linux on x86-64 only.** No aarch64 build is made.
- **A damaged library copy** is named "the library copy of its part" in its banner and in the Save As refusal, also
  when it is a function definition, a symbol or a profile.
