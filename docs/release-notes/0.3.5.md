# ElektraWatt 0.3.5

The release and migration notes of ElektraWatt 0.3.5.

## In short

### New

- **Copy and paste pages:** Page ▸ Copy pages… copies pages with new folios, tags and names; Edit ▸ Paste in place pastes a block where it was copied.
- **Move to page:** Move to page… (the Page tab and the right-click menu of selected symbols) asks for the page and moves symbols to another page and keeps each cut wire as a pair of interruption points, after a preview.
- **Lists on your frame:** lists print on the set's frame, set for all of them in one row of the project's Properties, with your columns.
- **DXF as the PDF:** Export DXF… writes AutoCAD 2010 files that are the PDF's pages, each symbol a named block with its texts.
- **Legend pages:** a panel layout's legend is a list page of its own after the layout, and the plate takes the whole sheet.
- **Two-level terminals:** Draw ▸ Terminal… lays blocks of two levels, each one terminal with one part; the terminal diagram shows the level.
- **A page per PLC card:** the station view draws each card of a station on a page of its own; all on one page stays a choice.
- **Your own PLC and bus parts:** a card holds inputs and outputs in one part, takes several supply pins and moves to another page from its rack.
- **Your own typeface:** a project prints in a font file of its own, such as Arial or Calibri, on screen and in every output.
- **Part not known yet:** devices can take a placeholder part, numbered TBD, until the real one is chosen.

### Changed

- **Wires:** a straight line between two ends stays straight where it crosses nothing, and a wire is cut round a text it cannot step round.
- **Cut and paste:** a cut and its paste move the same devices: terminals keep their strip, parts and bridges, and nothing is left behind.
- **Wire sizes:** a wire takes the size its circuit and its breaker's rating need; one set smaller by hand is a warning with a fix.
- **Wire numbers:** one row of the project's Properties turns them off on every page; wires can take their potential's name as their number.
- **Arrange and route:** a strip of terminals opens to its card's columns, and where no plan is better it says what stands in the way.
- **Imports:** reading an EDZ, a parts XML, a PLC file or a report spreadsheet runs as a job you can cancel.
- **QElectroTech import:** junctions, earth points, cables and title-block fields arrive as a person would draw them.
- **Dutch:** lists, findings, refusals and the navigators read Dutch in a Dutch window, and a project's decimal sign holds everywhere.
- **Window:** a greyed control says why, every key can be rebound, menus and buttons are of one kind, and a warning toast stays.

### When you upgrade

- **No migration:** a project of 0.1.0, 0.2.0 or 0.3.0 opens as it is.
- **This version's rules:** a project prints by 0.3.5's rules (wire sizes, 0 V, PE's name); a PE sized below its conductors is now an error.
- **Drawn anew:** a turned symbol's texts, PLC cards drawn in one row (now in cells) and junction bevels print as 0.3.5 draws them.
- **Words and scripts:** some terms changed in English and Dutch, and a few command-line lines; sections 3 and 5 list them.
- **Back to 0.3.0:** a project saved by 0.3.5 is not promised to open in 0.3.0; section 4 says what 0.3.0 does with one.

### Know before you install

- **Fix release:** it fixes what a first real drawing set met, and its command line may still change in a 0.x release.
- **Unsigned:** Windows may warn before the setup runs, so check each download against `SHA256SUMS` first.
- **No network:** the program makes no network connection of its own, with no update check and no analytics.
- **Engineering verification:** the checks do not replace verification by a competent person.
- **Not yet tried for real:** the DWG converter, the PLC exchange files, and on Windows the new way a PDF or the guide is opened.
- **Support:** with 0.3.5 out, 0.3.0 is no longer supported.

The sections below are the full notes.

## 1. What 0.3.5 is

ElektraWatt 0.3.5 is a fix release. A first real drawing set was made with 0.3.0: brought in from QElectroTech, made to
follow a drawing specification and doubled for a second installation. This release fixes what that job and the
people at the window met, after a round of hygiene in the code that changed nothing a user sees unless section 3
says so. It comes as the same downloads as 0.3.0, for Windows and Linux on x86-64, and with the same warnings:

- **Unsigned.** No file of this release is signed: no signed tag, no Authenticode signature on the Windows programs,
  no signed `SHA256SUMS`. Windows may warn before it runs the setup. Check a download as section 2 says instead.
- **No network code.** ElektraWatt makes no network connection of its own: no update check, no crash upload, no
  analytics (`PRIVACY.md`, in the installation and the repository).
- **Supported until the next release.** Before 1.0 only the latest 0.x release is supported
  ([`SECURITY.md`](../../SECURITY.md)). With 0.3.5 out, 0.3.0 is no longer supported.
- **Engineering verification.** ElektraWatt's checks do not replace engineering verification by a competent person.

## 3. What changed since 0.3.0

What is new as a command or a window action (Copy pages…, Paste in place, a typeface of the project's own, lists
with columns and rows of their own, two-level terminals, a part whose type is not known yet, Export DXF…, Fit the
layout to the sheet, Remove from my parts library…) is described in section 5, with its parameters.

### Pages, copies and the grid

- New page… asked for while a station's view is in front (the PLC workspace) comes with its Connection grid filled,
  the grid of the page tab beside the view, as it does from a page; the field was empty and the page took the default
  grid.
- A page's grid changed (`page.set_grid`) and a paste or a macro fitted to another grid move their symbols and
  junctions onto it together: where the nearest grid points would put two things on one another, or close a gap of a
  step or more that a wire could take, the later one moves on by whole steps, so no symbol ends on another, a row
  keeps its order and two pins more than a step apart keep a grid line between them for a wire (doc 06 §8 item 3,
  FT-1817).
- The same grid fit keeps a row of three or more like symbols that stood at one pitch at one pitch of whole steps;
  each went to its own nearest grid point, so some stood a step closer than their neighbours (doc 06 §8 item 3,
  FT-1935).
- A page's grid changed in Properties leaves every wire a way that had one: a symbol whose pins face the frame's
  drawing area keeps a grid line beside its edge for each of their wires that turns along it, and two pins wired
  straight that stood in line
  stay as near in line as the new grid allows, with a step of room beside the line where one of them cannot stand on
  the grid; wires to a card beside the frame's edge and to a terminal under a contactor found no way after a change
  to the 4 mm grid (doc 06 §8 item 3, FT-2010).
- A page macro's symbols are inserted where they stood, a symbol off the grid too; it was refused as off the grid
  though nothing moves it.
- Paste no longer refuses a block whose free text or graphic lies in the frame's bands, where the Text tool puts
  them; a copied fragment names those in its header (`free`, a member an older version ignores).
- Save as macro… with `pages` (folios) saves a page macro with nothing selected and no page marked; it said "Nothing
  is selected".
- New page… on a front-matter page keeps a layout page (any type the front matter does not hold) in the section it
  proposed when the type is chosen; it moved it into the front matter (doc 06 §5.6).
- Copy pages… renames in the copies' page titles and descriptions too (`page.copy`'s `rename`), and its card lists
  the titles that change; the line over the rename table says what an old text is matched against, and the table
  opens with one empty row with a hint (a row added read "Set 1") (doc 06 §3.6).
- Copy pages… of a bus device (a valve terminal's bus node, a PLC station) says on its card and in the toast after
  Apply that the copy needs a bus line and an address of its own (doc 06 §3.6).
- Copy pages…'s Folio offset and Or after folio are one choice: typing into one clears the other; both stood filled
  and the offset won unsaid (doc 06 §3.6).

### Wiring and interruption points

- A wire drawn that makes an error (L joined to N) says so at once in a toast, in the finding's words, with Undo; only
  the red wire and "1 Error" in Properties showed it (doc 06 §4.4).
- A placement's toast names the wires it made ("… and connected 13 to -101K1:14") and how to place without them, a
  Terminal… row's for all its terminals, and it stays up while the next placements come (doc 06a §7.4).
- An interruption point set on a symbol's pin (24V on a push button's contact) sets its cross-reference past that
  pin's number where its places beside the wire are taken; it lay on the number, and pasted or copied blocks carried
  the overlap along (doc 06a §5.2).
- The Wire tool keeps the straight line between two ends in line where it crosses nothing: a rail drawn one step
  over a row of coils stays as drawn (it went round their pins, and the taps then clicked onto the line found no
  wire); where something stands on the line the wire goes round and the tool's hint says so (doc 06a §7.4, FT-1864).
- A wire that runs through a text it cannot step round (a fixed text, a tag of an imported page) is cut round the
  text, 0.25 mm clear of it, in the window, the PDF, the PNG, the SVG and the DXF alike; a page where no wire runs
  through a text is drawn as before (ADR-0034 amendment 3, FT-1786).
- A wire's frozen number prints: on the page, in the wire list, in `api_v1_wire.number` and in Properties' title and
  Number row, which takes a number typed as the page should print it (`6A03`; empty unfreezes) where it refused it as
  not strict JSON; the frozen wire keeps its place in the count (doc 08 §5.3, FT-1858).
- Draw ▸ Connect ▸ Number wires by potential (`project.settings.set`, member `drawing`,
  `{wire_numbering: per_potential}`) gives every wire of a potential its potential's name as its code (`D02`,
  `6A03`), none to a protective earth or a potential known only by its fallback name; EW-POT-015 counts potentials as
  the units then (doc 08 §5.2, FT-1858).
- Print wire numbers is also a checkbox in the Main group of the project's Properties, which the filter "wire" finds;
  the command search shows whether it is on, and switching it says in a toast what it now is for the whole project.
  Number wires by potential says what it did, and while the numbers are not printed that they show once Print wire
  numbers is on (doc 03 §5.1).
- The history and the Undo and Redo toasts name a drawing setting changed alone by the setting ("Undone: Print wire
  numbers"); they said "Set drawing data" (doc 16a §6.24).
- A device put onto a wire leaves the wire's record (its ID, its number and a frozen number) on the part that keeps
  the end the wire's number is counted from, so the page prints the wire's number where it printed it and the new
  part the next one; the part at the record's first end kept it, and a wire whose number counted from its other end
  printed its number on the new part and a new one on its own (FR-CON-008, doc 06 §5.3, FT-1918).
- The Interruption point tool keeps the direction chosen until you choose another: with Target chosen every click
  places a target, its source drawn or not (after a target it turned to Source by itself); its bar, its toasts and
  EW-CORE-051 say it in a draughtsman's words: a potential comes from one source and goes on at its targets, and the
  finding names where the mark stands ("24V at 102-C1 is a target without a source: place where 24V comes from …")
  (doc 06 §3.5). The tool options card marks Source or Target only while that direction is chosen, so it never shows
  a direction the click does not place; points placed while the card showed Source could come out as targets.
- A wire the Wire tool finds no clear way for says so in a toast with Undo, where only the status line said it, and
  its dashed line is drawn at least a point wide on the screen at any zoom (the paper and the PDF keep the thin pen).
- A route given by a script to a terminal that a strip segment draws (`connection.draw`, `connection.route`, a
  placing hint) ends where the page draws the terminal; one that ends beside it is refused as a route beside a pin
  is, where it was kept and ended anywhere near the terminal.
- A selected wire or fluid line marks its two ends with the connection point's ring (doc 16a §7.1, FT-1780).
- A wire drawn to a drawn box's edge where no pin is keeps its ghost on the page while the new pin's name is asked,
  until it is given or the naming is cancelled (FT-1836).
- A bevel junction is drawn half a step on each leg, as the bevel where two wires of one pin part; it was a quarter
  step. An existing project draws its junctions so when this version opens it (doc 06a §3.4, FT-1898).
- An interruption point dropped on a drawn box's pin no longer lies along or in the box: on the lower side it stands a
  grid step below the pin and on the upper side two steps above it, joined by a straight wire; a source on the box's
  left side or a target on its right side, whose arrow would point into the box, is refused in words (doc 06 §3.5,
  FT-1798).
- A click on a selected mark's own cross-reference text follows it, as with nothing selected; it only selected the
  mark again (doc 06 §2.5, FT-1911).
- An external point's reference holds what is known of the far end: the device or an address alone ("Q4.1"), a
  location alone, or nothing for a far end not known; the point prints what it holds under its mark, and Supply comes
  in here… takes an empty field as not known (`ip.supply_in`, `external_ref.create`: `location` and `device`
  optional); EW-CORE-034 still asks for the cable and names the place by what is known (doc 06 §3.5, FT-1876). What
  0.3.0 does with such a reference is in section 4.

### Potentials, earth, 0 V and wire sizes

- A wire whose protecting device is rated above what its cross-section carries proposes the least cross-section that
  carries the rating, by IEC 60204-1:2016 Table 6, method B2 (PVC-insulated copper, 40 °C, no derating;
  `content/profiles/current/`): behind a C16 breaker 2.5 mm² instead of the class's 1.5 or 0.75 mm², a PE wire by the
  highest rating at its ends; Properties names the device and its rating as the source, and a wire's own
  cross-section, a core's or a potential definition's still wins. Projects of 0.3.0 show the raised size where they
  set none, and two findings change there: a size set by hand that equals the new proposal is EW-POT-016 (redundant
  override, info), and a PE size set by hand below its line conductors' raised size is EW-POT-006 (PE undersized, a
  safety error the release gate counts) (doc 08 §4.2, FT-2055).
- A wire behind a breaker that no supply reaches takes no size from the breaker's rating, as there is no circuit to
  follow; its Cross-section row in Properties now says so, its chip "no supply" where it read "profile", and its text
  "no supply found upstream of -101F1, so its rating is not used" (doc 08 §4.2).
- A wire on a single phase L or a neutral N whose voltage is not known takes the mains class's cross-section (1.5 mm²
  built in), as a phase L1, L2 or L3 does; it took the control size, 0.75 mm², so the sample's N wires were thinner
  than their phases. A project of 0.3.0 shows the larger size where it set none (doc 08 §4.2, FT-1834).
- A wire from a 0 V to an earth symbol is the bond also when the 0 V comes in through interruption points from
  another page, and when only its name says 0 V (`0VDC-6`, an imported supply whose pins say nothing): the 0 V stays
  0 V and is no longer typed PE as a whole, and Draw ▸ Connect ▸ Bond is not needed (doc 08 §3.7, FT-1821, FT-1867);
  the supply marks' panel proposes such a mark as 0 V (M), where it proposed a plus of 0 V. A project of 0.3.0 shows
  such a 0 V as 0 V when this version opens it.
- An earth symbol without a part has no tag unless a frozen one names it: it takes no number of the cables' letter W
  (a page's first cable is W1 again), prints none, is named by its pin (`PE`) in the wire list, the messages and
  Properties, and no check asks for its letter, an imported earth point (letter A) included; its Tag row says why it
  is empty. A project of 0.3.0 prints its earth symbols so when this version opens it (doc 03 §8.2, FT-1820).
- A protective earth that only an earth symbol names (an imported earth point, whose pin is `1`) is called PE in the
  potential list, on the page and in the SQL views; it was called `1`. A project of 0.3.0 calls it PE when this
  version opens it (doc 08 §3.5, FT-1933).
- A project's supply is set in its Properties and by `project.settings.set`, member by member (`supply.<path>`):
  its phases, neutral, PE, earthing, nominal voltage, frequency, upstream rating and short-circuit current,
  previewed as one step; a new project, which has none, takes one with the first value set (1 phase + N + PE,
  230 V, 50 Hz), and a value no supply has (four phases, 0 V) is refused in words; a basic or macro project, which
  has no supply, shows no Supply rows (doc 06 §3.1, ADR-0008 amendment 6, FT-1928).

### Routing, and Arrange and route

- Route lays the wires that go round one end of a card or a box (terminals under a card whose pins face up, each
  wired to the pin over it) side by side as nested rings, a step apart, the pin nearest the corner innermost, where the
  search had laid them one by one at uneven distances; the rings are kept only where the page costs no more (doc 06a
  §3.5, FT-1895).
- Route weighs each wire's kept route alone: a wire that lost its route, on a potential with other wires (a supply
  mark's), is routed again where Route left it without a route and named nothing, and the potential's other wires keep
  the routes they have where those cost no more (doc 06a §3.9, FT-1891).
- Arrange and route keeps a strip's terminals in the order they stand in, always: a feed terminal (wired to no channel
  of the card it stands over) keeps its place between its neighbours, where an earlier build of this release set it at
  the strip's end past the channels' terminals; its wires cross where your wiring crosses (doc 06a §4.4, §4.8).
- Arrange and route steps a card aside by the columns of its channels in use: where they interleave with the used
  columns of a card that faces it, the card with fewer in use steps until its own stand right of the other's, so a
  strip between the two keeps its order and no wire crosses; it stepped half a pitch by all the pins, and only for
  cards of one pitch (doc 06a §4.4, FT-1894).
- Arrange and route and Route keep a wire into an interruption point or supply mark on the mark's line: the layout's
  measure prices a trunk laid beside a mark's line, off it, at 32 steps, so a plan that shortens the wiring that way
  is no longer offered (doc 06a §1.2, C8, FT-1909).
- A second press of Arrange and route, or of Route, offers nothing: a plan is judged with each cable mark and wire
  marker where its new routes will draw it, and Route offers no plan whose marks, set on their new routes, put a text
  on another; a plan kept a cable's core name where the old route crossed the cable's line, and a second press routed
  a wire again (doc 06a §3.10, FT-1880).
- On a page of the QElectroTech grid a text's box keeps its size wherever its symbol stands, so a second press of
  Arrange and route finds the page the first stored; texts on such pages may stand a sixth of a millimetre from where
  they stood, and a wire beside such a text may take another route (06a §2.1, FT-1848).
- Route lays three potentials or more over one row of poles on trunks side by side; a trunk, or a route, more than
  two steps beyond everything else on the page was not held, so the next trunk took its line and its wires were left
  without a route (doc 06a §3.3, FT-1931).
- A wire between two pins that stand nearly in line, one of them off the grid (after a grid change), steps across
  square at the grid line nearest its middle; Route and the Wire tool drew it as one slanted segment (doc 06a §3.6,
  FT-2010).
- A stored route that misses an end it names (written outside the program, drawn with a hook to its pin) is broken to
  Route: a page-wide Route offers to draw it to its end, ticked in the preview as a wire you drew (doc 06a §3.2,
  FT-1975).
- After a click on empty space (a fixed bend) the Wire tool's route on runs along none of the wire drawn so far; it
  could run down, back and up onto the bend's own line and along the first leg, which the wire's commit then refused
  (doc 06a §7.4, FT-2097).
- Arrange and route keeps a spare terminal of a strip between two cards in its place in the strip: the card that steps
  aside steps a strip's pitch further for it, where the spare had found no room and stayed where it stood (doc 06a
  §4.4, FT-2097).
- Arrange and route opens the room the rings of wires round a card or a box need where the parts they lead to stay
  behind it (terminals you kept a step under a card whose pins face up): the card steps away until the rings round
  each end and a step fit between, where its wires found no way round (doc 06a §3.5, FT-2085).
- Arrange and route moves a cylinder or a service unit dragged inside a valve terminal's outline out of it to where it
  belongs (a cylinder over its valve); it joined the terminal and stayed (doc 06a §4.9, FT-2097).
- Arrange and route offers the plan that routes a wire Route leaves dashed though another wire then runs across a text:
  a supply page drawn side by side, whose first mark's wire had no way into the main switch, got "Nothing to arrange"
  where the plan set the feeder in one column and routed that wire (doc 06a §4.7).
- When Arrange and route finds no better plan, it says the page is arranged as well as the rules allow only where
  nothing stands in the way; else it names what does: a symbol left against a rule, a wire without a route, the faults
  the page keeps (doc 06a §4.9). A symbol left against a rule is named with what was in the way of its place on the
  side its pin faces: the symbol standing there, the edge of the drawing area, the text a wire would run through, more
  crossings, or a page no better, where it said only "no better place" (doc 06a §4.7). Its toast is titled "Nothing to
  arrange" and says what stands in the way in short sentences that end in what to look at, readable whole at 1920 ×
  1080; where several things do, it names the first and how many more, and its tooltip and Notifications hold them
  all; the long text was cut before the part a person could act on (doc 16a §6.10).
- Arrange and route sets a power supply under the breaker that feeds it where the designation of the strip its PE wire
  goes to stood in that wire's way: a strip designation now has places below and right of its terminal too, so a wire
  that comes round the terminal's left and over its top need not run through it (doc 06a §5.2).
- Arrange and route opens a strip of terminals at a narrow pitch over or under a card as one, in the order it stands
  in: the channels' terminals that stand in their channels' order go to their channels' columns, every other terminal
  (a feed, a common terminal, a terminal wired to the card's second row of pins, a spare) keeps its place between its
  neighbours, no terminal passes another, and the sensors and buttons over the strip come over their terminals, so
  the wires from the strip to the card run straight; the strip stayed at its pitch where another of its terminals
  stood among the channels' ones, and its sensors' wires went round it. Where it cannot open, or the page is no
  better with it open, the message names the strip and why (doc 06a §4.4, FT-2110).
- Route on a selection says so in its toast, "Routed 1 selected wire" or "Nothing to route among the 14 selected
  items", and how to route the page: select nothing (doc 06a §7.2).
- The Arrange and route card's rows scroll in the Preview pane (wheel and bar), and a zoomed page is fitted as the card
  opens, so the whole proposal shows above it; the rows ran past the pane's edge and the page was cropped (doc 06a
  §7.3).
- A straight route between two ends a fraction of a step apart across it takes its jog on the grid line nearest its
  middle, so a second Route offers nothing for it; the jog could fall off the half grid, which the next Route took
  again. Stored points change only where they were off the grid.
- A second Arrange and route on a page with nothing to arrange shows that it ran: a toast that says again what the
  toast on show says counts the times at its end ("… (2x)"), for every toast.

### Terminals

- Terminal… lays a row three grid steps apart unless told otherwise, the least pitch at which the terminals' numbers
  and the strip's designation stand clear of the neighbours' leads (two stays in the list); a terminal added to a strip
  already drawn on the page keeps that strip's pitch.
- Bridge terminals is in the right-click menu of selected terminals, beside Choose part… and Spacing… (doc 16a §6.13).

- A strip's bridge is drawn on a schematic page where the terminals it joins stand in one row: a line across their
  bridged leads with a dot on each, no record and nothing to select (doc 08 §6.5, FT-1908).
- A block of two levels reads as one block on the page: a short dashed tie joins its two symbols, a bridge hops over a
  lead it passes without joining it, and a level-2 bridge runs apart from the level-1 bridge along the same leads
  (doc 08 §6.5).
- A strip segment draws the bridges of its terminals, a line across the bridged leads with a dot on each, as
  terminals drawn alone in a row do; it drew none (doc 08 §6.5, FT-2020).
- The terminal diagram's first column is the strip, so two strips' terminals 1 read apart; its CSV and XLSX have the
  column too (FT-1805).
- The spacing of a terminal row (Terminal…'s Spacing, Spacing… on placed terminals) is kept between sessions as a
  user setting, `terminal_spacing` in the settings file; it lasted while the project was open (FT-1791).
- A Terminal… row is one Undo step only until the next commit, a property, table or card edit as much as a drawing
  tool's; after an undone row and as many property edits as the row had terminals, one Undo took those edits back
  together.
- Terminal strip (`strip.new`) with the tag of a strip the project has is refused, naming the strip and Draw ▸
  Terminal…, instead of making a second strip of that tag.
- Draw ▸ Place ▸ Terminal… has Levels: with 2, each terminal of the row is a block of two levels, two symbols side by
  side numbered on (1 and 2, 3 and 4 …) that are one terminal of one part, in one Undo step; the form then proposes the
  new starter part EW-GEN-TRM-3, a two-level feed-through terminal. Join device… on a terminal lists the free terminals
  of its strip only, the nearest first; it listed a terminal that was a block already first (doc 08 §6.3).
- A cut and its paste are a move: terminals (or any devices) cut on one page and pasted on another are the same
  terminals of the same strip, with their parts, levels, bridges and frozen tags, and nothing is left behind; they
  were pasted as new terminals of a new strip, and the old ones stayed as an unused strip that the parts list counted
  and that could not be deleted. The cut's toast says what it took and counts the wires that ended at it, which it
  removes with it ("Cut 12 terminals. 14 wires that ended at them are removed with them; a paste keeps the wires
  between the cut items only."); the paste's label says before the click that a tag will follow the new page, and its

## 4. The format

ElektraWatt 0.3.5 writes and reads the project format **0.1**, as 0.3.0 does: the repository's API guard reports no
breaking change to the published schemas in [`schemas/0.1/`](../../schemas/0.1/index.json). A project of 0.1.0, 0.2.0
or 0.3.0 opens in 0.3.5 without a migration and loses nothing.

**The latest version leads** (the project owner, 2026-11-22; ADR-0011 amendment 8): a project saved by a newer build
need not open in an older one, and where a change needs it the format may change in a way an older build cannot read.
Each such change is an entry of the amendment and says here what an older build does with a project that uses it. No
stand-in member and no raised `min_reader` stamp is added to keep an older build reading. What still holds without
exception: a project made by an earlier release opens in this build unchanged and loses nothing, and this build copes
with what an earlier release may have done to a file in between.

The one such change in 0.3.5 (amendment 8, entry 1): `external_ref.location` and `external_ref.device` became optional,
so a reference may hold an address alone, a location alone, or nothing for a far end not known (section 3, "Wiring and
interruption points"). A reference of 0.3.0 holds both and reads unchanged. 0.3.0, which takes the location and the
device as required, opens a project with such a reference for editing, sets the reference's line aside (EW-CORE-007),
reports the points that name it and writes the line back unchanged on save, and the published schema
`external_ref.schema.json` now says both may be absent or null.

The new values of members the format already had, each an additive variant that an older build keeps as an unknown
value (ADR-0011 amendment 1):

- `form`, `representation` and `symbol` `Align`: `baseline_centre`, `baseline_left` and `baseline_right` (a text on
  its baseline, section 5)
- `device`, `part` and `project` `Unit`: `mA` (technical data in milliampere, section 5)
- `page_item` `LayoutLabels`: `tags_or_numbers` (a layout's labels, section 3, "The panel layout and its legend")
- `form` `Overflow`: `fit_width` (a QElectroTech title block's cell scaled to its width, section 3, "Imports"; an
  older build draws the text as `error` does)
- `external_ref` `device`: an `Ident` or `null`, and `external_ref` `location`: a `Uuid` or `null` (the change above)

The same values as the repository's API guard reads them, one line each (`cargo xtask api-guard`):

- format-variant: form Align baseline_centre
- format-variant: form Align baseline_left
- format-variant: form Align baseline_right
- format-variant: representation Align baseline_centre
- format-variant: representation Align baseline_left
- format-variant: representation Align baseline_right
- format-variant: symbol Align baseline_centre
- format-variant: symbol Align baseline_left
- format-variant: symbol Align baseline_right
- format-variant: device Unit mA
- format-variant: part Unit mA
- format-variant: project Unit mA
- format-variant: page_item LayoutLabels tags_or_numbers
- format-variant: form Overflow fit_width
- format-variant: external_ref device Ident
- format-variant: external_ref device null
- format-variant: external_ref location Uuid
- format-variant: external_ref location null

The new optional members are listed with their surfaces in section 5: `ReportBlock.layout_page` and a report block's
`columns`, `caption`, `legend` and `added_rows`, `PlcSection.more_channels`, a free text's `of` and `bind`, a
terminal level's `designation` and a free text's `anchor`.

## 6. Upgrade steps

- **From 0.3.0:** install 0.3.5 over it as the user guide's [Upgrade](../book/src/how-to/install.md#upgrade) says.
  Nothing is migrated: a project of 0.1.0, 0.2.0 or 0.3.0 opens as it is.
- **A project you already have prints by this version's rules.** Until 1.0 a project made by an earlier version prints
  by this version's rules when this version opens it: every change in section 3 to what a page, a list or an export
  prints applies to a project of 0.3.0 as well, with no new derivation profile to choose. Frozen tags and numbers,
  committed computations and the PDF of a released revision stay as they are (ADR-0003 amendment 3).
- **Back to 0.3.0:** a project saved by 0.3.5 is not promised to open in 0.3.0 (section 4). An external point whose
  far end is not wholly known is set aside there and written back unchanged.

### What changes in a project you already have

Check a project against this list after opening it in 0.3.5 (each item is in section 3):

- Wire sizes: a wire behind a protective device rated above what its size carries shows the raised size where none
  was set (behind a C16 breaker 2.5 mm²); a size set by hand that equals the proposal is an info finding
  (EW-POT-016), and a PE size set by hand below its line conductors' raised size is EW-POT-006, an error the release
  gate counts.
- Wire sizes: a size set by hand below what its protecting device's rating needs (1.5 mm² behind a C16 breaker) is
  the new warning EW-POT-022.
- Wire sizes: a wire on L or N whose voltage is not known shows 1.5 mm² where it showed 0.75 mm².
- 0 V: a 0 V bonded to earth through interruption points or known by its name alone stays 0 V; it was typed PE.
- Earth symbols without a part print no tag, take no cable number (the first cable may become W1) and are named
  `PE` in the wire list.
- PE: a protective earth known only by an imported earth point's pin is called PE, not `1`.
- Turned symbols: the texts of a symbol turned a quarter stand anew round its body; a text you dragged keeps its place.
- PLC cards drawn in one row print their channels in cells; a card of the older two-row form is redrawn by Draw the
  card in one row.
- Junction bevels are drawn half a step on each leg.
- Bus lines drawn before take their physical net when drawn or changed again.
- Lists: a page holds as many rows as its frame has room for, prints on the project's frame and in the project's
  language, ends on no page of one or two rows; the terminal diagram has a Strip column and a Level column; the potential overview
  numbers declared bonds first.
- A layout's legend box prints as before until Move the legend to its own page; a legend made before 0.3 shows its
  four columns ticked in List columns….
- On pages of the QElectroTech grid a text may stand a sixth of a millimetre from where it stood, and a wire beside it
  may take another route.
- An export folder written by 0.3.0 is refused once by the PNG, SVG and DXF exports.
- A script that sets the wizard's `report_blocks` to `golden` must set `standard`.
- A symbol's texts written in several languages print in the project's language; the lists print dates in the
  project's date format; a project without a decimal separator of its own shows a comma in Properties where its
  language writes one.
- A script that runs `strip.delete_rows` uses Delete in the Strip column (`table.clear`).

## 7. Known limitations

- **DWG needs a converter that you install,** and ElektraWatt has not been tested with a real ODA File Converter: the
  tests use a stand-in program. There is no DWG export; export DXF and convert it with your CAD program.
- **The exchange files are not yet read by a real TIA Portal or CODESYS.** The AutomationML, tag-table and PLCopen files
  follow their formats and are checked on reference files only; the bus attribute names of the AutomationML export are
  unverified. The import preview does not list the affected folios, racks are not exchanged items and the HMI flag
  of a tag is not a setting.
- **Some reading still holds the window.** A PLC import's merge and an EPLAN report becoming a project once read run on
  the window's thread.
- **Some notices are in English in a Dutch window:** those of the Preview tab's re-address (old and new address),
  overview generator and instrument list.
- **A very large DXF may be refused.** The reader's memory budget is an estimate and about 150,000 plain entities fit; a
  legal large drawing can be over it. A PDF placed as an underlay is bounded in pages and pixels but not in time.
- **Printing draws no underlays.** `--underlays` of the exports does; the print set does not. A part's drilling pattern
  is not read from a DXF.
- **The EPLAN imports are not complete.** A part's picture from an EDZ, a device's connection points from a report
  spreadsheet and a report's re-import into an existing project are not built. The table from EPLAN function
  templates to function definitions is not checked against a real EPLAN export.
- **An imported project shows many hygiene findings** (a device without a part, a frozen value that deviates, a tag
  that deviates from its scheme, routes through symbols). None is an error, but the list buries what matters.
- **An imported QElectroTech folio still differs** in a few places: a master's contact list has no contact symbols
  and its rows stand closer than in QElectroTech; cross-references shown as a cross or placed at the bottom print as
  a list, with a report entry; QElectroTech's folio list arrives as ElektraWatt's own table of contents; an element's
  mirror is not read (QElectroTech 0.100 writes none; newer versions do). Measured on a real set with QElectroTech's
  face as the typeface, about one text in thirty stands apart from QElectroTech's own PDF: the folio list, the rows of
  a contact list, a few texts QElectroTech prints reading downward, which ElektraWatt turns to read from the bottom or
  the right, and rich texts that QElectroTech's computer printed in another face (Tahoma) 0.6 to 1.4 mm higher, which
  the project's typeface does not move. In Noto Sans the title blocks' texts also stand apart by the face's widths.
- **PLC drawings are tight on cards drawn before.** On a card drawn with two rows of pins the canvas prints a channel
  address and the module's pin labels small: "1 Q0.0" needs about 7 mm against a pin pitch of 5.3 mm, so they can
  be hard to read; Draw the card in one row draws it in the new form. The I/O list does not take the passed
  terminals, the signal range and the F-address (they are in the SQL view `api_v1_plc_channel`).
- **Your own parts have limits.** A device that belongs to no PLC is left out of the export to PLC software. A device
  placed first on a bus page takes its tag from that page, and the tag changes to the schematic page's when its black
  box is placed there later (a toast says so). Device description files (GSD, GSDML) are not read: the part is typed
  from the data sheet.
- **Fluid power is not complete.** A valve terminal's pilot supply is not derived and EW-FL-010 does not check its X
  port. The tube cut list has no cut allowance or order increment, and the tube labels no marker part, because no
  part carries them yet. A cylinder behind a throttle gets no `drives` link by itself. ISO 1219-2 component codes are
  not built.
- **A flow control set against a valve terminal's outline** can leave the tube from its valve without a way, and
  Arrange and route may leave it there; set it two steps off the outline (FT-2106).
- **Valve terminals have limits.** A terminal part that comes in several sizes is not asked for its size when it is
  placed. The part editor cannot set a valve terminal's kind (bus node or multipin) or its pin map; the starter parts
  carry them.
- **A silencer, a plug or a drain also shows an editable Medium row.** The window takes a device for a source of a
  medium by its ports, and these have one.
- **A station made in the New station view shows ? in its tag** where the page goes, until it is drawn on a page.
  EW-CORE-047 and the station's To do say so.
- **The edited date from the command line.** `ew` commands that save a project with changes set its edited date only
  when `SOURCE_DATE_EPOCH` is given, so that no output depends on the day it runs; without it the date stays as it
  was.
- **Some window finish is open.** The Medium table counts "1 lines". Seen once and not reproduced: a first click on a command bar button right after a table cell edit that only ends the edit, and the
  Properties header cut by its chips (FT-2006).
- **Interruption points need three grid steps** below or above each other: the name stands above the arrow and
  the cross-reference below, so nearer points would print over each other, and the tool does not place them
  (Alt does). Points ended on wires with the Wire tool's interruption point key are not held apart, so wires one
  grid step apart end in points whose texts overlap.
- **A point where the supply comes in keeps one warning.** After Supply comes in here… the checks still say that the
  external connection has no cable (EW-CORE-034): add the feeder cable, or waive the finding where that cable
  belongs to the other drawing set.
- **The offered potential needs a known supply.** 0 V is offered on a coil's A2 only when the potential on its A1
  has the type L+ or a phase, or a name that is such a type's word; the starter relay parts do not say whether their
  coil is AC or DC.
- **F1 inside a dialog opens the dialog's section.** A field of a dialog has no section of its own; rows of
  Properties have. There is no page for each kind of device: a contactor opens Devices and symbols.
- **Shapes cannot be drawn from the keyboard alone in the symbol editor,** only a thing already drawn can be moved with
  the arrow keys.
- **Handles show for one selected wire.** With several wires selected, none shows a handle.
- **A valve stays undrawn when a terminal's positions are filled through `ew apply` without the symbols.** Draw its
  valves in the valve terminal draws it.
- **The title block's layout and the frame's columns and rows cannot be changed in the window.** Both are planned for
  the next milestone (FT-1814 and FT-1815).
- **A wire can find no way after a grid change** between two bodies whose edges the fit leaves off the grid's lines,
  with no grid line a step from both: the message counts such wires and they stay dashed; move the items apart and
  choose Route (FT-2105). A `page.set_grid` without `area` (from the command line, a script or a replayed log) keeps
  no room at the drawing area's edge either, so a wire from a pin facing it can find no way; the window gives the
  area.
- **A grid change draws the page's wires anew**, as Route draws them: the rails move to two steps from the pins
  they tap, and a wire you drew straight down may run along a row first; Undo gives your wires back (FT-2111).
- **A move to another page keeps a net with one junction at most.** Move to page… and a PLC card's Move to
  page keep each wire to what stays behind as a pair of interruption points; a net that runs through two junctions
  or more (a supply rail) is refused in words: move it by hand, or cut and paste, which drops such wires and says
  how many (FT-2135). The moved symbols keep their coordinates on the new page and may land on what stands there:
  move them after, or choose Arrange and route.
- **Arrange and route leaves some pages to you.** It is an aid and the page stays the draughtsman's: what it
  offers is a start, never worse than what stood there, and not always a page ready to sign. It turns no symbol, does not spread a circuit over the sheet and
  moves no symbol to another page. Where the terminals of a strip are wired to a card in another order than they stand in, it leaves
  the whole page as it is and says so, the sensors over the strip too (FT-2143).
- **A symbol level beside the one that feeds it stays there.** Where a wire runs from a symbol's lower pin to the upper
  pin of one standing level beside it, Arrange and route leaves the second beside the first and the wire goes round
  it; move it two steps lower and choose Arrange and route again, which sets it in line (FT-2107).
- **After rows are unticked, the Arrange and route card can still list a few of your wires** that Route alone would
  route anew as well.
- **A channel with nothing wired has no function text.** The function text of a channel is its wired device's, so
  the station view's table and the PLC grid take none for a channel nothing is wired to, and say so.
- **A new terminal strip's tag follows the wizard's rule of letter, page and counter:** -X1021 for the first strip
  of page 102.
- **A list's "continues on" row is drawn in the window, not printed.** The printed page of a list of several pages
  is unchanged.
- **The project's Document title is not a cell of the title block.** The program's frame prints no cell for it;
  Title block fields… says which cell prints each field.
- **A terminal renamed through its Tag** in Properties gets a frozen tag that the page does not print.
- **The importer's messages** (the EW-IMP findings of an import's migration report) read in English in a Dutch
  window: they are stored in the project as the importer wrote them. A re-import's two findings are the exception.
- **A new page's grid.** A new page takes the QET 10 px connection grid unless you choose 4 mm in New page or the
  current page has it; the setting "grid for new pages" is not built.
- **A connection point marked not used** shows no mark on the page.
- **Two texts name a thing by its ID or path:** EW-CORE-008 prints a form copy's ID, and the refusal of an image
  file its path.
- **A few built-in symbols keep their English names** in a Dutch window (the junction's dot and bevel).
- **A device dropped on a wire connects into it** without asking; a toast says so.
- **The window's pictures were reviewed on Windows only** for this release.
- **Opening a file on Windows is new and not yet tried there.** An exported file, its folder, Open in PDF viewer and
  the guide (F1) open through the system's own open call, built and checked for Windows but not run on it: where
  one of them opens nothing, open the file from its folder, or the guide from the installation folder.
- **A file dropped onto the window opens or imports nothing** but an image: a project, a QElectroTech file or a table
  is refused in words; open or import it from the File menu.
- **Unsigned files.** Nothing is signed (section 1); Windows SmartScreen may stop the setup until you choose to run
  it. Signed releases come with 1.0.
- **Placeholders of online-only files** (Windows' cloud placeholders, iCloud stubs and other dataless files) are not
  detected: a project in a cloud-synced folder whose files are not downloaded fails to open with a missing file,
  instead of opening read-only with the files named.
- **`ew check`** has `--integrity` but not yet its offline mode, `--gate`, `--pages`, `--structure`, `--packs-as-of`,
  `--baseline` and the JUnit and SARIF outputs.
- **What comes with 1.0:** signed files, tags and checksums, a second approval of release jobs, reproducible builds,
  the per-machine Windows installer (MSI), the `.deb` and Flatpak packages, the update check, the crash report with
  its upload, the publishing of the libraries on crates.io, and the steward's processes. No macOS build is planned
  before 1.0. Device descriptions (GSD, GSDML, IODD) and native DWG reading are planned for 1.x.
- **Windows and Linux on x86-64 only.** No aarch64 build is made.
- **A damaged library copy** is named "the library copy of its part" in its banner and in the Save As refusal, also
  when it is a function definition, a symbol or a profile.

## 8. The notices of the AppImage's runtime

Unchanged since 0.1.0. The Linux AppImage starts with the AppImage project's static type-2 runtime, release 20251108:
a separate program at the start of the file, not linked into ElektraWatt. It is MIT-licensed and links statically
musl libc (MIT), libfuse 3.15.0 (LGPL-2.1-only), squashfuse 0.5.2 (BSD-2-Clause), libzstd (BSD-3-Clause), zlib
(Zlib) and mimalloc (MIT). Their notices are in [`NOTICE`](../../NOTICE), and in every installation; the runtime's
source is at <https://github.com/AppImage/type2-runtime>, tag 20251108, commit
dd6cebedcbddde9c82f89b011e8e1d40b6e43868.

The notices of the libraries ElektraWatt is built from are written from the dependency graph when each download is
built, and ship in every download as `THIRD-PARTY-NOTICES.txt`. No library joined the graph since 0.3.0: skrifa, which
`ew-commands` now uses to read a project's font file (section 5, Dependencies), was already in it.
