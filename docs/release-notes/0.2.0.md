# ElektraWatt 0.2.0

The release and migration notes of ElektraWatt 0.2.0.

## 1. What 0.2.0 is

ElektraWatt 0.2.0 is a fix release for the pilot. It builds no new feature: it fixes what stopped the work when
0.1.0 was used by hand, in the wizard, a new project, placing, wiring, routing, the symbol editor and the
QElectroTech import. It comes as the same downloads as 0.1.0, for Windows and Linux on x86-64, and with the same
warnings:

- **Unsigned.** No file of this release is signed: no signed tag, no Authenticode signature on the Windows programs,
  no signed `SHA256SUMS`. Windows may warn before it runs the setup. Check a download as section 2 says instead.
- **No network code.** ElektraWatt makes no network connection of its own: no update check, no crash upload, no
  analytics (`PRIVACY.md`, in the installation and the repository).
- **Supported until the next minor release.** Before 1.0 only the latest 0.x release is supported, until the next
  minor release ([`SECURITY.md`](../../SECURITY.md)). With 0.2.0 out, 0.1.0 is no longer supported.
- **Engineering verification.** ElektraWatt's checks do not replace engineering verification by a competent person.

## 2. The downloads and how to verify them

The release on the repository's releases page holds these files, each built by the release workflow from the
release's commit:

| File | What it is |
|---|---|
| `ElektraWatt-0.2.0-x64-user-setup.exe` | The per-user setup for Windows 10 and 11: the window, `ew.exe`, the starter content, the sample project and the user guide in one folder, no administrator rights needed |
| `ElektraWatt-0.2.0-x86_64.AppImage` | The same for Linux (glibc 2.35 or newer, as on Ubuntu 22.04 and Debian 12), one file to make executable and run |
| `ew-0.2.0-x86_64-pc-windows-msvc.zip`, `ew-0.2.0-x86_64-unknown-linux-gnu.tar.gz` | The command-line program `ew` alone, with the starter content, the sample project, the licence texts and the notices |
| `SHA256SUMS` | The SHA-256 checksum of every other file |

Verify a download before you run it: check it against `SHA256SUMS`. The user guide's
[Verify a download](../book/src/how-to/install.md#verify-a-download) gives the commands for Windows and Linux;
[Install ElektraWatt](../book/src/how-to/install.md) installs, upgrades and removes each download.

## 3. What changed since 0.1.0

### The wizard

- Every step of the company-standard wizard says in plain words what it sets, what the choice changes and where it
  can be changed later. The steps are numbered 1 to 10, and each has one main button in a bar at its foot.
- Each step shows a Result that follows what you type: the title block's lines, the rows of a colour profile, the
  numbering with two worked names, each report with its page, each check level with an example finding. The
  colour step shows the cover page, which prints the colour table. The example page uses the room a wide window
  leaves.
- "Check scheme" reads "check level" in the wizard, and no text of the wizard names the sample project.

### Placing, the device browser and Properties

- Device and Symbol on the Draw tab open one browser over the dimmed window: a category tree with counts on the
  left, dense rows in the middle (name, part number, ratings, library; a part opens to its functions), and on the
  right a picture of what will be placed, with its connection points and a Place button. A click selects a row; a
  double click or Enter places it.
- Terminal on the Draw tab opens the browser on the terminals. Terminal strip (Draw menu) makes a strip at once and
  lost its "…".
- Every row of the Insert symbol list arms a tool or says why it cannot. Wire marker and the two interruption points
  arm their tools; the junction's dot and bevel, the cable marker and the external arrow are no longer rows; a
  greyed row says which page type takes it.
- Picking a contact of a relay already in the project fills that relay ("join -1K1") instead of making a second one.
  J, and Join device… in the page's right-click menu, open the join chooser on one selected symbol. Deleting a device
  removes its unplaced functions with it.
- While a device is placed, one label stands beside its outline and names its tag. The tool options card is one row
  under the tab bar, stays whole while you type into it, and covers no drawing of a fitted page.
- A drag right after the click that selected a symbol moves it. A paste floats with its middle at the pointer.
  Edit ▸ Select all (Ctrl+A) selects the page's items. A device selected by its tag shows its outline.
- Page ▸ New section…, a button beside New page in the Pages panel and the tree's right-click menu make a section,
  proposing the next number and the next hundred folios. The tree lists a section without pages, and New page
  proposes the first free folio of the section chosen in the tree.
- Properties: every row's label has a tooltip in English and Dutch; a click on a category header folds that
  category, and Enter and Space fold it too. A derived value's chip names its source (profile, potential, cable,
  default) and its menu goes there; a wire or an interruption point shows its potential's definition to edit, or
  Define potential… where there is none. A connection point can be marked not used from its Properties row or the
  page's right-click menu (Mark not used); its unconnected finding then drops to info. The rows are denser.
- Symbols, definitions, functions and fields are named in words, not by an ID or a key, in Properties and the part
  chooser; a library's tier reads "(System)".
- The symbol browser and the device browser each say in one line what they list: a symbol is a drawing without
  a part, a device a part of the catalogue with its functions. The symbol browser no longer lists the parts (the
  device browser's) nor the terminals (Terminal's). The right rail's buttons read Symbol browser and Device browser,
  where they read Symbols and Parts.
- Under a symbol's picture in either browser, Edit symbol opens it in the symbol editor, saving its next version to
  its library; a symbol of a read-only library (the starter's) offers Copy and edit, which says why and opens a copy
  saved to your own library.
- Terminal on the Draw tab asks for the strip (one of the project's or a new one with the tag it will take), the kind
  of terminal, how many and from which number; Place floats the first terminal and one click lays the row.
- A black box placed from a part puts the part's inputs on its top edge and its outputs at the bottom: the starter
  power supply's first + stood at the top with L, N and PE (the layout split the seven points four over three).
- A connection point chosen in a device's Properties is ringed on the drawing in the selection colour, so that
  "which + is this" is answered by looking.
- The command search finds a panel by its name. The PLC panel says that a placed card waits for a CPU, and how to
  place one. The page's Pending badge counts findings as Messages does. The terminal counter no longer proposes a
  designation in use.

### Wiring, routing and interruption points

- A selected wire shows a handle on every segment and bend. Every segment drags sideways, every bend drags as a
  corner, and the ends stay on their connection points. An unrouted wire takes its first route the same way.
- A right click on the page with any tool but Select is Escape, one step per click.
- With Select, the right-click menu is the quick way to what fits the thing under the pointer, its own entries first,
  then Cut, Copy, Paste, Delete and Properties: a terminal adds a terminal to its strip or opens the strip editor
  (a strip's row in the Terminal strips navigator too); a relay's coil adds its free contacts by name, a contact goes
  to its coil; a wire edits its route, marks it, defines its potential, makes or opens its cable and prints the wire
  numbers; several wires make a cable; an interruption point goes to its partner and sets its direction; a device's
  symbol chooses its part and opens its symbol in the symbol editor; the title block edits its fields; an empty spot
  offers Paste, Page properties and New page…. Shift+F10 or the menu key opens it at the selection.
- A wire without a route is drawn dashed and right-angled (straight for aligned ends, else with one corner), never
  as a diagonal, on the page, in the Wire tool's ghost and in every export.
- A straight wire drawn across a symbol in line passes through a terminal only. A fuse, a contact or a coil in the
  way is gone round; to put it in series, drop it on the wire or wire to its pins.
- Route page and Route selection draw the routes they plan on the canvas while their card is open, and the page
  moves to them when the card's panel takes room from the canvas. Where nothing new can be routed, the message says
  why each wire stays unrouted.
- A Wire marker box that is ticked always prints a marker: what the wire states, else what it is.
- The Marker tool marks: after a line dragged across the wires, Enter places the marker. Its Colours field takes a
  code in any case, two codes of one wire (`GN+YE`, `GNYE`), a company code or a colour's name from the colour
  profile; one colour is every marked wire's, a list (`BK, BU`) gives each its own. A colour the project does not know
  is refused with the codes it knows, and the marker can be corrected and placed again.
- Cable on the Draw tab makes the selected wires a cable in one form: its tag, its type as written (`3G1.5`,
  `4x0.75`, or a cable part's number) and each wire's core, which can be changed; Apply is one undo step. The wires
  then print the cores' cross-section and colours. On a cable's wire the same form opens that cable, to add a wire
  or take one out, and a wire's Properties name its cable and core.
- A wire marker stands clear of its wires: a short line across them and the text beyond its end, never over a wire.
- Draw ▸ Connect ▸ Print wire numbers prints every wire's number on its pages, the PDF and print: beside the wire,
  once, at the middle of its longest segment, and first in the text of a marker the wire carries. A cable's core
  shows its cable and core in Properties instead of "?".
- A selected wire whose potential has no name may be offered one on a card beside it, with why: the A2 of a coil fed
  from L+ is the 0 V and from a phase the N, a pin with a role (the − of a DC supply, N, PE) has that type, and the
  project's one named potential of that type is the name ("Potential 0VDC?"). Accept defines it in one step; Decline
  hides the card for that wire in the session.
- Define potential… offers the type as a list, with the words Properties shows for it (L1, N, PE, L+, …, or None);
  it was a text to type. A form's list shows every choice without a scroll.
- A wire whose potential has the type L1, L2 or L3 and no voltage or AC/DC of its own is a phase of an AC supply:
  it takes the mains class's cross-section (1.5 mm² by default) and the colour the colour profile gives a phase.
- Interruption points: a typed name stays after its source, and the tool floats its target, on the same page too.
  With the pointer on the sheet, D turns the direction instead of being typed into the name. Making a point the
  source makes the other source of its name the target in the same step, one undo for both. A click anywhere on the
  arrow, its tip included, ends a wire on its connection point.
- The interruption point tool takes the name first: chosen from the Draw tab or the menu, its name field has the
  keys, so the name is typed at once and Enter ends it. D turns the direction between source and target, to and
  fro (it went on to undirected, which is now a choice of a placed point's Direction in its properties). A new
  name typed after a pair starts with its source.
- An interruption point keeps room for its texts: where its name or its cross-reference would print over another
  point's, it is not placed and the message says why; Alt places it anyway.
- The message about three wires at a point shows only while a wire is drawn.

### The symbol editor

- A drawn symbol reaches a page: its key is made from its name until you type one; a refused action says why under
  the symbol's name; Save says where the symbol went; a second symbol of the same name takes the next free key; a
  changed symbol is saved as its next patch version.
- A drag draws a line, a circle, an ellipse and an arc, as it draws a rectangle.
- Select picks a shape, a connection point, a text slot or a link point. A drag moves it and shows its outline where
  it will land, an arrow key moves it one step, Delete removes it. A connection point stays on the connection grid.
- The Text tool takes one label after another: click the spot, type, Enter, and again. The field empties after each
  label.
- Close editor is the editor's main button, at the right end of its header. The editor's button on the Draw tab is
  named Symbol editor and stands in its own column. The toast after a save stands under the header, so Close editor
  can be clicked at once.
- Place on a new page with its grid no longer leaves an empty page when the placement is refused: the page is taken
  back and the page you were on shows again. A symbol file that cannot be read and a draft that cannot be written
  are said in ElektraWatt's words.
- The drawing grid is yours to choose, in the editor's header beside Fit drawing: 0.5, 1, 2 or 4 mm or QET 10 px,
  and Snap to grid off. Connection points keep to the connection grid whatever is chosen; the canvas shows both
  grids, and the choice stays for the session.
- A drawn symbol takes a category, under its name on the Drawing and Library tabs, in the browsers' words; it was
  always listed under "Assemblies and black boxes".
- Every tool of the editor's bar says in its tooltip what it does and how ("Line: drag, or click two points").

### The QElectroTech import

An imported folio now looks as QElectroTech draws it:

- Every wire has the route QElectroTech draws: the path the file stores, else QElectroTech's own automatic path. No
  imported wire is left unrouted, so the import needs no Route page.
- The frame is QElectroTech's (columns from 1, the border where QElectroTech draws it, no band QElectroTech hides),
  and the project's own title block is imported as a form, filled with each folio's values, its logo included (SVG
  too). QElectroTech's tables arrive as report blocks, and a folio report takes the name QElectroTech prints.
- Free texts, shapes and images arrive. Elements print their own texts and information; a symbol's text of several
  lines keeps its line spacing; a label that several elements carry prints on each; an element without a label
  prints no made-up tag.
- The folios print QElectroTech's cross-references at the arrows, for page links and for masters and slaves.
- An import without the starter content folder loses nothing: the starter documents are built into the program.
- The import card says what Create project will make, gives a verdict, names a missing starter library before the
  project is created, and groups the findings under Needs a fix, Worth a look and For your information. The second
  dialog that asked again is gone.

What still differs is in section 7.

### Checks and reports

- Every check rule's message reads in Dutch in a Dutch window, with Dutch fallback words and decimal commas.
- EW-POT-011 names the junction (folio and cell) or the group of interruption points, and the wires that meet there.
- EW-POT-021 no longer reports two loads in series between the two sides of a supply.
- EW-POT-001 accepts an L pin (a power supply's single-phase input) on one phase, L1, L2 or L3; it reported "role
  L; the defined type L1". An L pin on N stays an error.
- EW-CORE-069 (wire through a symbol) counts only symbols with connection points, so a cable or wire marker, or
  QElectroTech's cross-section mark drawn across a wire, is no finding.
- EW-RDS-003 judges a device's letter by its part's category where the part has one.
- A PLC card's channel bound to its own pin is spare until a wire reaches the pin; the PLC overview no longer shows
  every such channel as used.
- `ew render` and the page exports say what a page's findings are, such as "12 page findings: 12 empty fields in a
  frame or title block".
- Waive… no longer asks for a reason of at least ten characters: the reason and the author are optional.
- The line "Checks support, but do not replace, engineering verification" has gone from the Messages pane, and the
  Approve and Release dialogs no longer end with the disclaimer; About keeps it.

### The starter content and the sample

- The starter contactor is filed as a contactor: the browser lists it under Contactors and offers the letter Q.
- The starter set has a three-pole miniature circuit breaker (EW-GEN-MCB-3) and a 3/2 solenoid valve
  (EW-GEN-VLV-2), with their symbols and function definitions.
- The starter power supply's + and − are source outputs, so the potentials of the 24 V circuits are reached from it.
- The relay coil (`ew.iec.coil` and its `@qet10` twin) is drawn as IEC 60617 draws a coil: a box wider than high
  across its leads. It read as a resistor. Its connection points stay where they were.
- The starter symbols have Dutch names. The three-phase motor's texts are spaced so that its wires are routed clear
  of them.
- The sample project holds the new copies (the Dutch names, the power supply's definition); its findings and
  outputs are as before.

### Texts and Dutch

- No English reaches a Dutch window from the reference resolver, the schema errors (which named a JSON Pointer;
  they name the field), the strip editor (which also takes "ja" and "nee"), the failed saves, the function kinds and
  the ends of a wire. A blocked pin is named as the page prints it, an image over the limit by where it shows.
- Nineteen labels made by the machine ("Pos") have words.

### The window's finish

- The tool bar on the page stands in a strip of its own under the canvas, so it never covers the drawing or the
  title block.
- A page opens with the whole sheet and its title block in view, unless a fit to the width is more than 15 %
  larger.
- Every floating overlay (the browser, the command search, the junction editor, the text popup, the join chooser)
  closes on a click beside it, as Escape does, and has a close button where it has a title row.
- The device browser's picture says why it is empty for a part without a symbol, and the External reference field
  of the tool options reads label first.
- An open project refreshes its lock, so another session no longer takes a project that has stayed open for more
  than an hour.
- Open on the toast of a finished PDF export, and in the Jobs pane, opens the file in your PDF viewer; it did
  nothing on Windows.
- **File ▸ Import…** stands beside Open: it takes a QElectroTech project (`.qet`), whose import it starts, or a
  project archive (`.ewz`), which it extracts or opens read-only. The File menu no longer has an Open .ewz… entry.
- On Windows, `elektrawatt.exe`, its window, the task bar, the Start-menu shortcut and the setup show the
  ElektraWatt mark, the bolt of the menu button; no console window opens before the application any more.
  `elektrawatt --headless`, `--smoke` and `--version` still write to the terminal they are started from.
- **Page ▸ Title block fields…**, also a link under the page's name in Properties, edits in one form every field the
  page's title block prints from the project's data: the description, the project reference, the drawing and
  object IDs, the dates, the end user and the other parties, the revision and its Author and Checked (the names of
  the parties the revision names; Checked once the revision is approved). The page prints the new values at
  once, also on a page imported from QElectroTech. The project's master data and parties are editable in Project
  properties too.
- A panel layout page can be found and made: Draw ▸ Rail, Duct and Auto-fill rail say in their disabled reason how
  to make the page (New page… with the type Panel layout) and, on such a page, how to show an enclosure; Project ▸
  Enclosure… on a panel layout page that shows none puts the new enclosure's plate on it. The guide has a how-to,
  "Draw a panel layout". Enclosure… says in a toast which enclosure it made at which location; on another page the
  toast's Undo takes the enclosure back.
- In a project imported from QElectroTech, New page… gives the new page the frame and title block of the page it is
  made from; it had none, since such a project sets no frame defaults.
- Help ▸ Tutorials no longer lists the command-line walk-through; it is a how-to of the guide now, "Use the command
  line on the golden project". It lists every tutorial of the guide, the symbol editor's "Draw a six-pin power block"
  too.

## 4. The format

ElektraWatt 0.2.0 writes and reads the project format **0.1**, unchanged since 0.1.0: the repository's API guard
reports no change to the published schemas in [`schemas/0.1/`](../../schemas/0.1/index.json) (0 breaking, 0
additive). A project of 0.1.0 opens in 0.2.0 without a migration. One member joins the open drawing settings that
`settings.extra.drawing` keeps without a schema of its own: `wire_numbers` (`true` prints every wire's number; absent
means none), an additive member (ADR-0011 decision 6) that 0.1.0 keeps and ignores.

What changed is the content a project copies from the starter libraries:

- **Symbols.** Every starter symbol has a new patch version for its Dutch name (for example the interruption point
  `ew.gen.ip` 0.2.1, `ew.gen.ip-target` 0.1.1, the strip segment `ew.gen.strip-segment` 0.2.1, the heater
  `ew.iec.heater` 0.1.2). The three-phase motor `ew.iec.motor-3ph` is 0.3.0: its texts are spaced and its
  connection points move. The coil `ew.iec.coil` and `ew.iec.coil@qet10` are 0.2.2: drawn wider than high, their
  connection points unchanged. New: `ew.iec.mcb-3p` and `ew.iso.valve-3-2-sol-spring` 0.1.0, each with its `@qet10` twin.
- **Function definitions.** New: `ew.fn.mcb-3p`, `ew.fn.valve-3-2-sol-spring` and `ew.fn.psu-ac-dc` (the power
  supply), each 0.1.0.
- **Parts.** The starter parts library is 0.6.0: the contactor EW-GEN-CON-1 carries the category of a contactor
  (letter Q), the power supply EW-GEN-PSU-1 uses the new definition, and EW-GEN-MCB-3 and EW-GEN-VLV-2 are new. The
  sample project's parts library is 0.1.1 (its power supply uses the new definition).

A project keeps the copies it holds. It takes the new versions only when you update its copies from the library.

## 5. The command line, the commands and the other surfaces: what changed

Every surface is still **Preview** ([doc 17](../design/17-extensibility.md#11-api-stability-and-versioning) §11):
the command-line program, its JSON results, the commands, the queries and the SQL views may change in a 0.x release,
and each such change is listed in that release's notes.

### The command-line program `ew`

- **Behaviour changed:** ew import qet (without `--content` or `EW_CONTENT_DIR` it imports with the starter documents
  built into the program, so no folio report or wire is dropped; every wire is stored with the route QElectroTech
  draws, the stored path or QElectroTech's automatic path; free texts, shapes, images, the title block and its logo,
  tables and cross-references are imported)
- **Behaviour changed:** ew layout (measures routed wires only, as the check rules do: a wire without a route is left
  out)
- **Text changed:** ew render, ew export pdf|svg|png and the report PDF (the page findings line on standard error
  names each kind with its count, "12 page findings: 12 empty fields in a frame or title block", instead of "12 page
  findings (unresolved wire ends, unknown styles, overflowing table texts)")
- **Behaviour changed:** ew apply (refreshes the project's lock before each line, so a long log keeps the lock)
- **Behaviour changed:** ew verify-derived (also sweeps the memoised check findings)

### Commands

- **Behaviour changed:** command fields.set and fields.set_many (making an interruption point the source makes every
  other source of its name a target in the same step, one undo, unless the name has a star source or the call also
  sets that point's direction)
- **Behaviour changed:** command edit.paste (a child device pasted with its parent keeps its counter under the new
  parent; a child whose parent stays behind is renumbered as before)
- **Behaviour changed:** command numbering.renumber (gives up a counter whose tag a device with a frozen tag prints)
- **Behaviour changed:** command project.drawing.set (takes `wire_numbers`, `true` or `null`)
- **Behaviour changed:** commands cable.create and conductor.add (a conductor may list the `wires` that become that
  core in the same step; cable.create takes a `frozen_tag`)
- **Behaviour changed:** command fields.set and fields.set_many (the project row takes its master data,
  `master.long_description`, `master.document_title`, `master.project_ref`, `master.drawing_id`, `master.object_id`,
  `master.manufacturing_year`, `master.created` and `master.edited`, and its `parties`, besides `master.description`)
- **Behaviour changed:** command check.waive (`reason` and `author` are optional and of any length; a waiver without a
  reason records an empty one, without an author none)
- **Text changed:** command library.update (a refusal that leaves connected pins without a connection point names the
  pin as pages print it, an interruption point's by its name, "interruption point 0V:1", instead of "pin fn_cp 0")
- **Text changed:** commands, refusals in a Dutch window (the reference resolver's reasons, a schema violation, which
  names the field instead of a JSON Pointer, the strip editor's, the failed saves' reasons and the image over the
  pixel limit, named by where it shows, read in Dutch)

### The window

- **Added:** window action `project.wire_numbers` (Draw ▸ Connect ▸ Print wire numbers)
- **Added:** window action `cable.from_wires` (Draw ▸ Connect ▸ Cable…, Cable on the Draw tab: the selected wires as
  a cable's cores, in one form)
- **Added:** window actions `picker.category` and `picker.open` (the device browser's category tree and a part's
  functions), `tool.place_terminal` (Draw tab, Terminal…), `section.new` (Page ▸ New section…), `edit.select_all`
  (Edit ▸ Select all, Ctrl+A) and `cp.unused` (Mark not used)
- **Added:** window actions `symbol.edit` and `symbol.copy_edit` (the browsers' Edit symbol and Copy and edit, on
  the symbol named or the browser's current row)
- **Behaviour changed:** window `tool.place_terminal` (asks for `strip`, `kind`, `count` and `from` in its form
  instead of opening the device browser) and `place.pick` (`count`: a terminal row laid by one click)
- **Text changed:** window right rail (Symbol browser and Device browser, where it read Symbols and Parts)
- **Added:** window action `page.title_block` (Page ▸ Title block fields…; its parameters are the title-block paths,
  `project.drawing_id`)
- **Added:** window action `file.import` (File ▸ Import…: a `.qet` starts `file.import_qet`, an `.ewz` opens
  `file.open_ewz`'s question)
- **Behaviour changed:** window `file.open_ewz` (no File menu entry of its own; File ▸ Import… reaches it)
- **Behaviour changed:** window `help.tutorials` (no longer takes `headless-workflow`: the page is a how-to)
- **Text changed:** window `strip.new` (reads "Terminal strip", without "…": it makes the strip at once)
- **Text changed:** window Draw tab (the symbol editor's button reads "Symbol editor", where it read "Symbols"; the
  Wire marker has a button, Marker)
- **Text changed:** window wizard (`wizard.apply_check_scheme` reads "Wizard: apply the check level")
- **Behaviour changed:** window canvas (a right click with any tool but Select is Escape; the tool bar stands under
  the canvas; a page opens with its whole sheet unless a fit to the width is more than 15 % larger)
- **Behaviour changed:** window canvas context menu (`command_bar::canvas_menu` takes where the click fell, object,
  frame or empty spot; what fits the thing comes first; a right click on an empty spot clears the selection;
  Shift+F10 or the menu key opens it at the selection) and the Terminal strips navigator's strip rows (Add terminal,
  Edit strip)
- **Added:** window action `potential.offer` (`accept`: the card's Accept or Decline of a potential reasoned for the
  selected wire)
- **Behaviour changed:** window Define potential… (its Type is a list of the stored words; a typed printed form such as
  `L+` still reaches `potential.draw` as its `type` parameter)
- **Behaviour changed:** window script describe text (`page.describe` gives each wire's corners, "via x,y … mm")

### Checks

- **Text changed:** checks, every rule (the message reads in Dutch in a Dutch window, with Dutch fallback words and
  decimal commas; the English messages are unchanged)
- **Text changed:** checks EW-POT-011 ("`<potential>`: it is unclear which wire feeds the junction at `<cell>` on folio
  `<page>` (wires `<wires>`); draw one wire into it from the supply side", or the group of interruption points)
- **Behaviour changed:** checks EW-POT-021 (a series chain of loads between two sides of a supply is not reported;
  two loads fed from the same side and joined on the far side still are)

## 6. Upgrade steps

- **From 0.1.0:** install 0.2.0 over it as the user guide's [Upgrade](../book/src/how-to/install.md#upgrade) says.
  Nothing is migrated: a project of 0.1.0 opens as it is.
- **What you may notice in an existing project:**
  - A wire drawn from now on across a fuse, a contact or a coil goes round it; wires already drawn keep their routes.
  - A wire without a route is drawn with right angles instead of a diagonal.
  - A wire whose Wire marker box is ticked now prints a marker.
  - A PLC card's channel bound to its own pin shows as spare until a wire reaches the pin.
  - Fewer findings: EW-POT-021 on loads in series, EW-CORE-069 on marks drawn across wires.
  - Contactors placed earlier keep their tags. Once the project's copy of the starter contactor is updated from the
    library, a new contactor is offered the letter Q, and EW-RDS-003 warns on a contactor lettered K.
  - The project keeps its copies of the starter symbols and parts until you update them from the library (section
    4). The three-phase motor's new version moves its connection points, so check the wires at a motor after
    updating it.

## 7. Known limitations

- **An imported QElectroTech folio still differs** in a few places: a master's contact list has no contact symbols
  and its rows stand closer than in QElectroTech; cross-references shown as a cross or placed at the bottom print as
  a list, with a report entry; QElectroTech's folio list arrives as ElektraWatt's own table of contents; an element's
  mirror is not read (QElectroTech 0.100 writes none; newer versions do); fonts are substituted, so texts sit
  slightly lower.
- **Interruption points need three grid steps** below or above each other: the name stands above the arrow and
  the cross-reference below, so nearer points would print over each other, and the tool does not place them
  (Alt does). Points ended on wires with the Wire tool's interruption point key are not held apart, so wires one
  grid step apart end in points whose texts overlap.
- **A second wire to an occupied pin** is drawn over the first wire's last stretch and shows no dot, so the drawing
  does not say that the two are joined. End the second wire on the first wire instead: that makes a junction with
  its dot.
- **A terminal renamed through its Tag** in Properties gets a frozen tag that the page does not print.
- **The importer's messages** (the EW-IMP findings of an import's migration report) read in English in a Dutch
  window: they are stored in the project as the importer wrote them.
- **Two or more CPUs.** In a project with two or more CPUs a new card is attached to no CPU, and the window has no
  command to attach it: the PLC panel does not list it. `ew apply` with `assembly.attach` does it.
- **A new page's grid.** A new page takes the QET 10 px connection grid unless you choose 4 mm in New page or the
  current page has it; the setting "grid for new pages" is not built.
- **A connection point marked not used** shows no mark on the page.
- **Three texts name a thing by its ID or path:** EW-REL-004 prints a revision's ID, EW-CORE-008 a form copy's ID,
  and the refusal of an image file its path.
- **A few built-in symbols keep their English names** in a Dutch window.
- **A device dropped on a wire connects into it** without asking; a toast says so.
- **The window's pictures were reviewed on Windows only** for this release.
- **Unsigned files.** Nothing is signed (section 1); Windows SmartScreen may stop the setup until you choose to run
  it. Signed releases come with 1.0.
- **Placeholders of online-only files** (Windows' cloud placeholders, iCloud stubs and other dataless files) are not
  detected: a project in a cloud-synced folder whose files are not downloaded fails to open with a missing file,
  instead of opening read-only with the files named.
- **`ew check`** has `--integrity` but not yet its offline mode, `--gate`, `--pages`, `--structure`, `--packs-as-of`,
  `--baseline` and the JUnit and SARIF outputs.
- **What comes with 1.0:** signed files, tags and checksums, a second approval of release jobs, reproducible builds,
  the per-machine Windows installer (MSI), the `.deb` and Flatpak packages, the update check, the crash report with
  its upload, the publishing of the libraries on crates.io, and the steward's processes. No macOS build is planned
  before 1.0.
- **Windows and Linux on x86-64 only.** No aarch64 build is made.
- **A damaged library copy** is named "the library copy of its part" in its banner and in the Save As refusal, also
  when it is a function definition, a symbol or a profile.
