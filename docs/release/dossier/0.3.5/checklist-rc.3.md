# Release checklist: v0.3.5-rc.3

[The release checklist](../../checklist.md), copied and filled for the third candidate of 0.3.5. There is no CI
until 1.0 and the release workflow has an early alpha's size, so each item says what was run by hand and what was
not. An item that is not met is on record here for the owner's go; it is not hidden by a passing suite.

**Candidate:** `v0.3.5-rc.3` · **Commit:** the commit of `release/0.3` that the tag names · **Draft:** the draft
prerelease `v0.3.5-rc.3` on the repository's releases page · **Filled by:** the release manager ·
**Date:** 2026-11-25

| Item | Check | Signed by | Result and evidence |
|---|---|---|---|
| RC-01 | The threat model reviewed for this release | — | **Not done as a review of its own.** One row changed and was read by the review before this candidate: an SVG is no longer scanned by a model of the parser's work; a plain rejecter refuses what was refused for safety (internal subsets, entities, scripts, event attributes, `foreignObject`, references that leave the document) and caps what the parser does not survive (size, elements, nesting, reference chains and cycles, large numbers), and row TM-18 says what is accepted beyond that: a crafted file can make drawing it slow. The review found that rejecter's own work quadratic; it is linear now, with a test. One `unsafe` block is new: a file or the guide is opened through the system's wide open call on Windows; the second maintainer's review of it is on record in the review, and the call has not run on Windows yet (RC-05). The release still adds no network code |
| RC-02 | No open fuzz crash; at most 10 quarantined tests | The release manager | **Met for what runs by hand.** On the candidate's tree, nothing else building: the whole workspace with the deep run and the private corpus (`cargo xtask check --deep`) passed, 7,847 tests and 9 of 9 deep tests, with the persona briefs replayed and the generated guide pages checked. No fuzz campaign runs before 1.0; no test is quarantined. A review of everything since the second candidate came before it: three major findings, each mended with a test written first (the opener waiting on the launched program off Windows; a debug build's check after a command panicking on a project that failed it before the command; the SVG rejecter above), and twenty small ones mended. Of the tests that went since the second candidate, each went with the code it tested or is covered elsewhere; the one guard that had gone with a copy (merge writes every record to the file the writer does) is back |
| RC-03 | Advisory waivers dated; SQLite's bundled version clean | The release manager | **Met.** `deny.toml` and `.cargo/audit.toml` both have `ignore = []`, so there are no waivers. `cargo deny check advisories licenses bans` on the candidate's tree says "advisories ok, bans ok, licenses ok". No third-party dependency was added or changed since the second candidate; the lock file gained one crate of the workspace itself. SQLite's own list was not read again for this candidate; the bundled version is the one 0.3.0 shipped |
| RC-04 | `SECURITY.md` names the release and its support end | The release manager | **Met.** Unchanged since the first candidate: "0.3.x — Yes, until the next minor release (0.4.0)", "0.2.x — No", "0.1.x — No" |
| RC-05 | The manual tests (RDP, screen readers, printers, network observation, the desktop installs, the crash offer) | — | **Not run for this candidate.** The installers, a printer and a screen reader are the owner's to try on a real desktop. Two things are new for that test: Open PDF, Open in PDF viewer, the privacy file, the log folder and F1 open through one call that has not run on Windows (try a file in a folder whose name has a character outside the system's code page, and that F1 lands on its heading); and a release build of both programs was compiled on Windows and on Linux for this tree, but nothing was packaged before the release run. The exported DXF pages were not opened in a CAD program by anyone |
| RC-06 | The translation status meets NFR-I18N-01; the guide is in every installer | The release manager | **Met for the window and the tutorials.** The rule `translations` of `cargo xtask rules` passes on the candidate's tree: every text key of every crate has its Dutch (8,131 keys), and the rule now names a key that exists in English only. `cargo xtask book-po --check` passes. The guide beyond its introduction and tutorials is English. The guide's folder in the installers was not looked at by hand |
| RC-07 | The content audit of the bundled assets | The release manager | **Met by its test.** `ew-library`'s content audit passes on the shipped content. Since the second candidate the bundled content changed in comments and README files only |
| RC-08 | Profiles and format, CLI and API changes listed in the release notes | The release manager | **Met.** `docs/release-notes/0.3.5.md`, sections 3 to 7, written anew for everything since the second candidate (about a hundred visible changes of 599 commits). `cargo xtask api-guard` against 0.3.0: "0 breaking, 363 additive"; no stored value was added since the second candidate. Since the second candidate: `project.settings.set` takes over four commands, whose names stay as aliases (an older command log replays); `rep.move` takes `keep`; `strip.delete_rows` is gone; the window's actions `rail.entry`, `ui.app_menu`, `ui.context_menu` and `ip.supply_apply` are new; the rules EW-CORE-084 and EW-REL-002 left the catalogue; `ew commands` lost two columns and some refusals changed their words. Each has its line in section 5. The summary has 30 bullets, none over 160 characters |
| RC-09 | The engineering-verification disclaimer in About, the guide and the report | The release manager | **Present in About's source and in the release notes' section 1.** Not screenshotted for this candidate |
| RC-10 | LG-1 on file | The owner | **Met.** The owner's statement on file for 0.1.0 stands: no employer is involved |
